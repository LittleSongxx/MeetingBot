# 4 项 Agent 能力落地记录（2026-10-30）

> 计划见 [`Agent能力落地方向调研-2026-10-30.md`](Agent能力落地方向调研-2026-10-30.md)；本轮按该计划的第 1~4 项实现并验证。

## 实现了什么

| 能力 | 实现 |
|---|---|
| **原文证据（可核对）** | 六字段中的数组条目支持 `evidence`（segment_no/start_ms/end_ms/speaker/quote）；模型只给逐字 quote，后端在 `TranscriptSegment` 里做确定性匹配，匹配不上不展示；纪要详情每条可点“原文”；Agent 自检提示词增加证据核对（UNSUPPORTED），重写后保留/重绑定证据 |
| **质量评测与反馈** | 生成时保存 `meeting_minutes.ai_draft_json`；`meetingbot/fastapi-app/evaluation/` 提供零模型调用的离线评测：六字段覆盖率、有证据条目占比、引用合法率、AI 草稿→人工终稿修改率、golden set 决策/行动项/证据召回 |
| **行动项** | 新表 `action_item` + `/actionItem` 接口；已确认纪要可生成 DRAFT 行动项（pending_items 全量 + 带负责人/期限的 decisions），人工确认生效后为 OPEN，支持完成/撤回/编辑/批量确认/删除/CSV 导出；AI 提取幂等（同来源只生成一次），不自动同步外部系统 |
| **单场会议问答** | `POST /meetingMinutes/ask/{id}`；无向量库，中文 bigram 检索本场转写片段 + 纪要，答案必须带 segment_no/quote 引用；引用做二次校验（片段存在 + quote 逐字命中），`found=true` 但无有效引用时降级拒答；会话不落库、不跨会议 |

## 数据/接口变化

- 表：`meeting_minutes.ai_draft_json`、`action_item`（14 张表）。
- 迁移：`db/migrations/2026-10-30_agent_capabilities.sql`（已有库一次性执行；全新库已并入 `01-schema.sql`/`02-seed.sql`）。
- Prompt：新增 `MINUTES_QA`，四条旧模板追加【证据要求】（迁移只追加不覆盖）。
- 接口：`/actionItem/*`（列表、按纪要查询、生成、确认、编辑、状态、手动新增、删除、CSV）；`/meetingMinutes/ask/{id}`。
- 前端：行动项页面 + 菜单/路由；纪要详情“原文”按钮、行动项区块、问答弹窗；运行观测增加“纪要问答”调用类型。
- 权限：行动项读=会议可见，写=管理员/纪要创建人/条目创建人；owner 可改自己条目的完成状态；问答=纪要可见且只读。
- 级联：删会议/纪要同步删行动项；重新生成纪要只删 DRAFT 行动项，已生效承诺保留；用户引用检查覆盖行动项。

## 验证

- 后端：`ruff check` 通过；`unittest` **83 个测试全绿**（新增 evidence/action item/QA/evaluation 指标测试）。
- 数据库：全新隔离 MySQL + 新后端镜像，bootstrap 成功（14 表/6 prompt/演示证据/AI 草稿/3 条行动项）；已有库迁移后正常启动。
- 前端：15 路由 0 console error；行动项页真实数据、确认/完成/撤回、CSV 导出；纪要详情 13 个“原文”按钮、行动项区块；问答真实模型提问返回带引用答案；375px 全路由无横向溢出。
- 评测：`python -m evaluation.run_eval` 在演示数据上输出六字段覆盖 100%、证据合法率 100%、golden 决策 3/3、行动项 3/3。
- 部署：backend/web 镜像从修复后源码重建并重建容器，健康检查正常；旧 meetingbot-local 栈未受影响。
