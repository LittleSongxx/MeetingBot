# 4 项 Agent 能力落地记录（2026-10-30）

> 计划见 [`Agent能力落地方向调研-2026-10-30.md`](Agent能力落地方向调研-2026-10-30.md)；本轮按该计划的第 1~4 项实现并验证。

## 实现了什么

| 能力 | 实现 |
|---|---|
| **原文证据（可核对）** | 六字段中的数组条目支持 `evidence`（segment_no/start_ms/end_ms/speaker/quote）；模型只给逐字 quote，后端在 `TranscriptSegment` 里做确定性匹配，匹配不上不展示；纪要详情每条可点“原文”；Agent 自检提示词增加证据核对（UNSUPPORTED），重写后保留/重绑定证据 |
| **质量评测与反馈** | 生成时保存 `meeting_minutes.ai_draft_json`；`meetingbot/fastapi-app/evaluation/` 提供零模型调用的离线评测：六字段覆盖率、有证据条目占比、引用合法率、AI 草稿→人工终稿修改率、golden set 决策/行动项/证据召回 |
| **行动项** | 新表 `action_item` + `/actionItem` 接口；已确认纪要可生成 DRAFT 行动项（pending_items 全量 + 带负责人/期限的 decisions），人工确认生效后为 OPEN，支持完成/撤回/编辑/批量确认/删除/CSV 导出；AI 提取幂等（同来源只生成一次），不自动同步外部系统 |
| **单场会议问答** | `POST /meetingMinutes/ask/{id}`；无向量库，中文 bigram 检索本场转写片段 + 纪要，答案必须带 segment_no/quote 引用；引用做二次校验（片段存在 + quote 逐字命中），`found=true` 但无有效引用时降级拒答；会话不落库、不跨会议 |

## 第二轮复核修复（2026-10-30 下午）

对新增能力做了一次全量复核，发现并修复了 6 个真实问题，均补了回归测试：

1. **页面编辑保存会丢证据元数据**：`merge_evidence` 在没有 segments 的场景只保留 quote，导致 `segment_no/start_ms/end_ms/speaker` 被清空；改为原样保留完整 evidence（生成/自检仍做逐字校验）。
2. **演示数据每次重启覆盖人工修改**：`demo_seed` 对 DRAFT 演示纪要无条件重写；改为只在缺 `evidence` 或 `ai_draft_json` 时补齐。
3. **行动项重复**：`pending_items` 与 `decisions` 表达同一件事时生成两条；按归一化内容跨字段去重。
4. **清空负责人后姓名残留**：只改 `owner_user_id=null` 时 `owner_name` 还在；更新时同步清空/同步新负责人姓名。
5. **草稿行动项无法撤回**：前端对 DRAFT 显示“撤回”，后端只接受 OPEN/DONE；允许 DRAFT→CANCELLED（DRAFT 不能直接完成/进行中）。
6. **纯空白内容**：问答问题、手动/编辑行动项内容为纯空格时会被接受；统一 strip 后拒绝。

另修复：编辑行动项弹窗里的“会议”下拉可改但后端不支持迁移——前端改为编辑时禁用。
验证：89 个单测全绿、ruff 全绿、隔离全新库 bootstrap 正常、真实 API 回归（证据保存前后元数据一致、外部用户问答/生成/确认均 403、空白内容被拒、负责人清空生效）、CI 通过。
