# 前端调研：Vue 3 + Vite + Element Plus 管理端

> 调研范围：`ai_meeting/vue`（工程配置、入口、路由、请求层、全部 17 个页面、样式与静态资源）。
> 方法：只读阅读源码 + 交叉比对 `ai_meeting/fastapi-app` 的接口定义；**未安装依赖、未启动 dev server、未做浏览器实测**，因此所有"运行时行为"类结论均标为推断。
> 证据等级定义见文末「§9 证据等级说明」。文中路径均相对项目根。

---

## 0. 结论摘要（TL;DR）

1. 前端是一个**纯管理端 SPA**（无 to C 端页面），技术栈 Vue 3.5 / Vite 5 / Element Plus 2.14 / axios / echarts，无 TypeScript、无 Pinia/Vuex、无 ESLint/测试、无组件库封装层。全部 17 个 `.vue` 页面共约 4400 行，`src/components/` 是**空目录**。证据：`ai_meeting/vue/package.json:11-28`、`ai_meeting/vue/src/views/**`（目录清单）。
2. **鉴权只有"半层"**：路由守卫只判断 `localStorage['xm-user'].id` 是否存在（`ai_meeting/vue/src/router/index.js:61-72`），不校验 token 有效期；`requiresAdmin` 只覆盖 4 条路由且判断依据是可被篡改的 localStorage 字段。真正的权限校验全部在后端（`ai_meeting/fastapi-app/common/auth.py:21-48`），前端守卫本质是"未登录跳转 + 菜单隐藏"。
3. **前后端契约整体高度一致**：我逐条核对了前端 45 个调用点与后端 61 个路由，字段名、分页参数、状态枚举基本对得上（甚至刻意保留了两种分页参数命名）。真正的不一致只有 5 类，其中 2 个会直接导致生产环境不可用或功能失效（见 §8.1）。
4. 复杂交互是这套前端的亮点：**3 处 3 秒轮询**（转写/纪要/Agent）、**1 处手写 SSE**（Agent 详情，`fetch` + 流解析）、**多类型文件预览**（图片/音视频/PDF/文本/docx 段落/zip 清单 7 种分支）、**blob 导出**、**上传防重复/大文件**、**4 张 ECharts 图**。但富文本编辑器依赖（wangeditor）引入了却完全没用。
5. 生产构建配置有明确故障点：`ai_meeting/vue/.env.production:1` 的 `VITE_BASE_URL='http://:9090'` 是**非法 URL**，`npm run build` 产物无法访问后端；且后端返回的头像地址被硬编码为 `http://127.0.0.1:9090`（`ai_meeting/fastapi-app/api/files.py:58`），换机器/换端口即失效。

- **没有配置 Vite 代理**：`vite.config.js:11-105` 全文中无 `server.proxy` 段 → 开发期前端（5173）**直连**后端（9090）。
- 因此跨域靠后端 CORS 放行：`ai_meeting/fastapi-app/main.py:35-43` `allow_origins=["*"]`、`allow_methods=["*"]`、`allow_headers=["*"]`（等级：直接）。后端绑定 `localhost:9090`（`main.py:60`）。
- 环境变量只有 1 个 `VITE_BASE_URL`，被 4 处使用：

| 文件 | 值 | 使用点 | 证据 |
|---|---|---|---|
| `.env.development` | `http://localhost:9090` | axios `baseURL`；el-upload `action`；SSE 手拼地址 | `.env.development:1`、`request.js:7`、`User.vue:150,92`、`Person.vue:56,6`、`Agent.vue:189,298` |

→ **生产构建的严重缺陷**：`npm run build` 后 `baseURL` 为 `http://:9090`，axios 请求全部失败；`vite preview` 同样受影响。等级：直接（值字面可证）+ 推断（浏览器实际报错形态未实测）。

### 1.4 Element Plus 的接入方式（存在三套并行机制）

1. `main.js:5-7,12` 全量 `app.use(ElementPlus, { locale: zhCn })` + `import 'element-plus/dist/index.css'`（全量样式）。
2. `vite.config.js:18-23` 又用 `AutoImport` / `Components` + `ElementPlusResolver({ importStyle: 'sass' })` 做按需解析。
3. `vite.config.js:15-17` 用 `unplugin-element-plus` 的 `ElementPlus({ useSource: true })`，配合 `css.preprocessorOptions.scss.additionalData` 注入 `src/assets/css/index.scss`（`vite.config.js:93-104`）来覆盖主题色（`index.scss:1-7`：primary `#0066bc`、success `#46b61f`、warning `#ffad00`、danger `#e52f2f`、info `#47afdc`）。

结论：全量注册与按需解析并存，文档级配置互相冗余；且 `AutoImport` 实际没被用到——所有页面都显式 `import { ElMessage } from 'element-plus'` 等（例如 `Meeting.vue:156`、`Transcription.vue:125`）。等级：直接（配置与 import 字面可证）+ 支持性（是否导致样式重复打包/主题混用未实测）。

细节（均为直接证据）：
- 所有页面组件都被**静态 import 后**又包成 `component: () => Home` 的箭头函数（`router/index.js:3-20` 静态导入，`30-43` 箭头包装）→ "懒加载"写法无效，打包仍会打进首包。

### 2.2 守卫逻辑：是否真的鉴权？

守卫全文只有 12 行（`router/index.js:61-72`）：

```js
const user = JSON.parse(localStorage.getItem('xm-user') || '{}')
if (to.path.startsWith('/manager') && !user.id) return '/login'   // 仅判缓存里有没有 id
if (to.meta.requiresAdmin && user.role !== 'ADMIN') return '/manager/home'
```

| 结论 | 说明 | 证据 | 等级 |
|---|---|---|---|
| 只做"未登录跳转"，不做 token 校验 | 不解析 JWT 过期时间、不请求 `/currentUser`；token 过期后仍可进入页面，直到第一个 API 返回 `code='401'` 才被踢回登录页 | `router/index.js:63-67`、`request.js:42-45` | 直接 |
| 可被本地绕过 | 手工写 `localStorage.xm-user={"id":1,"role":"ADMIN"}` 即可通过前端路由守卫 | `router/index.js:63,69` | 推断（代码路径可证，未实测） |
| 真正的权限在后端 | 后端 `require_admin`（`common/auth.py:42-48`）和业务层数据权限（如 `meeting.py:93-112`） | `ai_meeting/fastapi-app/common/auth.py:21-48` | 直接 |
| `requiresAdmin` 只覆盖 4 条路由 | user / department / aiModel / promptTemplate | `router/index.js:31,32,40,41` | 直接 |
| 角色来源是 localStorage，而非服务端最新值 | 管理员改了某员工角色后，该员工需重新登录才会看到菜单变化；`/currentUser` 接口后端已提供但前端从未调用 | `Manager.vue:104-107`；`api/__init__.py:115-117`；前端 grep 无 `currentUser` | 支持性 |
| 未登录访问任意 `/manager/*` → `/login`；其余路径（`/404`、`/login`、`/register`）不守卫 | — | `router/index.js:64-67` | 直接 |
| 已登录访问 `/login` 不会自动跳管理端 | 无对应逻辑 | `Login.vue:90-116` 全文 | 直接 |

### 2.3 角色如何控制菜单

菜单写在布局页 `Manager.vue:38-86`，用 `v-if` 按 `data.user.role` 裁剪，`data.user` 来自登录缓存（`Manager.vue:104-107`）：

| 菜单分组 | 菜单项 | 可见角色 | 对应路由 | 路由级 requiresAdmin | 证据 |
|---|---|---|---|---|---|
| （无分组） | 系统首页 | 全部 | `/manager/home` | 否 | `Manager.vue:42-45` |
| 会议中心 | 会议管理 / 会议资料 / 转写任务 / AI会议纪要 | 全部 | 见路由树 | 否 | `Manager.vue:46-55` |
| 智能助手 | 纪要自检 / 运行观测 | 全部 | `/manager/agent`、`/manager/observability` | 否 | `Manager.vue:56-63` |
| 系统配置 | AI模型配置 / Prompt模板配置 | **仅 ADMIN**（整个 sub-menu `v-if`） | 两条均 requiresAdmin | 是 | `Manager.vue:65-72` |
| 组织与员工 | 部门管理 | 仅 ADMIN | `/manager/department` requiresAdmin | 是 | `Manager.vue:80` |
| 组织与员工 | 员工账号管理 | 仅 ADMIN | `/manager/user` requiresAdmin | 是 | `Manager.vue:82` |
| 组织与员工 | 所在部门成员 | **仅 EMPLOYEE** | `/manager/departmentMembers` **无 requiresAdmin** | 否 | `Manager.vue:84`、`router/index.js:33` |
| 顶栏下拉 | 个人资料 / 修改密码 / 退出登录 | 全部 | `/manager/person`、`/manager/password`、清缓存回 `/login` | 否 | `Manager.vue:22-32,109-113` |

发现：
- 「所在部门成员」菜单只给员工看，但路由没加 `requiresAdmin`，管理员手输 URL 也能进；后端返回的是"当前登录用户所在部门成员"，管理员一般无部门 → 空表（`api/user.py:244-255`）。等级：直接（代码）+ 推断（管理员实际数据）。
- 菜单把「会议中心」「智能助手」开放给员工，但后端对每个接口都按"创建/主持/参会"收窄数据范围（如 `meeting.py:444-460`、`transcription.py:316-328`、`meeting_minutes.py:176-186`、`agent.py:180-181`）→ **越权风险主要靠后端兜住，前端菜单只是展示层**。等级：直接。

## 4. ④ request.js：拦截器、错误处理、token 存放、401

`ai_meeting/vue/src/utils/request.js`（全文 66 行）是唯一 HTTP 封装：

| 环节 | 行为 | 证据 | 等级 |
|---|---|---|---|
| 实例 | `axios.create({ baseURL: VITE_BASE_URL, timeout: 30000 })` | `request.js:5-10` | 直接 |
| 请求头 | `FormData` 时**删除** `Content-Type`（让浏览器补 boundary）；其余写 `application/json;charset=utf-8` | `request.js:16-20` | 直接 |
| token 存放 | **`localStorage['xm-user']` 里的 `.token`**，每次请求读缓存并写入请求头 `token`（后端 `Header(default=None)` 同名） | `request.js:22-24`；后端 `common/auth.py:21-22` | 直接 |
| 响应成功 | `responseType==='blob'` 时**原样返回二进制**（早于任何 code 判断） | `request.js:37-39` | 直接 |
| 401 | 业务码 `res.code === '401'` → `ElMessage.error(res.msg)` + `router.push('/login')`，**但不清理 `xm-user`、也不 reject** | `request.js:42-45` | 直接 |
| 字符串响应 | `typeof res === 'string'` 时尝试 `JSON.parse` | `request.js:47-49` | 直接 |
| 返回值 | 直接返回响应体 `{code,msg,data}`，页面自己判 `'200'` | `request.js:50-51` | 直接 |
| HTTP 错误 | 404→"未找到请求接口"；500→"系统异常…"；其余 `console.error`；`Promise.reject` | `request.js:55-62` | 直接 |
| 401 与后端协议 | 后端所有业务异常（含 401/403）都返回 **HTTP 200 + `{code:"401"|"403",msg}`**，所以前端只能靠业务码判断 | `common/exception_handler.py:16-24`、`common/result.py:7-21` | 直接 |

**已识别缺陷/风险**（均带证据）：

1. **网络错误会抛 TypeError**：`error.response.status` 未判空，断网/超时（`error.response === undefined`）时错误处理器自身抛错，原始错误被掩盖。证据：`request.js:53-62`。等级：直接（代码路径）。
2. **blob 请求的 401 不被处理**：`request.js:37-39` 在 `res.code==='401'` 判断之前就 return，所以 token 过期时下载/导出接口拿到的是 JSON 错误体，被当二进制处理。等级：直接；影响见 §8.1。
3. **401 后缓存不清理**：`xm-user` 仍在，用户回登录页重新登录会覆盖；但若用户直接刷新 `/manager/*`，守卫仍放行（`router/index.js:65`），形成"进得去但接口全 401"的状态。等级：直接 + 推断（刷新行为未实测）。
4. **`res.code === '401'` 后页面仍继续执行**：由于没有 `reject`，调用方 `.then` 里还会走 `else ElMessage.error(res.msg)` 分支，可能出现**双提示**。等级：支持性（需看各页面分支，如 `Meeting.vue:243-245`）。
5. **token 存在 localStorage**：任何 XSS 都能直接读走 24 小时有效的 JWT（`settings.py:32-34`）。前端存在一个可从后端数据注入 HTML 的入口（见 §8.1 第 6 条），两者叠加构成实际风险。等级：支持性（需 XSS 触发点成立）。

**绕过 request.js 的两条旁路**（一致性问题）：

- 头像上传：`el-upload :action="baseUrl + '/files/upload'" :headers="{token: ...}"`，不走 axios 实例、不走 30s 超时/错误提示（`User.vue:88-100`、`Person.vue:5-17`），失败只给"头像上传失败"。
- Agent SSE：`fetch(\`\${baseUrl}/agent/events/\${id}\`, { headers: { token } })`，手拼地址、手读 token、手解析 SSE，**401 时只提示"自检实时连接已断开"**，不会跳登录页（`Agent.vue:188-190,289-335`）。等级：直接。

## 5. ⑤ 状态管理方式

- **没有 Pinia / Vuex / provide-inject**：`package.json:11-20` 无相关依赖；`src` 全目录 grep `pinia|vuex|provide(|inject(` 无结果。等级：直接。
- **唯一全局状态 = localStorage 的 `xm-user`**（登录返回的 `account_dict` + `token`）：

| 操作 | 位置 | 证据 |
|---|---|---|
| 写入 | 登录成功 `setItem('xm-user', JSON.stringify(res.data))` | `Login.vue:103` |
| 读取 | 路由守卫、请求拦截器、Manager 布局、7 个页面 | `router/index.js:63`、`request.js:22`、`Manager.vue:106`、`User.vue:154`、`Meeting.vue:162`、`Person.vue:60`、`Agent.vue:296`、`DepartmentMember.vue:33`、`Password.vue:46`、`Home.vue:70` |
| 更新 | 个人资料保存后整份回写 | `Person.vue:87` |
| 删除 | 退出登录 / 改密成功 | `Manager.vue:111`、`Password.vue:84` |

- **页面内状态**一律 `reactive({...})` 单对象（如 `Meeting.vue:164-198`、`MeetingMinutes.vue:340-363`），没有拆 composables，也没有跨页共享缓存；列表页每次进入都重新请求。
- **组件通信只有 1 处**：`<RouterView @updateUser="updateUser" />`（`Manager.vue:90`）+ `Person.vue:80,89` 的 `defineEmits/emit('updateUser')`，用于保存资料后刷新顶栏头像/姓名。除此之外全仓没有 `defineProps`/`props` 的业务使用（仅 `MeetingMinutes.vue` 的两个就地组件用 props，`251,272`）。
- 结果：刷新页面即回到"以 localStorage 为唯一身份源"的状态；角色/部门/头像变更必须依赖重新登录或手工回写缓存。等级：直接。
