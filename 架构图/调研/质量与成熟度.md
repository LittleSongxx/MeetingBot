### 1.2 实测运行结果：**跑不起来（环境缺依赖）**

我在 Windows（Anaconda Python **3.13.9**，pytest 8.4.2）下执行：

```text
cd ai_meeting/fastapi-app
python -m pytest -q
```

结果：pytest 能启动并被收集，但所有测试模块在 import 阶段失败：

```text
tests\test_agent.py:5: in <module>
    from tortoise import Tortoise
E   ModuleNotFoundError: No module named 'tortoise'
```

（8 个文件同类错误，**直接**：命令输出可复现。）

依赖探测（`python -c import ...`，**直接**）：

| 需求包 | 当前环境 | 影响 |
| --- | --- | --- |
| `fastapi` / `uvicorn` / `tortoise` / `aiomysql` / `aiosqlite` / `reportlab` / `python-multipart` | **缺失** | 测试与后端都起不来 |

| WSL Ubuntu 22.04 的 `python3`（3.10.12） | 无 fastapi、无 pytest | 该路径也不能跑 |

**结论**：
- 测试**设计上不依赖 MySQL**（全部 `Tortoise.init(db_url="sqlite://:memory:")`）；
- 但按 `requirements.txt` 装完也**不能跑测试**——`requirements.txt` 里没有 `aiosqlite`（SQLite 异步驱动）和 `pytest`（`requirements.txt:25-32` 数据库段、`:19-22` Web 段均无；全文 49 行无这两项，**直接**）；
- 再加上当前环境缺失 `fastapi/tortoise/reportlab` 等，**本次只能做静态评估**；我没有安装任何依赖（遵守任务约束）。

### 1.3 设计层面的可测试性（正面）

- 每个测试文件 `asyncSetUp` 里 `Tortoise.init(db_url="sqlite://:memory:")` + `generate_schemas()`，测试之间完全隔离（`test_agent.py:30-37` 等），**不需要 MySQL、不需要网络**（**直接**）。

## 3. ③ 安全清单

### 3.1 账号与密码：**明文存储、明文比对（高）**

| 结论 | 证据 | 等级 |
| --- | --- | --- |
| 密码以明文写入 `user.password`，登录时字符串直接比较 | `api/__init__.py:62`（`user.password != account.password`）、`:83-94`（注册直接 `User.create(password=account.password)`）、`:102-111`（改密直接比较后 `update(password=account.newPassword)`）；`models.py:29-30` 注释"登录时与页面提交的密码直接比对" | 直接 |
| 全仓无任何密码哈希实现（bcrypt/passlib/hashlib 用于密码均无命中） | grep `bcrypt|passlib|pbkdf2|salt|hmac` 无命中；`hashlib` 仅用于文件 SHA-256（`api/meeting_material.py:1,111`） | 直接 |
| 管理员建号默认密码固定 `123456` | `api/user.py:149-150` | 直接 |
| 演示 dump 里就是明文密码（admin/admin 等） | 根 `ai_meeting.sql:534-536`；`ai_meeting/ai_meeting.sql:476-480` | 直接 |

影响：数据库泄漏 = 全站账号直接失守；内部人可读密码；无法做"密码错误次数/强度"治理。建议：`bcrypt`/`argon2`（个人项目加个 `passlib[bcrypt]` 即可），种子账号改成一次性初始密码 + 首次登录强制改密。

## 5. ⑤ 错误处理与日志

### 5.1 事实（直接）

- **全仓没有 `logging`**：grep `logging|getLogger|logger.` 在 `fastapi-app/**/*.py` 命中数 = 0；唯一的输出是两处 `print`：
  - `common/exception_handler.py:29`：`print("捕获到422错误:", exc.errors())`
  - `common/exception_handler.py:42`：`print("捕获到系统错误:", repr(exc))`
- **所有业务异常都返回 HTTP 200**：`common/exception_handler.py:21`、`:36`、`:47`（注释明说"http总是返回200"）；自定义 `CustomException` 默认 `code="500"`（`common/exception_handler.py:8-13`）。
- **异常基本不吞，但只落库不落日志**：
  - 转写失败 → `TranscriptionTask.status=FAILED, error_message=str(error)[:2000]`（`services/transcription_service.py:489-496`）；
  - 纪要失败 → `MeetingMinutes.status=FAILED, error_message`（`services/minutes_service.py:173-175`）；
  - 自检失败 → `AgentRun.status=FAILED, error_message`（`services/agent_service.py:426-433`），步骤失败 → `AgentStep.status=FAILED`（`:204-211`、`:274-277`）；
  - AI 调用成功/失败 → `AiCallLog`（`services/model_factory.py:85-115`；转写 `transcription_service.py:91-121`）。
- **静默返回点**（既不打日志也不落库）：抢占失败直接 return（`transcription_service.py:415-416`）、纪要状态不符直接 return（`minutes_service.py:132-134`）、自检状态不符直接 return（`agent_service.py:361-364`）、调度去重直接 return（三个 `schedule_*`）。
- **启动恢复失败的处理**：`main.py:19-26` 在 `lifespan` 里 `await recover_*`，任一恢复函数抛异常会导致应用启动失败；此时只有 uvicorn 自带 traceback，没有业务日志（**推断**）。
- `print` 出去的 422 明细和未捕获异常**没有堆栈**（`repr(exc)`），且只到 stdout，重启/容器里容易丢。

### 5.2 任务失败是否可见

**业务上可见，运维上不可见**（**推断**，基于代码路径）：
- 可见：任务表 `status/error_message/stage` → 前端列表展示；运行观测页的 `recent_failures` 汇总 AI 调用失败 + Agent 运行失败（`services/observability_service.py:204-215`）；`AiCallLog` 统计成功率/耗时/Token（`:121-166`）。
- 不可见：服务端没有任何日志/日志文件/日志级别、没有 traceback 关联、没有请求 ID 贯穿（`AiCallLog.request_id` 只用于单次模型调用）、没有健康检查端点（grep `health` 0 命中）、没有告警。

### 5.3 异常处理设计上的其他问题

| 现象 | 证据 | 影响 |
| --- | --- | --- |

## 6. ⑥ 并发 / 一致性风险

### 6.1 任务模型：纯进程内后台协程（**直接**）

三个业务各自维护"任务字典 + 信号量 + `asyncio.create_task`"：

| 服务 | 内存状态 | 调度 | 恢复 |
| --- | --- | --- | --- |
| 转写 | `_running_tasks: dict`、`_semaphore`（并发 2）`transcription_service.py:22-31` | `schedule_transcription` `:505-514` | `recover_transcription_tasks` `:517-527` |
