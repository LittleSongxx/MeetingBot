# 改造后项目复核与 AI Agent 能力评估（2026-10-30）

> 复核对象：`MeetingBot` 仓库 main（238 commits，`9d8e547`）+ 本机运行栈 `meetingbot-aim-local`
> 复核方式：真机 API 探测、Playwright 全路由、隔离容器复现、后端/前端只读深度审计（2 份子报告）+ 旧分支能力对照
> 结论一句话：**当前运行栈功能可用、视觉/路由问题已修复，但「全新部署」按 README 走会直接起不来（P0 已复现）；同时存在 1 个存储型 XSS 和 1 类越权覆盖问题。作为「AI Agent 项目」，它目前只是「反思环 + LLM 结构化生成」，不具备工具调用、检索、记忆、对话与评测能力。**

## 0. 结论摘要

### 0.1 可用性判断

| 维度 | 判断 |
|---|---|
| 当前运行栈（已有演示数据的环境） | **可用**：14 个管理端路由 + 登录/注册/404 全部正常渲染，0 console error / 0 pageerror / 0 失败请求；核心增删改查、导出、SSE、下载均实测通过 |

## 2. P0：已实测复现的两个启动级缺陷

### P0-1 全新部署：`SEED_DEMO=1` 时 bootstrap 必崩，容器起不来

**证据链**

- `meetingbot/fastapi-app/bootstrap.py:236`：
  `for file_name, _file_type in DEMO_MATERIALS:` —— 循环变量 `_file_type` **遮蔽**了同文件 `:63` 的模块函数 `def _file_type(extension)`；
- `bootstrap.py:248`：`file_type=_file_type(extension)` 此时 `_file_type` 已是字符串（如 `"AUDIO"`）→ `TypeError: 'str' object is not callable`；
- `Dockerfile:33` 启动命令是 `python bootstrap.py && exec uvicorn ...`，bootstrap 非 0 退出 → uvicorn 不启动；
- `compose.yaml:52` `restart: unless-stopped` → 反复重启；`web` 依赖 backend healthy → 整栈不可用；
- `.env.example:59` 默认 `SEED_DEMO=1`，README 快速开始就是 `cp .env.example .env` → **按文档走必踩**。

**隔离复现**（`review/h1-repro.txt`）

```
aim-repro-backend|Exited (1) 14 seconds ago
File "/app/bootstrap.py", line 263, in main
    await seed_demo()
File "/app/bootstrap.py", line 249, in seed_demo
    file_type=_file_type(extension), content_type=None, file_ext=extension,
TypeError: 'str' object is not callable
```

**为什么现在线上没暴露**：运行栈的 MySQL 卷里演示资料早就存在（早期镜像播种成功），`exists` 分支全部跳过，永远走不到 `:248`；但只要 `docker compose down -v` / 换机 / 新环境部署就会触发。**README 里「首次启动自动写入演示数据」在当前代码上是假的。**

**修复（一处小改，建议立刻做）**

```python
for file_name, material_type in DEMO_MATERIALS:
    ...
    file_type=material_type, content_type=None, file_ext=extension,
```

（`_file_type` 函数与三组扩展名白名单随之变成死代码，可删或保留备用；建议把「空库 + SEED_DEMO=1 启动」加进 CI/部署冒烟。）

### P0-2 删除演示数据后重启：固定 `AICDEMO` request_id 撞唯一索引 → 崩溃循环

**证据链**

- `demo_seed.py:171-173` 固定 `request_id=f"AICDEMO{index:04d}"`（共 10 条）；
- `models.py:250` `request_id` 唯一；`db/01-schema.sql` 有 `uk_ai_call_request_id`；
- 删除演示转写任务（页面允许：`api/transcription.py:274-301` 只拦 PENDING/PROCESSING）或删除演示会议（admin）时，**`ai_call_log` 被有意保留**（`api/meeting_minutes.py:137` 注释「保留作为审计记录」；`api/meeting.py:352-382` 也不删）；
- 再次启动时 `bootstrap.py:251` 无条件调用 `seed_ai_demo`；guard 只看「该音频是否已有转写任务」（`demo_seed.py:188-193`），任务已删 → 重新播种 → `_create_call_logs` 再插 10 条固定 ID → `IntegrityError`；
- `bootstrap.py:255-265` 的 `main()` 无 try/except，异常直接抛到 `asyncio.run` → 退出码 1 → `&&` 短路 → 容器重启循环。

**隔离复现**（`review/h1-repro2.txt`；因 P0-1 阻塞播种，此轮用「仅修 `_file_type` 遮蔽」的 bootstrap 挂载启动）

```
--- counts after fresh seed ---
task 1 / minutes 1 / run 1 / logs 10
--- simulate page delete: delete demo task/minutes/run, keep ai_call_log ---
remaining_logs: 10
--- restart backend ---
status=exited exit=1
tortoise.exceptions.IntegrityError: (1062, "Duplicate entry 'AICDEMO0001' for key 'ai_call_log.uk_ai_call_request_id'")
```

**影响**：管理员在页面上删掉演示数据（或 `SEED_DEMO` 开着但数据库被部分清理）后，只要重启就永久起不来；恢复只能登服务器把 `SEED_DEMO` 改 0（文档未写这条）。这是「演示数据污染生产运维」的典型。

**修复建议**

1. `request_id` 改随机（如 `"AICDEMO" + uuid4().hex.upper()`），或按 `(call_type, biz_id)` 做幂等 upsert；
2. `seed_demo()` 整体包 `try/except`，失败只 `logger.exception` + 告警，**绝不阻断 uvicorn 启动**；
3. `seed_ai_demo` 的 guard 改为「检查每个子块是否齐全」，播种过程用事务/标记表；
4. 补一个部署冒烟：空库启动 → 删演示数据 → 重启，两次都要 healthy。

## 3. P1：真实缺陷与安全问题

> 按严重度排序；每条给路径证据，详细触发条件/建议见子报告。

### 3.1 安全：存储型 XSS 可窃取管理员会话（高）

- `meetingbot/vue/src/views/manager/Meeting.vue:361-371`：删除确认框把 `preview.title`（会议主题，用户可控）用模板字符串拼进 HTML，并 `ElMessageBox.confirm(..., { dangerouslyUseHTMLString: true })` 渲染；
- 会议标题后端只做非空校验（`api/meeting.py:65-68`），且**任何登录用户**都能建会（`api/meeting.py:224-247` 仅要求登录）；
- token 存在 `localStorage['xm-user']`（`Login.vue:107`），所有请求从 localStorage 取 token（`request.js:22-24`）→ 员工可构造标题 `<img src=x onerror=...>`，管理员点「删除」即执行脚本、读走 token；
- 全仓仅此一处 `dangerouslyUseHTMLString`（其余均为 `{{ }}`/`h()` 文本渲染）。
- **修复**：删除 `dangerouslyUseHTMLString`，用 `h()` 或独立弹窗组件渲染标题+统计；后端限制标题长度并做 HTML 转义/过滤；补 CSP（见 3.7）。

### 3.2 越权：任意会议可见者可覆盖/清空已确认纪要（高）

- `api/meeting_minutes.py:94-129`（`POST /meetingMinutes/generate/{task_id}`）：`:101` 只校验 `get_accessible_meeting`（创建人/主持人/**参会人**都能过）；`:112-126` 对已存在纪要直接复用并 `status=GENERATING`、清空六块内容与 `confirmed_by/confirmed_time`，`:124` 把 `created_by` 改成调用者；`CONFIRMED` 无任何保护；
- 生成失败（模型 Key 被清、模板停用、网络错误）后原内容**永久丢失**（无版本表、无软删）；
- 同类权限过宽（与「读=会议可见」一致，但与「删=创建人/admin」不一致，`api/meeting_minutes.py:132-143` 对比）：
  - 资料删除/批量删除：任意参会者可删他人上传（`api/meeting_material.py:316-342`）
  - 转写重试：任意参会者可替他人重试、消耗额度（`api/transcription.py:239-271`）
  - 纪要编辑/确认：任意参会者（`api/meeting_minutes.py:205-218`、`:221-230`）
  - 自检发起：任意参会者（`api/agent.py:131-143`）
  - → 普通员工可反复触发付费模型调用/删除他人数据，**成本 DoS + 数据破坏**；
- **修复**：`generate` 至少 admin 或 `minutes.created_by`；CONFIRMED 需先取消确认/二次确认；旧内容落版本表；统一「写/删=admin 或对象创建人」规则；对 generate/retry/start 加配额/限流。

### 3.3 Agent 恢复与应用的边界 bug（中）

1. **最后一轮重写被中断 → 恢复直接 finalize**：`services/agent_service.py:386-390` 的「轮数已满→直接汇总」在 `:398-411`「中断恢复续跑重写」判断之前；结果是「第 2 轮问题已修复」的结论，但修订稿其实是第 1 轮（用户采纳后写入错误纪要）；
2. **resume 无 CAS、可能卡 RUNNING**：`api/agent.py:267-278` 无条件把状态改 RUNNING；若旧协程尚未退出，进程内调度器 `schedule_agent_run` 因旧 task 未 done 直接 return → 库里 RUNNING 但无执行者，SSE 永远不结束，delete 又拒绝 RUNNING（只能重启）；
3. **apply 无版本绑定**：`api/agent.py:205-252` 在 `WAITING_CONFIRMATION` 期间如果纪要被人重新生成/手工编辑，apply 仍把旧修订稿整体覆盖，且不拦 `GENERATING` 状态；
4. **失败运行无 retry**：`FAILED` 只能删除重建（重复计费），`interrupt` 后的普通异常还会被 `except Exception` 覆盖成 `FAILED`（`agent_service.py:467-475` 未带 `status="RUNNING"` 条件）。

### 3.4 bootstrap 每次启动覆盖页面配置 + 管理员 token 全失效（中）

- `bootstrap.py:114-156`：每次启动无条件 upsert 4 条模型配置（取各类型 id 最小一条），覆盖 `name/provider/base_url/api_key/model_name/timeout/enabled`；
  - 管理员在「AI 模型配置」页面改的 Key/地址/模型，重启后被 `.env` 覆盖；
  - `.env` 的 `DASHSCOPE_API_KEY` 为空时，会把库中 Key 清空并禁用 → 页面配置永久丢失；
- `bootstrap.py:73-100`：每次启动重设管理员密码（bcrypt 重新加盐）→ 行变化 → JWT `pv` 失效 → **每次重启所有管理员被强制下线**；
- `DEPLOYMENT.md:97-100` 已文档化「以 .env 为准」，但页面仍允许编辑，属「可编辑但不可持久化」的体验陷阱；
- 建议：已存在配置仅「补空」不覆盖（或提供 `BOOTSTRAP_MODEL_CONFIG=seed|fill|off` 开关）；`ensure_admin` 仅在密码校验失败时重设；重启后 token 失效写进 README。

### 3.5 任务可靠性：删除/重启/多进程下的重复执行与孤儿（中）

- **删除会议不拦运行中任务**：`api/meeting.py:352-382` 先删文件、再删各表，不与 `PENDING/PROCESSING/GENERATING/RUNNING` 互斥；后台任务继续写 `transcript_segment/agent_step/ai_call_log`，产生孤儿并继续烧模型费；
- **恢复=从头重跑**：转写分段结果只在最后一次性写库（`transcription_service.py:469-480`），纪要/自检也无 checkpoint；重启后已完成分段/分块重复调用模型、重复写 `ai_call_log`（随机 request_id 无法去重）；
- **锁不是锁**：`execute_minutes/execute_agent_run` 用 `exclude(stage="已领取")` 抢占，但第一步进度更新就把 `stage` 改掉（`minutes_service.py:166`、`agent_service.py:185`），多 worker/多副本时后续可再次抢占；`recover_*` 会把另一进程正在跑的任务重新入队；
- 单进程约束已文档化（`DEPLOYMENT.md:222-240`、`compose.yaml:13-21`），但实现比文档更脆弱；建议加 `lock_owner/locked_at/heartbeat` + CAS + DB advisory lock；
- `ai_call_log` 无业务幂等键、无删除/归档路径（永久增长，删除业务后变孤儿）。

### 3.6 API 边界与前端异常处理（中）

- **分页无上下界（实测）**：9 个列表接口均无校验（`api/meeting.py:464-466`、`api/user.py:306`、`api/transcription.py:342-344`、`api/meeting_minutes.py:195`、`api/agent.py:189` 等）；`page_size=-1` / `page_num=0` → Tortoise `ParamsError` → 返回 `{"code":"500","msg":"系统错误"}`；`page_size=100000` 直接放行，叠加每行 N+1 与整段 `full_text` 可打爆 DB/内存；
- **前端 401 处理**（`frontend.md` 2.3）：并发 7 个请求弹 7 条重复提示、不清 `localStorage['xm-user']` → 路由守卫仍放行，形成「进管理端→401→踢回→再进」循环；单请求还会双弹；blob 401 同样不清缓存；
- **断网无提示**：`request.js:84-89` 未判空 `error.response` → `pageerror: Cannot read properties of undefined (reading 'status')`，页面只剩空表；
- **注册路由直达**：生产 `/register` 仍渲染可提交表单（后端 403 兜底），建议守卫拦截；
- **localStorage 损坏白屏**：`router/index.js:63` 等 3 处 `JSON.parse` 无 try/catch，坏缓存导致白屏；
- **SSE 每秒查库**：`api/agent.py:291-320` 每个详情页每秒 `AgentRun.get` + `run_dict`（6~8 条 SQL），无心跳/超时/退避；运行被删时 `DoesNotExist` 未捕获；
- **N+1/大字段**：列表 DTO 返回整段 `full_text`、每行 4~6 条 SQL（`transcription.py:69-118`、`agent.py:76-128`、`meeting.py:175-221` 等）——`page_size=100` 约 500+ SQL。

### 3.7 前端交付：性能与移动端（中）

- **首屏 2.4MB 未压缩**：入口 `index.js` 1,890,256B + `index.css` 517,278B；`router/index.js:3-20` 静态 import 全部 14 页，仅 `/manager` 懒加载；`main.js:5-6` 全量 Element Plus + 全部图标，抵消了 unplugin 按需方案；gzip 后应可降到 ~661KB（省 72%），但**nginx 未开 gzip**；
- **无缓存/安全头**：`nginx.conf` 无 `gzip`、无 `expires/Cache-Control`、无 `CSP/X-Frame-Options/nosniff/Referrer-Policy`，`server_tokens` 未关（暴露 `nginx/1.30.5`）；
- **移动端不可用**：管理端零响应式，侧栏固定 220px，375px 视口下 14 个路由中 12 个横向溢出（426–686px），460px 弹窗超屏；
- 其余：`document.title` 不随路由变、Observability 空/错误态空白、图标按钮无 aria-label、登录/注册页大量重复、列表页骨架复制粘贴。

### 3.8 观测与成本口径（中低）

- `ai_call_log` 的 `request_size/response_size` 字节/字符混用；失败调用无 usage；ASR 调用无 token（观测「Token 总量」只反映 LLM）；
- `observability_service.py:88-96` 把日期范围内**全部**日志读进内存聚合，`ai_call_log` 缺 `create_time` 前置索引（默认 30 天全表扫描）；
- 员工侧：`SPEAKER_MATCH` 日志永远不可见、`MINUTES` 归属随重新生成漂移；`agent.selectByMinutes` 可看他人运行详情；
- 无成本字段、无预算、无限流；无 trace/metrics/告警（旧分支有 Jaeger/Redis 限流/预算闸，当前没有）。

## 4. P2：低危/工程化清单（摘要）

1. `/docs`、`/openapi.json`、`/redoc` 无鉴权（本机 19092 可访问，nginx 未反代，风险低）；
2. `GET /files/download/{filename}` 无鉴权（实测未登录可下头像，文件名 uuid 随机降低枚举性）；
3. 全局异常处理器硬编码 `Access-Control-Allow-Origin: *`，与「同源部署」语义不一致；CORS 实际未装中间件（OPTIONS 405）；
4. `REGISTER_ENABLED` 代码默认 `True`（注释写默认关闭），`/register` 路由未拦；
5. 无登录限流/账号锁定（实测连续 5 次错误密码均正常处理）；无密码强度校验（注册/改密/新增用户）；
6. 无服务端 logout/吊销（仅 localStorage remove）；JWT 24h 无 refresh；
7. 模型错误原文透传页面/DB（`model_factory.py:121-122`）；`min_value` 未校验的 `.env` 数字（如 `ASR_TIMEOUT_SECONDS=10m`）会让 bootstrap 直接失败；
8. 列表接口无长度/字符集校验，超长文本 → MySQL DataError → 「系统错误」；

## 5. 作为「前后端 AI Agent 项目」的关键欠缺

> 完整版见 `C:\Users\admin\AppData\Local\Temp\review\agent-gaps.md`，这里给结论与优先级。

### 5.1 本质判断：LLM 工具 ≠ Agent 系统

当前唯一的「Agent」是 `services/agent_graph.py:52-110` 的三节点反思环（review→refine→finalize，最多 5 轮），由 LangGraph 编排；其余是固定管线（转写 → 分块 map-reduce 生成 → 反思环 → 人工确认）。对照 Agent 常见能力：

| 能力 | 当前 | 说明 |
|---|---|---|
| 反思/自我批判 | 有（弱） | 唯一自主行为 |
| 工具调用 / function calling | 无 | 无 tool 定义，只有 LLM 返回 JSON |
| 规划 / 多步任务分解 | 无 | 图写死；分块是数据分片不是规划 |
| 记忆（短期/长期） | 无 | 无会话、无跨会议事实 |
| 检索 / RAG | 无 | 转写全文截断 2 万字符直接喂审查（`agent_service.py:137-145`） |
| 多轮对话 / 流式输出 | 无 | 无 chat；SSE 只推运行状态 |
| 人机协同 | 有（弱） | 中断/恢复/应用/拒绝，无部分采纳、无反馈沉淀 |
| 评测/回归 | 无 | 无 golden set、无指标、无 CI 评测 |
| 成本/预算/限流 | 无 | 无配额、无预算闸、无降级；任意可见者可反复触发付费调用 |
| 安全护栏 | 无 | 无 prompt injection 检测、无审核、无 PII、API Key 明文入库 |
| 可观测（Agent 轨迹） | 部分 | `agent_step` 有每步时间线，但无 trace/指标/告警 |

### 5.2 旧分支有、当前没有（按重要性）

1. **工具调用 Agent + 多轮对话**（旧 `chat_tools.py/chat_graph.py/chat_service.py`，单 Agent + 5 工具）
2. **知识库/RAG + 引用绑定**（旧 `kb_*.py/hybrid.py/citations.py`，pgvector+BM25+RRF，纪要确认才入库）
3. **评测体系**（旧 `evaluation/` 1053 文件、RAGAS 基线、回归/轨迹/工具选择测试）
4. **记忆/会议系列/待办**（旧 `memory_service.py/series_service.py/action_item_service.py`）
5. **持久化任务编排**（旧 compose 有 temporal/redis/jaeger；当前单进程 asyncio）
6. **模型工程化**（旧 `pricing.py`、失败分类/重试/预算闸；当前 `model_factory.py:37-38` `max_retries=0`，一次失败整任务失败）
7. **安全护栏**（旧 `prompt_injection.py`、`moderation.py`、`test_injection_redteam.py`）
8. **MCP / 外部工具生态**（旧 `test_mcp_server.py`）
9. **AI 前端**（旧 `Chat/Memory/MeetingSeries/ActionItems.vue` + `CitationCard/CostPanel/OnlineEvalPanel` + TS/vitest/eslint）

### 5.3 最有价值、改动量最小的 5 件事（建议顺序）

1. **评测闭环**（1~2 天）：5~10 场标注会议做 golden set；指标：字段覆盖率、决策召回、引用准确率、人工采纳率；改 prompt 前后跑同一套指标并留 artifact。这是「AI 工程」与「LLM demo」的分水岭。
2. **引用/证据绑定**（1~3 天）：六个纪要字段的每条内容带 `segment_id + start_ms + speaker`，前端可跳转/对照；直接回应幻觉问题，也为 RAG 铺路。
3. **工具化 Agent**（约 1 周，可小步）：先落「行动项」表 + 确认纪要后自动生成待办，再扩 `search_minutes/get_transcript` 两个只读工具，做最小 chat 面板（多轮 + SSE 流式）。
4. **可靠性/成本护栏**（2~3 天）：失败分类 + 仅瞬态错误指数退避重试 + 单任务 token 预算 + 每用户每日配额；分段/分块结果落库支持续跑。
5. **前端 Agent 体验**（3~5 天）：自检详情「修订前后 diff + 按条应用/拒绝」；聊天面板流式 + 引用卡片；顺手做路由懒加载 + gzip/缓存/安全头。

> 不建议现在做：多 Agent 协作、Temporal/消息队列、pgvector 全套基础设施——个人项目投入产出比低，先把「工具调用 + 评测 + 引用」做扎实。
