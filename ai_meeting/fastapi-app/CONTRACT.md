# 契约层：把不变量下沉到数据结构

日期：2026-09-25。范围：六类已实测缺陷的**系统性修复**，以及共享判据的合并。

---

## 一、为什么不是继续加规则

前几轮的做法是"发现一类缺陷 → 加一条检测规则 → 词表漏一个写法 → 多一个假阳性"。
这条路必然过拟合：**缺陷类是有限的，写法的变体是无限的**。实测已经撞到墙上：

- 期限字段误用（动作写进时间槽）只能靠"这个字符串像不像时间"事后猜；
- 无依据内容只能用词法覆盖度猜，而它在三种归一化下符号翻转；
- 审查规则（如 `MISSING_DEADLINE`）没有证据约束，误报率 77.8%；
- 评测套件与产品各写一份归一化与身份判据，必然漂移。

本轮换做法：**把不变量下沉到契约**，让违规在结构上可判定、甚至不可表达。

---

## 二、五条不变量

| # | 不变量 | 违规如何变成可判定 |
|---|---|---|
| 1 | **类型化槽位**：断言值的槽位必须声明 `basis`（stated / derived / open_ended / not_mentioned / model_inferred） | "动作写进时间槽"= `basis=stated` 但文本不承载时间语义 → `slot_type_mismatch` |
| 2 | **来源闭合**：`basis=stated` 必须给出能在原文定位的证据；`derived` 必须给出锚点 | 无依据的断言 → `stated_without_verifiable_evidence` / `derived_without_anchor` |
| 3 | **证据只在断言处允许**：非断言槽位带证据即违规 | 伪造引用 → `evidence_on_non_assertion` |
| 4 | **审查证据策略**：每类 issue 声明需要哪种证据（正向证明"原文有" / 反向证明"原文没有" / 不适用） | 缺失类规则无前提 → `missing_rule_without_premise`；无依据类规则的目标其实在原文里 → `unsupported_claim_present_in_source` |
| 5 | **保默认**：初稿里存在而修订稿里消失的条目，必须有显式删除声明 + 理由 + 证据 | 静默删除 → `silent_deletion` / `unjustified_deletion` |

**关键性质：新增字段或槽位不需要新检测代码。** 只需在 `SLOT_KINDS` 或 `ISSUE_EVIDENCE_POLICY` 加一行，schema、校验器、提示词说明三者同时生效。

---

## 三、一处定义，多处派生

```
contracts.SLOT_KINDS / BASE_ITEM_FIELDS      ← 唯一真源
        ├─→ minutes_json_schema()            模型看到的 JSON Schema
        ├─→ minutes_pydantic_models()        落库前的结构校验
        ├─→ present_output()                 前端/导出看到的字符串
        └─→ validate_minutes()               不变量校验

contracts.ISSUE_EVIDENCE_POLICY              ← 唯一真源
        ├─→ review_json_schema()             模型看到的审查结构
        ├─→ issue_evidence_guide()           附在提示词后的证据要求说明
        └─→ check_issue_evidence()           取值层面的条件强制
```

以前这三处各写一份，必然漂移。现在只有一张表。产品源码里 `build_schema_instruction` 的注释已经确立了同一原则（"结构约束只写在 SCHEMA 常量里，管理员改 Prompt 模板不影响它"），本轮只是把它贯彻到校验与展示。

---

## 四、共享判据（消除两套实现）

三个判据过去在产品和评测里各有一份，是漂移的直接来源。现已抽成共享模块，**评测读产品的定义，不再自己猜**：

| 模块 | 内容 | 谁在用 |
|---|---|---|
| `common/timex.py` | 时间语义判定（结构化日期 / 相对偏移 / 时长 / 开放时段 / 非断言） | 产品契约校验、评测指标 |
| `common/textsim.py` | 文本归一、条目身份判据（相似度 + 最长公共块）、措辞覆盖 | 产品静默删除判定、评测配对与合并识别 |

`evaluation/metrics/grounding.py` 通过 `shared_contract` / `shared_normalize` / `shared_is_same_item` / `shared_time_basis` 委托过去；产品目录不可用时退回本地实现并**如实标注用的是哪一份**。

两个判据里的阈值都是在真实数据上校准出来的，不是先验设定：相似度 ≥0.5 且最长公共块 ≥min(4, 较短长度)——第二条是实测加上的，没有它短条目会因两字巧合被大量错误配对（"旧事项" vs "全新的事项" 相似度恰好 0.5）。

## 五、契约版本与迁移

- 存储是**类型化且带版本**的（`contract_version = 2`）；展示是字符串的。
- `upgrade_output()` 读侧收敛：把 v1 的裸字符串槽位升级为类型化槽位，**幂等**。
- `present_output()` 写侧适配：产出消费方需要的 `owner_suggestion` / `deadline_suggestion` 字符串。
- **不新增数据库列、不做迁移**：表结构来自 `ai_meeting.sql`，而契约违规是**从已存 JSON 派生的诊断**，按需求算而不是存起来（存了就是会漂移的缓存）。
- 表现适配只有**一个出口**（`present_minutes_fields`），详情、导出（DOCX/PDF）、写回共用它。实测：导出与前端代码**一行未改**。

旧数据里的"动作写进时间槽"值**不被静默丢弃**：升级时如实保留文本并标 `basis=stated`，由校验器报 `slot_type_mismatch`。有测试守着。

## 八、本轮抓到并修掉的自身缺陷

新写的代码也被自己的测试抓到两个真实 bug，都记在这里因为它们界定了判据的边界：

1. **`2026-09-28` 被判为"非断言"**——非断言标记里有 `-`，按"包含即命中"就命中了日期。修法：短而有歧义的标记必须**整体相等**，只有本身是短语的标记才允许包含匹配。
2. **`乙事项` 被判为删除**，尽管 `关于乙事项的进一步说明` 明显包含它——3 字条目取不出 4-gram，措辞覆盖判据失效。修法：身份判据增加**子串包含**分支，覆盖"展开/拆分"这一常见形态。

另外修正了一处编辑失误：把 `agent_service` 的病历块插入到了错误的缩进层级，吃掉了 `except` 分支；已修复并编译验证。

## 九、这套设计**没有**解决的问题

必须说清楚，避免把结构性修复当成万能：

1. **不变量保证"可判定"，不保证"判断正确"。** `basis` 是模型自己标的；标错时校验器只能抓到*不一致*（标了 stated 却给不出证据），抓不到*标错但自洽*。真正的准确性仍需要人工裁决（见 `GAP_REMEDIATION_RESEARCH.md` 第五节）。
2. **"有依据"的标准仍未写入代码书。** 类型层能表达"这个值是怎么来的"，但不能决定"什么样的推导算合法"。D1–D5 五项许可操作仍需作为文档落地。
3. **内容级无依据仍无可靠代理。** 契约让条目可以引用来源句，因此未来可以走 ALCE 式的引用召回/精确率，但产品当前还不产出引用。
4. **召回侧（漏记）仍无度量。** 静默删除不变量管的是"多删"，不管"漏写"。
5. **一次运行的真实模型行为尚未验证。** 本轮全部改动未经付费调用验证——schema 变了，模型能否稳定产出符合新契约的结构，需要一次授权运行才能确认。这是最大的未验证点，不能默认它一定成功。

## 十、测量方法与一条硬限制：哪些能在旧数据上回溯测，哪些不能

契约不变量已接入离线指标套件（`evaluation/metrics/contract_checks.py`），因此**每次
`run_metrics.py` 都会自动产出契约指标**，不需要另写脚本：

```bash
# 契约层需要 pydantic，所以要用产品的 venv 跑评测套件
ai_meeting/fastapi-app/.venv/bin/python evaluation/metrics/run_metrics.py --set all
```

### 可在旧产物上引用

| 不变量 | 判据性质 | test26 | dev22 |
|---|---|---:|---:|
| `slot_type_mismatch`（期限字段误用） | **⚠️ 上界，不是定义性判定**——见下方更正 | 初稿 10 / 自检后 9 | 初稿 21 / 自检后 19 |
| `silent_deletion`（初稿有、自检后消失且无声明） | 半定义性：身份判据来自共享的、校准过的 `textsim`，与一处独立实现交叉验证（先前用 4-gram 覆盖度独立算得 75/99） | **71** | **95** |

**⚠️ 更正（2026-09-25 复核，推翻本节原先的写法）**：本节此前写 `slot_type_mismatch`
"判据是定义性的……没有启发式，不存在假阳性"。**这在旧产物上不成立**：

旧产物里 `basis` 不是模型声明的，而是升级路径（`contracts._upgrade_item`）推断的——
非空裸字符串一律标 `stated`，只有命中非断言词表的才标 `not_mentioned`。因此凡是
"语义上是『未定』但措辞不在词表内"的值，都会被记成"声明了却没有时间语义"。实测：

| 数据集 | 契约代 | 合计 | 每场 | 备注 |
|---|---|---:|---:|---|
| synthetic | v1 | 5 | 0.83 | 4 条是 `未定`、1 条是 `即时生效` |
| VCSum test26 | v1 | 19 | 0.73 | 混着真缺陷（`完成数据收集和目标差距分析`）与词表漏写法（`持续跟进`、`具体时间未定`） |
| VCSum dev22 | v1 | 40 | 1.82 | 同上（`具体时间待定`、`会后跟进`） |
| **VCSum test26（契约 v2 实跑）** | **v2** | **3** | **0.12** | **这一批才是定义性的**：`basis` 由模型自己声明，词表漏写法不产生假阳性 |

因此：**跨代比较这一项等于比较两件事**。旧产物上的数字只能当上界引用；
`metrics/contract_checks.py` 现在会在计数下方直接列出原值供人工分辨，
并把这条限制写进 `RETRO_MEASUREMENT["legacy_slot_mismatch_caveat"]`，
报告渲染时一并打出来。

### 不能在旧产物上测量（硬限制，不是待办）

`stated_without_verifiable_evidence`、`item_without_verifiable_evidence`、
`missing_rule_without_premise`、`evidence_on_non_assertion` 四项**无法回溯测量**。

原因：旧契约（v1）的槽位是裸字符串，**模型从未被要求给出 `basis` 或 `evidence`**。
在旧产物上跑这些不变量，每一条带文本的断言都必然失败——那是把新契约的缺失记成旧数据
的缺陷，是**测量假象**。实测印证：test26 初稿"失败" 94 + 522 条、dev22 123 + 459 条，
**换用真实转写后数字完全不变**——正因为它们与转写无关，只与"没有证据字段"有关。

因此套件把它们单独放在 `legacy_artifact_counts` 下并标注**禁止引用**，报告里也会打印
假象总数（test26 272 条、dev22 1190 条）。**这四项只有在新契约下真实运行一次之后才有意义。**

### 为什么不给"近似实现"

契约判定没有近似版——近似就是另一套规则，而本轮的全部工作正是消除"两套规则"。
产品目录不可用时，套件**明确报告不可用**并说明原因，而不是退回本地近似。
这与 `grounding.shared_contract` 的处理一致。

## 十一、验证运行方案

### 目的（按重要性）

1. **模型能否稳定产出新契约**——`basis` + `evidence` 是否被填、填得对不对。这是当前最大的未知，也是唯一必须花钱才能回答的问题。
2. **四项证据类不变量的真实发生率**——目前在旧数据上完全是未知数。
3. **期限字段误用是否因 schema 变更而下降**——旧数据为 10（test26）/ 21（dev22）条，理论上应显著下降。

### 分三阶段，每阶段有决策门

| 阶段 | 规模 | 预算（模型调用） | 通过判据 | 不通过则 |
|---|---|---:|---|---|
| **1 冒烟** | 3 场 | **≤ 24** | 六字段结构合规；`basis` 非空率 ≥ 90%；无 `slot_type_mismatch`；至少 1 条 `evidence.quote` 能在转写定位 | 停下读原始输出，判断是提示词问题还是 schema 过复杂；**不要**直接扩大运行 |
| **2 计量** | 10 场（含阶段 1 的 3 场） | **≤ 80** | 四项证据类不变量有非零计数（说明门控在工作）；`stated_without_verifiable_evidence` 占比 < 50% | 若模型普遍不填证据 → 把 `evidence` 改为可选后重测，而不是放弃契约 |
| **3 全量** | 26 场（test26） | **≤ 200** | 与阶段 2 比率一致（无系统性漂移） | 报阶段 2 数字并标注未全量 |

**预算口径**：沿用既有账本机制，`--authorized-llm-calls` 必须显式传入，缺失即拒绝。
每场约 6 次调用的经验值（test26 历史 156 次 / 26 场）来自生成 1–4 次分块 + 自检最多 4 次。
**本次运行不含 ASR 调用**（沿用既有文本 fixture 路径）。

### 执行前检查

- [ ] 容器内产品镜像已更新到含新契约的版本（`docker compose up -d --build backend`）
- [ ] 预检确认 schema 指纹已变化：`run_public_eval.py --mode preflight`
- [ ] 既有产物已备份（本次写入新 run 目录，不覆盖旧结果）
- [ ] 授权额度明确（阶段 1 为 24 次）

### 允许与不允许的结论

**允许**：模型对新契约的产出率、四项证据类不变量的发生率、期限字段误用的变化、每场调用与 Token 开销。

**不允许**：任何"质量提升/退化"的因果结论（无对照臂）、任何人类有效性声明（无人工金标）、把两阶段数字合并成一次实验（阶段 2 是阶段 1 的超集，不是独立重复）。

### 失败处理的首要怀疑对象

契约变更后的首次运行**最可能暴露的是提示词与 schema 不同步**，而不是模型能力问题：
`ai_meeting.sql` 里种子化的提示词正文仍写着 `deadline_suggestion` 等旧字段名（72 处），
而 `build_schema_instruction` 会把新 schema 追加在正文之后。两者冲突时模型行为不确定。
因此**阶段 1 若失败，第一件要查的是提示词正文与 schema 是否互相矛盾**，而不是调 schema。

（`contracts.coerce_item` 已经能接住旧键名，不会静默丢数据；但提示词正文与 schema
语义冲突时，模型可能两边都不满意，这时需要的是把正文也更新到新契约。）

## 十二、验证运行记录

### 供应商切换：Qwen/百炼 → DeepSeek

主模型已切到 `deepseek-flash`（`https://api.deepseek.com`）。切换过程中发现并解决一个
**会导致请求直接失败**的问题，以及一个**会导致长纪要截断**的问题：

| 发现 | 处理 |
|---|---|
| DeepSeek **不支持** `response_format={"type":"json_schema","strict":true}`，只支持 `json_object` | 结构化输出改为**能力驱动**（`common/providers.py`）：声明表按主机决定策略，新增供应商只加一行 |
| `response_format` 用错**不影响本地测试**，只在真实调用时才失败 | 因此新增了零成本的声明表单测 + 一次最小连通性验证，把这类问题前移 |
| deepseek-flash **默认开启思考**，实测一次抽取中 **97% 的输出 token 是推理**（2242 中 2175） | 推理改为**按调用类型声明**（机械抽取关、审查/修订开），并把 `LLM_MAX_TOKENS` 从 4096 提到 16384，避免推理挤掉 JSON |
| 思考关闭后同一任务：延迟 10.29s → **0.57s**，输出 2242 → **81** token，答案相同 | 机械类调用（分段抽取/合并/说话人匹配）一律关推理 |

推理与结构化输出被拆成**两件独立声明**：前者按**任务性质**（与供应商无关），
后者按**供应商能力**。混在一起写就会出现"换个供应商就得改调用代码"。

## 十五、对齐业界的运行时改动（2026-09-26）

三条改动都是"把已经写在契约层里的东西接到运行时"，不是新机制：

1. **审查证据硬门控**（`gate_issues_by_evidence`）：证据要求不满足的意见**不许推动重写**；
   一条不剩则本轮判通过；被挡下的意见原样保留在步骤 payload 里。
   实测（历史 46 条真实意见离线复算）：保留 42、挡下 4（全是"缺失类给的前提定位不到"），
   且真实意见的证据字段完整度 100%，门控不会让审查空转。
2. **证据门控保留**（`enforce_preservation(..., transcript=...)`）：
   只恢复"本来有可定位证据"的消失条目。实测依据：历史 80 条消失条目里 77 条（96%）
   带可定位证据（过度修订）；另 3 条无依据，允许无声明丢弃——全盘恢复会丢掉
   "清除无依据内容"这个核心功能。
3. **生成侧内容归零护栏**：合并步参照各分段的并集，内容全空即按失败处理。

**两处更正**：

* 契约文档第 6 条（"refine 输出编辑指令而不是重写全文"）**是设计声明，不是运行时事实**；
  运行时是"自由重写 + 声明 + 保默认"。本轮不改协议，改为让保留判据看条目自己的证据，
  理由是声明协议的可观测性刚刚才补齐（见下条），换协议的风险大于收益。
* 旧构建里 `revised.raw_model_output` 是**消费后**产物（六字段），`dispositions` 被
  `enforce_preservation` 吃掉后不落盘——因此"模型不给删除声明"这个说法当时**无法被观测**，
  据此下的结论已撤回；重建后那次运行的原始输出里确实有声明（2 条，各带 2–3 条证据）。

## 十六、生成侧根因护栏，与两处工具层误诊的更正（2026-09-26）

### 16.1 单分块生成路径此前完全没有护栏（已部署，**未在真实运行中触发过**）

`is_content_empty_rewrite` 是**内容级代理**，它拿两份输出的条目数相比，**只在"有参照物"
时成立**：重写步有初稿、合并步有各分段。而 `minutes_service.execute_minutes` 的
**单分块路径（`result = partials[0]`）没有参照物**，因此那条判据在它身上根本无从下手
——这条路径此前一道护栏都没有。

补的不是第三个代理，而是**根因**。事故（`vcsum_21`）的机制不在内容层，在**默认值层**：
`minutes_pydantic_models()` 给 `summary` 默认空串、给五个列表字段默认 `[]`，
于是 `model_validate({"summary": ...})` 通过，"模型没给"被补成"模型给了空的"。
Pydantic 恰好记录了这个区别，所以直接读它：

| 函数 | 读的是什么 | 判什么 |
|---|---|---|
| `unprovided_content_fields(model)` | `model.model_fields_set` | 原始输出里**没出现**的内容字段名 |
| `is_unprovided_content_generation(model)` | 同上 | 五个列表字段**全部**未提供 → 按失败处理 |

**边界写清楚，免得以后被当成疏漏**：

* 显式给了空数组（`"topics": []`）**不算异常**——会议确实可以没有决策；
  默认值把这两件事混成一件，这两个函数要能把它拆开；
* 只缺一两个字段**不按失败处理**（那不是事故形态，误伤会直接拉低可靠性）；
* 读不到 `model_fields_set` 的对象（普通 dict）**不判违规**——这一条只在**确证缺席**时成立。

覆盖：6 项单测（含上面三条边界）。**"实现了"与"验证了"分开写**：

| 环节 | 状态 |
|---|---|
| 函数与边界 | **已验证**：6 项单测，含三条"不误伤"的反例 |
| 解析链没偷偷补默认值（护栏会不会变成静默零的关键） | **已验证**：用**真实事故产物**跑完整链——`vcsum_21` 的 `revised.raw_model_output`（只有 `summary`、627 字）经 `parse_model_json` → `model_validate` 后 `model_fields_set` 仍只有 `summary`，护栏返回 `True`。`SchemaJsonParser` 只多剥代码块围栏，确认**不补字段** |
| 进了线上镜像 | **已验证**：容器内 `/app/services/contracts.py` 与 `/app/services/minutes_service.py` 都 grep 到该函数（与保默认、内容归零、审查双层门控同在） |
| 真实运行中触发过 | **没有**。与 `enforce_preservation` 当初的处境相同——"已部署"不等于"已验证有效" |

### 16.2 更正一：产品**从未**受"接口慢"影响，受影响的是宿主侧的评测脚本

上一轮把「一次生成 159 秒、一次判定 169–188 秒」记成"接口会突然变慢"。实测（细节见
`evaluation/RUN_INDEX.md` 第十一节）：宿主每次建连要先耗尽不可达 IPv6 的连接重传
（**133.5 秒**），容器内同一行代码 **0.0 秒**——两边解析顺序相反。
因此：**26 场产品运行的产物没有被这个缺陷污染**，被污染的是在宿主上跑的评测脚本
（完整性评测、会议级判读、引用级判读）以及它们的耗时结论。

### 16.3 更正二：「思考开关对耗时没有影响」是**不可读**，不是"无效"

那条对照（开 135.5 秒 / 关 134.6 秒）两次都测在同一个 135 秒传输停顿上，
**它不可能测出模型侧的任何差异**。传输修好后同一小提示重测：开思考 106 token、
关思考 59 token——**开关在生效**。而同一份**大**输入上（会议级判读）差异是数量级的：
`thinking=OFF` **1.2 秒** / `thinking=ON` **317.3 秒**。

由此得到一条可操作的规则：**排查"调用很慢"之前，先分三段看**
——`probe_transport()` 的逐地址族连接诊断（网络）、`timings.to_headers_ms`（服务端何时
给出响应头，即模型 TTFT）、`timings.body_read_ms`（吐字时长）。只报一个总时长的观测
无法区分这三者，本项目因此误诊过一轮。

### 16.4 更正三：会议级判读的**评测脚手架自己制造过"无依据"**

首次跑通会议级读数后，`thinking=ON` 的敏感性子样本暴露出判定例证里有一类：

> 「纪要称本次为圆桌讨论的**完整**合并纪要，但转写明确提示**可能已截断到 60000 字符**，
> 无法支持『完整』这一说法」

那句"可能已截断"是**评测提示词自己写的**，而且是无条件写的——本语料最长转写 47,972 字，
**一次都没有真的截断**。**脚手架把免责声明写成了判定者眼里的"纪要不完整"的证据。**
同源的还有第二类：纪要是照**会议标题**写的（`本次乡村教育论坛（VCSum 31）`），
标题来自夹具清单、不在转写片段里，于是被判成"凭空出现的编号"。

对产品的含义有两条，都值得记住：

1. **给判定者的每一句话都会被当作证据**。尤其是无条件给出的"可能不准"这类声明——
   它在人眼里是免责，在判定者眼里是事实陈述。要写就写成条件式的（"确实截断了才说明"）。
2. **凡是模型看不到、但产品能看到的信息，都必须一并交给判定者**（这里是会议标题）。
   否则判定者会把它算成"产品凭空捏造"——**这是评测侧的假阳性，不是产品缺陷**。
