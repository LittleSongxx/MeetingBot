# AliMeeting4MUG：AIMeeting 行动事项评测协议

本协议在查看模型输出前固定口径。数据集为 ModelScope `modelscope/Alimeeting4MUG` 的 `default.validation`（65 场）和带标签的 `default.test` / `except_TS_test1.zip`（82 场）；源文件 SHA-256 见 `source/alimeeting4mug/source-manifest.json`。test1 是公开的第一阶段带标签测试集，不等于不可见的最终挑战榜单。

## 被测系统和输入

- 一场会议作为一个配对样本。每条 `sentences` 保留原始顺序、speaker 和秒级时间，作为一个 `TranscriptSegment`；文本先进入原项目 `execute_minutes`，其初稿再进入 `execute_agent_run`。绕过 ASR，故任何结果都不是转写 WER/CER。
- 模型端只收到转写与片段；`action_ids` 和其他金标始终留在宿主评分端。每次运行锁定数据哈希、产品/模型配置、Prompt 哈希、参数、调用账本和原始输出。
- 比较初稿与 Agent 修订候选稿。修订候选稿未自动采纳；前后差异是整条生成与审查流水线的配对观察，不是严格的单因素因果消融。

## 自动可核验指标

逐场记录执行成功率、六字段 Schema 有效率、Agent 是否生成修订、实际 LLM 调用数、Token、模型耗时与总耗时，并按会议报告分布。失败场次计入覆盖率分母。单独报告源文长度、分块数与审查上下文截断情况。

`action_ids` 是句级行动相关标签。test1 中 236/43,228 句为正例，32/82 场无正例；绝不以 Accuracy 单独代表行动项能力。产品的 `decisions`/`pending_items` 是生成式条目且没有来源句 ID，因此**不能直接计算官方 AID Precision/Recall/F1**，也不能把字符 ROUGE 或模型自评分当成行动项质量。

## 内容质量人工评测

先在 dev 固定判定手册，再对 test1 使用至少两名互相独立的标注者；标注时隐藏金标及“初稿/修订稿”阶段，分歧仲裁后才揭开金标。对 `decisions` 与 `pending_items` 的每个条目记录：是否为未来可执行事项、是否有原文直接证据及其主要 `sentences.id`、是否把疑问/建议/历史事实升级为承诺、是否重复。跨句合并可关联多个 ID；没有证据、无法确定来源和非行动决策须分别标记，不能从分母中消失。

主结果应报告生成项级的有据且正确比例、无依据率、重复率，以及金标行动相关句覆盖率；零正例会议另报误报场次率。可附“人工锚定句集合”对金标的 P/R/F1 作为诊断，但须明确它不是官方 AID 榜单分数：后验句子映射和生成式任务定义均不同。负责人、截止日期没有对应公开金标，只能另做原文证据人工审查，不能报公开集字段准确率。

初稿与修订稿按同一会议配对，报告绝对差值和会议级 bootstrap 95% 区间；dev 用于调试与判定手册，test 不据结果反向调 Prompt。小样本运行标为探索性试跑，不外推为完整 82 场成绩。
