# AliMeeting4MUG 盲审填写说明

评审者只使用 `source_sentences.csv` 和 `review_items.csv`。按 `case_id` 查找整场原句，用 `sentence_id` 引用直接证据；不要打开 `stage_key.json`、`action_ids` 或产品原始报告。A/B 是同一会议的两个匿名版本，不推测顺序。先由两人独立填写副本，再对不一致处仲裁并形成一份完整的 `review_items.csv`。

每条生成内容的五个空列按以下口径填写：

| 列 | 允许值 | 判定口径 |
| --- | --- | --- |
| `evidence_sentence_ids` | 空，或 `12;13` 形式 | 直接表达该条核心行动/事实的原句 ID；跨句信息可填多个。不以同主题、仅提供背景的句子凑证据。 |
| `actionable` | `0` 或 `1` | 是否提出具体、未来可执行的动作；纯现状、已发生事实、静态决策、泛泛愿望填 `0`。尚待确认的具体建议仍可填 `1`，并在 `overstated` 判断其确定性表述。 |
| `grounded` | `0` 或 `1` | 条目所有关键事实、对象、金额、时间和责任归属均获原文支持才填 `1`；局部相似但新增关键细节填 `0`。填 `1` 必须有至少一个证据 ID。 |
| `overstated` | `0` 或 `1` | 将疑问、假设、建议或待讨论方案写成已确定承诺，或擅自补齐负责人/期限，填 `1`。 |
| `duplicate` | `0` 或 `1` | 同一 A/B 版本内重复表达先前已出现的相同行动，后出现的条目填 `1`；不同版本之间不互判重复。 |

`decisions` 中可能有合理的非行动决策，不应仅因 `actionable=0` 判它错误；`pending_items` 中可能有待确认建议，不应仅因出现在该栏目就视作承诺。若一条内容既有直接证据又加入了无据细节，可填写部分证据 ID，但应设 `grounded=0`。如原文无法判断，评审者应在独立备注中记录疑点，仲裁后再填确定的 `0/1`；评分工具不接受空白或 `?`。

仲裁完成后使用 `alimeeting_annotation_score.py` 离线评分。其“锚定句 P/R/F1”是把生成条目人工映射回原句后的诊断，不是官方逐句分类器的 AID 榜单分数。零金标会议出现行动输出也只是待核查信号，不自动等于幻觉。负责人、期限没有公开集字段金标，不能据此报告字段准确率。
