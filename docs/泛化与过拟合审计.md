# 泛化与过拟合审计（2026-10-23）

> 原则：**只做系统级、可迁移的机制优化**；不针对单个 badcase 加特判规则；
> 机制只允许依赖通用输入（问题文本、工具 schema、转写、检索上下文、结构化契约），
> 不得出现评测 case id / gold 路径 / 某次实验名；阈值先预注册，效果必须跨集报告。

## 0. 结论

- 已落地机制里，**S1 引用绑定** 风险最低（规则作用于"数字/日期 × 引用上下文"的通用结构，
  离线已在 6 个 packet 上复算，运行时 4 次重复 A/B）；**S3 槽位守卫** 属通用规则，
  在两个 test26 产品运行上稳定，但 constants 有样本启发成分，需 held-out 金标复核；
  **S2 状态覆盖** 的关键词线索有"按评测问题措辞设计"的过拟合风险，已被 A/B 否决并默认关，
  不再作为机制使用（后续改工具契约）。
- 新增静态守卫 `tests/test_no_eval_leakage.py`：扫描产品 `services/api/common` 的**运行时字符串**，
  禁止评测集专属标识；注释/docstring 可保留真实事故出处（不参与行为）。当前通过。

## 2. 关键检查：我们有没有"按评测集调参"？

- **无 case id 分支**：产品代码无 `cross30/`、`vcsum_XX`、`m0xx` 之类的行为分支；
  静态守卫测试通过（只允许注释里作为事故出处出现）。
- **无 gold 读取**：产品运行时不读 `evaluation/gold`；评测脚本与产品代码分离。
- **阈值来源**：质量闸阈值是预注册下限（防退化线），不是按单次结果贴边调；S1/S2/S3
  的判定线在跑之前写进 LEDGER；S2 的失败按预注册保留为负结果（没有改线重判）。
- **已知风险点**：S2 的线索词确实是从 cross30 题型归纳出来的；它已被 A/B 否决，
  没有进入默认行为，且后续不再走"线索词提示"路线。
- **S3 的 dev22 结果**：旧 schema 的 74 条 pending_items 里 evidence 字段缺失、owner 是自由文本，
  规则把它们判为 fabricated/unlocated 属于 **schema 不可比**，不是"模型更差"；
  这也说明校验器应只对**类型化槽位**生效（产品运行时走 `contracts.upgrade_output` 后再校验）。

## 3. 后续优化的泛化约束（写死）

1. **S2 备选（工具契约扩展）**：只改工具输出 schema——
   - `query_meeting_state(kind=decision)` 的条目带 `supersedes_id`、`minutes_status`（DRAFT/CONFIRMED）、
     关联 action_item 的状态摘要；
   - `list_facts(kind=recording/meeting)` 带 `series_id/系列内会议列表`；
   这是**数据契约**，对任何会议通用，不改提示词、不按 case 特判。评估：cross30 + new_meeting + eval100
   三个集，主指标 recall-v2；必须跨集同向才采纳。
2. **S3 item F1**：先在**独立会议**上建 AI-draft gold（标注 `human_checked=false`），
   再评抽取 F1；gold 集与调参集分开，禁止用评测产物当 gold。
3. **任何新机制**必须满足：
   - 机制说明书只引用通用输入；
   - 先离线/零调用回放，再付费 A/B；
   - **至少两个集**报告（开发集 + 一个未见集/held-out）；
   - 负结果保留、不改判定线；
   - 阈值/常量不来自单条 badcase。
4. 每条新机制合入时跑 `tests/test_no_eval_leakage.py`（产品运行时字符串静态扫描）。

## 5. 不做清单（防过拟合）

- 不为单个 case 加关键词/正则/特判（例如"m012 就提示查 action_item"；
  "cs 系列题就加 series 提示"）——S2 的教训；
- 不把评测集 gold 当产品输入或阈值来源；
- 不在看到结果后改判定线/换分母（S2 负结果按原线保留）；
- 不把"单次运行差异"包装成机制提升（faithfulness 单次波动约 5pp）。
