# RAG 全链路参数（标准化配置，2026-10-17）

这份表回答一个问题：**这条 RAG 链路的每个可调参数现在取什么、为什么取这个、改了要付什么代价。**
取值的依据是公开做法（Qdrant 官方索引/过滤文档、Azure RAG 检索阶段指南、DashScope 模型文档）
与本语料上的实测（`evaluation/LEDGER.md` 的「标准化链路」一节），**不做学术式消融**。

## 一、链路与参数

```
转写/纪要 ──切块──▶ 切片（300 字窗口，2 行重叠）
    ├─ 稠密：qwen3.7-text-embedding（1024 维）
    ├─ 稀疏：字符 bigram 次线性 TF + Qdrant 服务端 IDF（= BM25 词法口径）
    ▼
Qdrant 混合检索（prefetch 24 × 两路，服务端 RRF 融合）
    ▼
qwen3.7-text-rerank（专用 cross-encoder 类，24 候选打分）
    ▼
截断 top-3 ──▶ 生成模型
```

| 参数 | 当前值 | 位置 | 改它要付什么 |
|---|---|---|---|
| 窗口字数 | **300**（`KB_CHUNK_TARGET_CHARS`） | `services/kb_chunking.py` | 换值 = 切片正文变 → 内容指纹变 → 下次索引自动重建（要重嵌） |
| 重叠 | 2 行（约 15%） | 同上（常量） | 同上；重叠太少会切断跨句事实，太多会重复召回 |
| 切分方式 | 句读边界（`。！？；`）+ 单句上限 800 字硬切 | 同上 | 会议转写是连续口语，没有章节结构；按句读切比固定窗口稳定 |
| 稠密模型 / 维度 | `qwen3.7-text-embedding` / **1024**（`EMBEDDING_MODEL`、`EMBEDDING_DIM`） | `.env` → bootstrap 同步到 `ai_model_config` | 换模型/维度 = 换向量空间，必须重建（指纹含模型名与维度，自动触发） |
| 稀疏臂 | 字符 bigram 次线性 TF + **IDF 由 Qdrant 按语料统计** | `services/kb_sparse.py`、`common/qdrant.py` | `modifier=idf` 是**建库时**的声明；换它要换 collection 名重建（代码会 fail-fast 而不是静默退化） |
| 混合与融合 | 两路各 prefetch 24，服务端 **RRF**（`query.fusion=rrf`） | `common/qdrant.py` | 候选深度影响召回；RRF 免调权重 |
| 重排 | `qwen3.7-text-rerank`（`RERANK_MODEL`；`RERANK_BASE_URL` 可指专属端点） | `services/model_factory.rerank_documents` | 每次检索一次 HTTP；24 候选实测 **平均 278.5ms、约 3.9k token/次、0.00195 元/次**（单价 500 微元/千） |
| 候选深度 | **24**（`RERANK_CANDIDATES`，两路 prefetch 同步） | `services/kb_service.py` | 40 候选实测 precision +0.5pp（检不出），延迟 +36.5%、成本 +65.7%；保持 24 |
| 重排开关 | 默认**开**（`KB_RERANK_ENABLED`） | `services/kb_service.py` | 关掉省延迟，但 context_precision 会掉 |
| 截断 | **top-3**（`RERANK_TOP_K`） | 同上 | k 越大召回越宽、单条精度越低（见第二节四臂标定） |
| 工具默认条数 | `search_knowledge` **5**（可到 20，重排后仍截到 top-3）；`list_facts` 20（可到 50） | `services/kb_tools.py` | 模型要更多也只会拿到 3 条切片；要更大就调 `RERANK_TOP_K` |
| 摘录预算 | **30 段/轮**（`EXCERPT_SEGMENTS_PER_TURN`；单次上限 60） | `services/kb_tools.py` | 单次上限管不住多次调用（q90 两次 112 段）；预算按轮共享 |
| 跨录音预检索 | **0=关**（`CROSS_RECORDING_PREFETCH_K`） | `services/chat_service.py` | 入口每段 top-k 注入；k=1/2/3 把 cross8 precision 压到 51–60% |
| 跨录音条件补搜 | **1**（`CROSS_RECORDING_SUPPLEMENT_K`） | 同上 | 只在强标记 + 已做两次工具 + 转写覆盖 <2 段时补缺失段 top-1；独立 cross8 71.1/87.5，全 68 precision 擦线非劣 |

## 二、本语料实测（27 条人工标注题）

**判定只用一个族**：DeepSeek（`deepseek-flash`、thinking=off、label `f` 的标定家族）。
qwen 不再当裁判；旧读数只作历史对照，不与新读数相减。

标准口径（RAGAS：contexts = **检索到的全部切片**，不是"答案实际引用的那些"）：

| 配置 | context_precision | context_recall | faithfulness 内容级 | answer relevancy | recall@k / MRR / nDCG | 上下文数 |
|---|---|---|---|---|---|---|
| 500×8（历史） | 33.5% | 93.5% | 100% | 100% | 0.919 / 0.827 / 0.854 | — |
| 500×5（历史基线） | 53.0%（71/134） | 95.2% | 94.5% | 96.3% | 0.956 / 0.846 / 0.879 | 134 |
| 500×5（标定复跑） | 54.0%（74/137） | 95.2% | 96.4% | 100% | 0.956 / 0.821 / 0.867 | 137 |
| 500×3 | 65.1%（56/86） | 95.2% | 96.0% | 100% | 0.956 / 0.846 / 0.880 | 86 |
| 300×5 | 58.5%（83/142） | 95.2% | 96.9% | 100% | 0.926 / 0.815 / 0.835 | 142 |
| 300×3（纯参数标定） | 81.0%（68/84） | 95.2% | 94.3% | 96.3% | 0.944 / 0.870 / 0.886 | 84 |
| 300×3 + 资料覆盖 + 录音时间 + 工具卫生（A4；预检索关） | 78.9%（71/90） | 98.4% | 94.2% | 100% | 0.963 / 0.872 / 0.900 | 90 |
| **300×3 + 资料覆盖 + 录音时间 + 工具卫生 + 跨录音条件补搜 K=1（当前）** | **80.0%（72/90）** | **98.4%** | **96.4%** | **100%** | **0.981 / 0.890 / 0.907** | **90** |

**读法**：`context_precision` 的短板不是"检索不到"（recall 一直 95%），而是
"一次问一两个事实，却交回若干段同主题、答不了问题的窗口"。纯参数臂 300×3 的 84 条
上下文里 68 条有用；500×5 的 137 条里 74 条有用——**无用条数从 63 降到 16**，precision
的主要来源是分母变小，不是分子变大。两个因素是交互的：500 字下 k=5→3 是 +11.1pp，
300 字下 k=5→3 是 +22.5pp。**当前产品**在此基础上加了资料覆盖规则 + 录音墙钟时间
（修 q26）、工具输出卫生（get_minutes.fields / list_facts.keywords / 摘录每轮 30 段），
以及**跨录音条件补搜 K=1**（`CROSS_RECORDING_SUPPLEMENT_K=1`）：
只在强跨录音标记（两段/两场/各自/一致/上午对下午）、本轮已做两次工具结果、
转写覆盖仍 <2 段时，对缺失录音各补 top-1；裸“分别”不触发。27 条读数
precision **80.0%**、recall **98.4%**、内容级 **96.4%**、AR 100%、q26 3/3，
检索 **0.981/0.890/0.907**；27 条没有强标记，补搜零触发，因此这是干净回归。
**跨录音预检索仍默认关**：入口预检索 k=1/2/3 把 cross8 precision 压到 51–60%，
条件补搜只补缺失段，cross8 独立 8 题臂 **71.1/87.5**（32/45、14/16），q91
覆盖与 recall 都从 0/2 到 **2/2**；q94 覆盖 2/2、recall 0/2（裸“分别”不触发，
移动端事实仍是已知缺口）。全 68 的 cross8 子集是 **70.7/81.2**（29/41、13/16），
比 A4 的 68.3/75.0 高，但 q88/q95 有跨会话方差，未到独立臂的 14/16。

**代价必须一起报**：纯参数臂 300×3 的零调用 `recall@k` 是 94.4%、MRR/nDCG 0.870/0.886
（比 500×5 的 0.956/0.846/0.879：recall −1.2pp、排序两项更高）；判定式 recall 95.2%。
**A4（上一版，预检索关）** 是 0.963/0.872/0.900，三项都高于 500×5 基线；
当前条件补搜版是 **0.981/0.890/0.907**。
A5（预检索 k=3）的判定指标更高（81.6/100/96.5/100），但检索 recall 0.944
低于基线 1.2pp，且 cross8 precision 只有 60.0%——那是“覆盖优先”的版本，
不是当前标准。**当前选择“条件补搜”**：独立臂 recall 达 87.5%、precision 71.1%；
全 68 的 cross8 子集 13/16、整体 precision 64.3% 是擦线非劣（比 66.7% 低 2.4pp，
约 5–6 条上下文），不能声称 precision 提升。q94 的缺口保留，q95 的上午验收数据
是段内相关性问题（覆盖已是 2/2，补搜不会触发）。
历史 qwen 读数（51.5%）保留作对照，不与本表相减。

**Contextual Retrieval（已实现、默认关）**：索引时给每块加"规则头 + 一句 LLM 生成的主题"
再嵌入，引用正文不变（`kb_chunk.embed_text` 与 `text` 分开）。300×3 上实测
precision 77.3%（68/88）vs 关时的 81.0%（68/84）：有用条数一样，分母多了 4 条；
MRR 0.870→0.889、nDCG 0.886→0.893、answer relevancy 96.3%→100%，但主指标未过成功线。
因此 `KB_CONTEXTUAL_ENABLED=0`；要开就按 LEDGER 任务 3 的预注册重跑。

**候选深度 24 vs 40（任务 6，2026-10-17）**：同一批 27 题、同一窄规则，只改
`RERANK_CANDIDATES`。40 候选的 precision 75.8% vs 24 的 75.3%（+0.5pp，检不出），
但 rerank 平均延迟 380ms vs 278.5ms（+36.5%）、输入 token 193,855 vs 117,021
（+65.7%）、成本 0.0969 vs 0.0585 元（+65.7%）。**保持 24**。rerank 单价按
`RERANK_INPUT_PRICE_MICRO_PER_1K=500`（公开价 0.5 元/百万输入 token，未核对本账号账单）
计入 `ai_call_log.cost_micro`，不再显示"未定价"。

**扩展集 n=68 的读法（2026-10-17，代理起草、待人工确认）**：27 条人工集的 78.4% 不等于
产品普遍水平。**改动前** 68 条题整体 precision **39.0%**、recall 88.8%、内容级 90.3%；
按来源拆，搜索窗口 69.4%、结构化事实 18.3%、摘录片段 1.8%；跨录音 12.9%/56.2%。
**5 步改动后复测（三版）**：k=3 预检索版 precision **60.7%**、recall **95.2%**、
内容级 91.0%、AR 100%，cross8 60.0/93.8；无预检索（A4）precision **66.7%**、recall
**91.2%**、内容级 **92.4%**、AR **97.1%**，cross8 **68.3/75.0**；**条件补搜 K=1
（当前）** precision **64.3%（151/235）**、recall **93.6%（117/125）**、内容级
**90.5%**、AR **98.5%**，cross8 **70.7/81.2（29/41、13/16）**，recording coverage
67/76。补搜只实际触发 **q89（+1 条）与 q91（+2 条）**；q91 从 0/2 到 2/2，
q94 仍 1/2（裸“分别”不触发），q95 仍 1/2（覆盖 2/2，缺的是段内相关性）。
**precision 64.3% 只是擦线通过非劣门 64.0%（差 0.3pp，约 0.7 条上下文），
不能声称 precision 提升；recall +2.4pp、AR +1.4pp、内容级 −1.9pp。**
按意图：single_fact 60.9/89.7、aggregation 74.0/98.0、cross_meeting 70.7/81.2
（cross 的 precision/recall 为条件补搜臂；按意图的 single/aggregation 来自 A4 表，
本轮未逐意图重算，不混用）。**搜索路径没坏；工具卫生把 fact 18.3→51.6；
跨录音在“覆盖优先”时 recall 93.8/ precision 60，“精度优先”时 68.3/75，
“条件补搜”时 70.7/81.2。** 68 条仍是代理起草/单会议/单裁判，不能外推；
q88 在本轮 AR 0、金标 1/2（独立臂是 2/2）是跨会话方差，补搜未触发它。

**资料覆盖规则 + 录音墙钟时间（P1，2026-10-17）**：系统提示词里有一条**代码持有**的
规则（`chat_service.SOURCE_COVERAGE_PROTOCOL`）：`list_facts` 的 `source_coverage`
显示还有未确认纪要/转写录音时，"确认纪要里没有"不等于"没发生过"；只有明确问
"有哪些行动项/待办"且清单不完整时，才必须再检索转写；**先做一次不限来源检索**，
只有录音清单的 `recorded_at/period` 明确指向某段录音时才用 `source_ids` 收窄。
`recorded_at` 是 `transcription_task` 的**录音实际开始时间**（墙钟），不是上传时间；
种子两段录音回填 09:00/14:00，因此 q26 能直接定位下午场 task 7。实测 q26 从
**0/3 → 3/3**，precision 75.3%→**78.4%**，检索三项 0.944/0.830/0.855→
**0.981/0.883/0.905**（全部超过 500×5 基线）。**真实部署必须在上传时提供录音开始时间；
没有它，规则退回"两段都查、如实说明"。**

## 三、改参数的正确顺序

1. 改 `.env`（块大小/模型/k）→ 重启 backend（bootstrap 会把模型配置同步进库）；
2. 触发重建索引（三个来源各 POST 一次 `/kb/index`）——**内容指纹覆盖了正文、payload 结构、
   嵌入模型与 collection**，所以改这些都会自动重建；**稀疏 IDF 与 collection 名绑死**，
   换它要改 `QDRANT_COLLECTION`；
3. 重建后用 `make smoke` 看零调用检索指标（recall@k/MRR/nDCG），再决定要不要跑判定。

## 四、明确**没有**做的（避免被当成遗漏）

| 没做 | 为什么 |
|---|---|
| 语义切分 / 父子块 / Contextual Retrieval | 都要额外机制（父块表、索引时逐块 LLM 调用）；本语料 128 个片段、61 个切片，收益与成本不成比例。**本轮先做 Contextual Retrieval 的 LLM 版并量收益**（LEDGER 任务 3）；语义切分与父子块仍不做，除非 Contextual Retrieval 的收益证明值得再上一层 |
| 多向量 / ColBERT | 需要新索引与 GPU 侧能力；当前混合+重排已覆盖"精确串 + 语义"两类召回 |
| k 的自适应（按问题类型给不同 k） | 需要先有可靠的意图路由；该路由的逐类 F1 目前还有两类不可用（见 LEDGER） |
| 修改 BM25 的 k1/b | Qdrant 的稀疏 IDF 只暴露 modifier；完整 BM25 参数要自建检索服务，超出本项目范围 |
| 重叠窗口去重（**已实现、默认关**） | 300×3 的零调用反事实：删掉的 10 条全部被判有用，precision 81.0%→78.4%、recall 不变。相邻窗口不是重复噪声，而是各含答案的有用上下文。开关 `KB_DEDUPE_ENABLED=1` 可开，阈值见 `.env.example` |
| Contextual Retrieval（**已实现、默认关**） | 索引时逐块一次 LLM 调用（`KB_CONTEXTUALIZE`，61 次/0.023M token）；300×3 上 precision 77.3% vs 81.0%，主指标未过成功线。机制保留，`KB_CONTEXTUAL_ENABLED=1` 可开；语义切分与父子块仍不做 |
