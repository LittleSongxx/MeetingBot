# Agent 侧指标盘点（2026-10-17）

这份文档回答一个问题：**除了轴 5 的四个 RAG 指标，Agent 相关的指标现在到底测了什么、
没测什么。** 数字都连口径；n 小的一律标"方向信号"。

## 一、已经测的

### 1. 意图识别（逐类 F1，零调用评分）

- 样本：`gold/qa_seed.json` 的 **100 条**（q01–q100）；意图标签**全部由代理起草**
  （含 27 条人工题的意图字段），**待人工确认**。
- 分类法：四类，每类对应一个不同动作——`single_fact`（检索）、`aggregation`
  （先列清单）、`cross_meeting`（分别检索多来源）、`smalltalk`（不检索）。
- 当前读数（`make smoke` 的「意图识别」一节，零模型调用）：

| 意图 | 支持数 | precision | recall | F1 |
|---|---:|---:|---:|---:|
| single_fact | 55 | 93.9% | 83.6% | **88.5%** |
| aggregation | 32 | 70.7% | 90.6% | **79.5%** |
| cross_meeting | 8 | 100% | 62.5% | **76.9%** |
| smalltalk | 5 | 100% | 100% | **100%** |
| 宏平均（类等权） | 100 | — | — | **86.2%** |

- 混淆矩阵的主要形态：single_fact→aggregation 9 条；aggregation→single_fact 3 条；
  cross_meeting→aggregation 3 条（8 条支持，样本太小）。
- 置信度/弃权：100/100 有 `confidence`（均值 0.85），**弃权 7 条**；21 题被判为
  并列多问句（提示式分解）。
- **边界**：`cross_meeting` 的标签不能从问题本身判定（"答案落在哪段录音"是语料布局），
  已降级为诊断维度；四类 F1 只作方向信号，不能当强制路由的依据。

### 2. 查询规划的检索效果（两臂，100 题，零判定调用）

| 端点 | 规划关 | 规划开 |
|---|---:|---:|
| 多检索轮次（分解/改写起作用） | 8/100 | **22/100** |
| recall@k | 0.846 | **0.897** |
| MRR | 0.627 | **0.673** |
| nDCG@k | 0.668 | **0.709** |

**只测了检索侧**，没有测"规划对答案质量（faithfulness/relevancy）的影响"。
当前标准配置里规划**默认关**；这组数只说明"开着不比关着差、检索覆盖更高"。

### 3. Agent 行为端点（27 条人工题，P1 标准配置）

| 量 | 读数 | 口径 |
|---|---:|---|
| 轮级失败 / 空答案 | **0/27** | `stop_reason=stalled` 或空答案 |
| 首轮工具调用 | **27/27** | 首轮 `tool_choice=required` 生效 |
| 工具调用总数 | **32**（search 28 + list_facts 4） | 27 轮；4 轮多工具 |
| 引用可定位 / 未越权 | **100%（54/54）/ 100%（74/74）** | 零调用；编编号 0 |
| 每轮 CHAT token | 207,067 / 27 ≈ **7.7k** | 产品 `chat_message.token_count` |
| 每轮延迟（仅 CHAT 调用） | p50 **4.6s**、p90 **6.2s**、p95 **6.7s**、max **9.1s** | `ai_call_log` 按轮求和；不含 rerank/嵌入 |
| rerank | 28 次、平均 **295ms**、**0.0556 元** | 24 候选；单价 500 微元/千 |
| q26 三条金标 | **3/3** | 用 `recorded_at=14:00` 定位 task 7 |

**工具选择的分布（诊断，不是准确率）**：首轮 24 次 `search_knowledge`、3 次
`list_facts`；按意图分，single_fact 16 次 search / 1 次 list_facts，aggregation
8 次 search / 2 次 list_facts。**没有"哪个工具才是对的"的金标**，所以这只是行为分布，
不能算工具选择准确率。

### 4. 扩展集（68 条代理起草，2026-10-17）

这是比 27 条人工集更接近"普遍水平"的读数（仍未人工确认、单一会议）：

| 指标 | 扩展集 n=68 |
|---|---:|
| context_precision | **39.0%（144/369）** |
| context_recall | **88.8%（111/125）** |
| faithfulness 内容级 | **90.3%（308/341）** |
| answer relevancy | 98.5%（67/68） |

按来源类型拆 context_precision：**chunk（搜索窗口）69.4%（129/186）**、
fact（list_facts/get_minutes）**18.3%（13/71）**、segment（get_transcript_excerpt）
**1.8%（2/112）**。按意图：single_fact 51.5%/89.7%、aggregation 59.4%/98.0%、
cross_meeting **12.9%/56.2%**。检索侧：59 条带转写窗口的题 recall@k/MRR/nDCG
**0.943/0.962/0.958**；全 68 条 0.825/0.713/0.747（结构化路径拉低）。

**结论**：搜索路径本身没问题；精度塌在"工具返回的东西太多"（get_minutes 22 条、
list_facts 一批、get_transcript_excerpt 112 条）和跨录音题。27 题的 78.4% 不能
当普遍水平。扩展集 68/68 完成、0 失败；共 612,565 CHAT token（34+34 两批）。
引用：183 条被引、130 条可定位 100%、未越权 100%，但 **1/68 轮死链**
（q93 引用 [3][5]，该消息快照只有 [1]，属会话级编号复用；`chat_checks` 记为 missing_ref）。

### 5. 拒答与编造（12 条不可答题）

| 量 | 读数 | 口径 |
|---|---:|---|
| 拒答率 | **100%（12/12）** | 负样专用 `refused=true`（label g） |
| 编造率 | **0%（0/12）** | `fabricated=true` |
| 负样上下文 useful 率 | **22.2%（8/36）** | 检索仍带回同主题噪声 |

通用 `answered` 字段不是拒答检测器（实测把 12 条"资料不足"全判成 answered=true）；
负样必须用 `refused/fabricated`。

## 二、还没测 / 测不了的

| 维度 | 状态 | 为什么 |
|---|---|---|
| 工具选择准确率 | **没测** | 没有"每个问题该用哪个工具"的金标；现有只是首轮工具分布 |
| 规划对答案质量的影响 | **没测** | 两臂只跑了检索侧指标；判定调用成本高 |
| 实体核查护栏的误报/漏报 | **没测** | 只有 q14 等回归样例，没有标注集 |
| 多轮一致性 | **没测** | 27/68 题是顺序会话，但没有逐轮一致性/状态指标 |
| 记忆压缩质量 | **没测** | 只测了 token 节省（−8.9%），没测摘要是否丢结论 |
| 意图标签的人工确认 | **未完成** | 100 条全是代理起草；`annotation.py --export-intent-csv` 可导盲判包 |
| Agent 全成本 | **部分** | rerank 有单价；CHAT/嵌入的 `ai_model_config` 单价为 0（显示"未定价"） |
| 工具故障下的鲁棒性 | **没测** | 27 题 0 失败，但没有故障注入/超时压测 |
| 扩展集（68 条） | **已测** | 见上节；39.0% precision / 88.8% recall，结构化工具与跨录音是主要缺口 |
| 工具输出预算 | **未做** | get_minutes/list_facts/get_transcript_excerpt 的条目数不受每轮总量约束（q90 112 条） |
| 会话级引用编号复用 | **未修** | q93 复用了上一轮 [3][5]，消息快照只有 [1] → 死链；需要会话级登记或生成后校验 |

## 三、下一步（按 ROI）

1. **人工确认意图标签**：把 100 条导成盲判包（`gold/annotation.py --export-intent-csv`），
   人工确认后把 `intent_source` 改成 `human`，F1 才能从"方向信号"升格。
2. **工具选择金标（50 题）**：为每题的"第一步该用哪个工具"标一个期望值，算首轮
   工具准确率；这是比"意图 F1"更直接的 Agent 指标。
3. **规划 A/B 加答案质量**：如果要把规划开默认，必须补 faithfulness/relevancy，
   不能只看 recall/MRR。
4. **实体核查抽样**：从 27/68 轮答案里抽 30 条带人名/数字的断言，人工判"该拦没拦/
   不该拦却拦"，估误报/漏报。
5. **把延迟/成本进 smoke**：从 `ai_call_log` 零调用汇总 p50/p95 与每轮成本，
   让 Agent 的体验指标随每次改动复算。
