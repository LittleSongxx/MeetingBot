# MeetingBot 作品集一页纸（2026-10-23）

> 一个**会议智能 Agent**：MOSS 本地 ASR → LangGraph 审查/修订纪要 → 结构化行动项 →
> 跨会议 RAG 问答；用 5 轴评测 + 预注册 + 质量闸驱动优化，所有数字可回源。
> 入口：[质量仪表盘](quality_dashboard.html) · [主报告](质量指标全面分析与通用优化方案.md) · [路线](项目推进-深度分析与路线图.md) · [账本](../evaluation/LEDGER.md)

## 1. 架构（两张 LangGraph 图）

```
音频 ──(MOSS SA-ASR 侧车，8 场 cpCER 13.47%)──→ 转写 (product_db)
   │
   ├─ agent_graph: START → review(证据门控/契约前提校验) → refine(有界重写) → finalize
   │        └─ 支持复核(AGENT_JUDGE)、轮数由代码兜底
   │
   ├─ 确认纪要 → KB outbox → pgvector + BM25 索引
   │     ├─ action_validate(槽位校验) → action_item(闭环)
   │     └─ 系列/记忆状态 (query_meeting_state)
   │
   └─ chat_graph: START → agent(工具+预算/停滞硬闸) → tools → coverage(缺口提示)
                    → nudge(首轮未检索) → finalize(引用绑定/实体核查/质量留痕)
```

关键机制：单 Agent（串行查-读-答，5 工具，无并行/信任边界）；终止条件在代码里
（轮数/token/成本/工具数/停滞）；"无证据不判定"（首轮未检索→结构性提醒/标注）；
生成后**引用绑定**（零模型调用，cited-gap 18.31%→9.39% 回放，4 次 A/B −8.35pp）。

## 3. 三个"案例—机制—数字"卡片

1. **引用归属错**：cross30 数字 cited-gap 18.31%，其中 19/39 其实在别的检索上下文里。
   机制：`citation_bind` 生成后重绑（纯规则）。结果：离线 9.39%、配对 faith +1.06pp、
   4 次 A/B cited-gap −8.35pp（precision −0.75、faith −1.33 均过线）。**默认开**。
2. **轨迹可靠性不可评**：单 trial 只有 F1/strict。机制：27 题 ×3 trial。结果：
   **pass^3=85.19%**、F1 macro 0.706、must_cite 25/25、forbidden 0/81。
3. **行动项槽位无守卫**：owner/deadline 可能不在转写里。机制：`action_validate` 槽位校验
   （owner 拆分后须全部出现、deadline 须时间表达、evidence LCS≥10），确认后写待办前降级。
   结果：VCSum 26 场/50 条审计 owner fabricated 0/6、deadline 降级 2 条；产品 666 项测试通过。

## 4. 诚实的负结果 / 边界

- **S2 系列/状态覆盖**：**提示模型多查状态**是负结果（调用 +9.5，但 recall −5.17pp、faith −4.08pp，
  默认关）→ 改为**工具契约扩展**（系列/状态元数据进工具返回与引用快照，不改提示词）：
  cross30 4 次/臂 recall-v2 **+5.60pp**、precision −1.63pp、faith +0.97pp；
  new_meeting 中性、mixed100 子集 +10pp → **非单集过拟合，默认开**。
- **S3 item F1：仪器不可靠，未硬凑**：宽松 AI gold 下产品 F1 0.174、qwen 抽取 0.279；严格定义后 10 场里 8 场 gold 0 条、两族共识 gold 仅 2 条 → F1 无定义。VCSum 是论坛型语料、多数无真正行动项；**需要行动项密集语料 + 人工金标**才能可靠量，本轮不据此改产品（避免对噪声 gold 过拟合）。槽位守卫仍有效。
- 单裁判/单数据集/单次波动：faithfulness 单次波动约 5pp；claim 级裁判 α=0.426 校准失败 →
  绝对数只作方向信号。
- MOSS 产品化到此为止：45min 守卫/2400s 超时是容量测试后的保守值；不做生产级运维。
- **历史成本不可回溯**：单价是后填的估算值（官方 USD × 7.1），历史调用仍 unpriced；OTLP/Jaeger 已配置但本机镜像拉取失败，trace 后端未激活。
- **泛化纪律**：机制只依赖通用输入（问题/工具 schema/转写/上下文）；产品运行时字符串
  禁止出现评测集标识（`tests/test_no_eval_leakage.py` 静态守卫）；S2 线索词提示因过拟合风险
  与负结果被否决；详见 [泛化与过拟合审计](泛化与过拟合审计.md)。

## 5. 三分钟 demo 脚本

1. `docker compose up` 后打开 `http://localhost:8080`（admin 登录）；
2. 上传一段会议音频 → 产品走 MOSS 本地侧车转写（显示 `moss-transcribe-diarize-0.9b(local)`）；
3. 生成纪要 → 审查/修订（展示 review issues/refine 轮次）→ 确认；
4. 确认后行动项出现（展示槽位校验后的 owner/deadline）；打开系列待办视图；
5. 知识问答："发布公告与对外通稿分别由谁负责、什么时候完成？" → 展示工具调用、
   引用卡片、引用绑定留痕；
6. 打开 `docs/quality_dashboard.html` 讲指标与 A/B。

## 6. 面试问答（高频）

| 问题 | 答法 |
|---|---|
| 为什么单 Agent？ | 串行查-读-答、5 工具、无并行/信任边界；多 Agent 只增信息丢失与调试成本 |
| 为什么工具 F1 不高不硬压？ | 18 次 extra 中 11 次有引用贡献；硬压 faith 88.63→73.53–83.69（有实验） |
| 评测怎么防自欺？ | 预注册、holdout、单次波动 5pp、CP CI、冻结基线 sha、judge α 校准失败就降级 |
| 引用绑定为什么是零调用？ | 数字/日期在检索上下文里可确定性定位；只加引用不改内容，配对回放无回归 |
| 最大负结果？ | S2 状态提示伤 recall/faith；claim 修复 +1.7pp 未过 +5pp；如实登记不产品化 |
| MOSS 取舍？ | 8 场 cpCER 13.47%（云端基线 30.09 背景）；本地 GPU/延迟换质量；45min 守卫 |
