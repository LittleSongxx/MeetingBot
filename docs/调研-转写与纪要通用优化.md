## 0. 结论先行

### 0.1 三句话结论

1. **轴1 是唯一「外部有成熟解法、且当前差距可量化」的轴**：本地端到端说话人归属性 ASR（MOSS-Transcribe-Diarize 0.9B，Apache-2.0）是应当压注的转写机制；它同时改善 CER 与说话人归属（公开 AliMeeting cpCER 22.17 vs 本项目云端单块 **30.1%**，差约 8pp）。但历史 8 场只成功 3 次（2 场有效 + 1 场**静默截断**），**复测的第一前置条件不是选型，而是工程加固与可观测性**（覆盖守卫、token 预算、超时/显存/失败日志、模型修订钉死）。
2. **轴2/轴3 的主要矛盾不是「缺机制」，而是「测量效度 + 修复依赖」**：审查意见与词法代理的一致性只有 **4.1%–7.8%**（dev22 为 0%），整篇 HHEM 口径会被「写短/写泛」刷低（passthrough 0% vs reflected 7.7%）；完整性的损失已定位在**分段抽取步 0.242**，而合并步 ≈0（−0.003）。因此预算应从「整篇反思重写」转向**抽取步关键点清单 + 断言级证据契约 + 独立评测端点**；plan+gap-fill 之所以只 +1.92pp，是因为它作用在已接近无损的合并步、且在强场引入清单噪声。
3. **轴4/轴5 存在已证实的低成本确定性缺陷**：`MISSING_DEADLINE` 无条件规则误报 **77.8%/85.7%**、期限 `field_misuse` **14/143**、owner `fabricated` **9/143（6.3%）**、审查 issue 大量不可定位——这些修复**零模型调用或一次规则改造**即可完成，优先级高于任何新模型/新 prompt。

### 0.3 三个「不做则白做」的前置条件

1. **测量先行（全轴 P0-0）**：现有轴2/文字轴的关键读数建立在 LLM 裁判与词法代理上，而本项目已实测跨族标签翻转 **26%–34%**、双族只一致 65.9%–73.9%；所有「±2–3pp 级」的机制效应都在裁判噪声内。任何 P0 上线前，先冻结一份**人工金标锚点包**（建议 100 条 claim × 2 名标注者 + 20 条会议级 minutes 判定），报告 κ/一致率，再谈机制收益。
2. **产物 provenance（轴1 硬前置）**：现有 MOSS 快照的 `model_name` 字段写的是云端模型名（`qwen-audio-3.1-asr-flash-filetrans`），且 task JSON 不含引擎版本/模型修订/解码参数/GPU/覆盖率/失败堆栈——**没有 provenance 的复测数字不能进 LEDGER**（详见 §4.1）。
3. **口径不重述**：cpCER 是「说话人归属性」指标，其改善可能来自「把话归对人」而非「听对字」；必须同时报 CER 与 Δcp。本项目 c3600 条件下 Δcp 只剩 **+5.1pp**，已证明剩余损失是**端到端分离固有归属误差**（LEDGER R5），不是切块问题——这决定了轴1 的机制选择只能走 SA-ASR 路线，不能靠切块/重聚类继续挤。

### 0.4 不建议 / 收益不明确（摘要，详见 §5）

- 不建议把 **DiariZen / Sortformer** 权重纳入产品：CC BY-NC 4.0 非商用（§6 R9/R11），且 AliMeeting DER 12.5 是**纯 diarization 指标**，不能换算成 cpCER。
- 不建议在本项目上继续做 **map-reduce 合并步优化**：本项目合并损失 −0.003，已经接近无损；问题在抽取步。
- 不建议用 **整篇 HHEM 分数**作为优化目标：HHEM-2.1 在 RAGTruth-Summ 上 recall 仅 **31.86%**（§6 R17），且「写短」即可降低整篇问题率（本项目 passthrough 0% 是更短/更泛的改写，不是更忠实）。
- 不建议做 **Reflexion 式跨会议长期记忆/自评分**（§6 R40）：本任务是离线一次性生成+人工确认，没有多轮环境反馈闭环；已有证据显示 prompt 自评自纠在无外部可核验反馈时收益不稳（§6 R33/R34）。
- 不建议为追逐「审查无增益」的既有结论而**反复调审查 prompt**：应先修 issue 契约与测量（A2-2/A5-1），否则每次读数都落在裁判噪声里。

### 1.3 外部数字的「不可外推」注记

- **MOSS 卡 22.17**：公开表是 AliMeeting 官方口径，具体切分/音频前处理/推理栈（模型卡推荐 SGLang Omni 或 vLLM）未在本项目链路复现；本项目输入是**8 通道平均下混后的单声道 16k MP3**，与官方评测输入不完全一致。**只可作方向锚，不可当成本项目预期值**。
- **DiariZen AliMeeting DER 12.5**：这是说话人日志（DER，collar=0）指标，不是 cpCER；级联到 ASR 后 cpCER 还叠加识别错误（仓库 DESIGN 记录的级联最好 cpCER≈23.2，但该数字本轮未在公开 URL 复核，仅作项目内参照）。
- **Sortformer**：模型卡明确「最多 4 说话人；RTX A6000 48GB 上最长约 12 分钟；非流式；英文为主」——与 26–37 分钟中文会议不匹配，且权重 CC BY-NC 4.0。
- **HHEM-2.1**：在 RAGTruth-Summ 上 balanced acc 64.42%、F1 44.83%、**recall 31.86%**；它擅长「精确率侧」，不是高召回检测器。用它当唯一裁判会系统性漏报。
- **Self-Refine 的「+20% 平均」**：7 个任务、GPT-3.5/4 时代、含对话/数学等；本任务是「有原文可核验的会议纪要」，属于「有可靠外部反馈才可能有效」的那一类（§6 R33/R34），不能直接套用。
- **MT-Bench 的「>80% 与人类一致」**：是 chat 偏好任务、强模型裁判；本项目实测跨族翻转 26%–34%，说明本任务上裁判一致性**低于**该公开结论的适用域。

## 3. P0/P1 机制详述

> 每个机制固定五段：**原理 → 外部证据与差异注记 → 最小实现路径 → 验证设计（样本量/配对/判定/回滚）→ 代价与风险**。
> 判定阈值优先沿用项目已预注册的口径；新机制若改变口径，必须写成新预注册并注明「与旧读数不可比」。

### 3.1 轴1：说话人归属性转写

#### A1-1（P0）MOSS 本地端到端 SA-ASR 8 场复测与引擎决策

**原理**：端到端 Speaker-Attributed, Time-Stamped Transcription（SATS）在**单次前向**里同时产出「谁—何时—说了什么」，绕开「ASR→diarization→对齐」级联中三段误差的相乘。cpCER 用说话人最优置换后的字错误率衡量 SA-ASR；Δcp=cpCER−CER 单独度量「归属损失」。本项目旧默认 c1200 的 Δcp 曾是 **+58.3pp**（跨块编号重置/碎片），c3600 单请求后降到 **+5.1pp**（已证为端到端分离固有归属误差，见 LEDGER R5）——继续压低 Δcp 只能换更强的 SA-ASR，而不是继续调切块。

**外部证据与差异注记**：
- MOSS-Transcribe-Diarize 0.9B：128k 上下文、单次推理最长 90 分钟、50+ 语言，Apache-2.0；模型卡 AliMeeting 公开值 CER 24.86 / cpCER **22.17** / Δcp **−2.69**（R1、R2）。同表商用 API：Doubao 37.57、Gemini 2.5 Pro 41.64、Gemini 3 Pro 32.84（cpCER）——本项目 c3600 云端 **30.1%** 已优于该表内 Gemini 3 Pro，与「距公開 MOSS 22.17 差约 8pp」的方向一致。
- 差异：公开值用官方评测切分/输入与**官方推荐推理栈**（模型卡 Quickstart 用 HF remote code，部署推荐 SGLang Omni 或 vLLM；长音频建议显式调大 `max_new_tokens`，示例 65536）。本项目是 8 通道平均下混单声道 16k MP3、FunASR 适配器、`max_new_tokens=32768`——**公开数字不可直接当成本项目目标**，只能作方向锚。
- cpCER 术语来源：M2MeT 2.0（ASRU 2023）明确引入并定义了 cpCER（SA-ASR 评测口径，R5）；第一代 M2MeT（ICASSP 2022）Track 2 用的是 FIFO/按说话人置换的 CER（R4），二者不能混引。MeetEval 提供 cpWER/cpCER/tcpWER 的统一实现（R6），tcpWER 额外要求时间对齐合理——对首测「无时间戳的假时间占位」要说明用的是 cpwer 而非 tcpwer。

**最小实现路径**（执行归 task-4，本节只定义验收）：
1. 输入锁定：复用 `evaluation/asr/first_test/hyp_*_avg.mp3`（与云端 c3600 完全同一份 16k 单声道输入），禁止重新用不同混音口径生成。
2. 侧车加固：模型 revision 固定、`max_new_tokens ≥ 15×audio_seconds + 4096`、超时 ≥ 3600s、串行、异常打印 traceback、返回 `audio_seconds/duration/truncated/elapsed/model`。
3. 评测链路二选一并声明：**直连侧车**（不依赖产品容器/凭据，快）或**产品真实链路**（可信但需重启后端，必须先向 lead 申请窗口）。两者都必须落 task-JSON 形态（含 `meeting_title`、`speaker_label`、`segments`），用 `evaluation/asr/cpcor.py::compute()` 与 c3600 同工具同参数计算。
4. 运行清单：每场记录音频秒数、tokens、墙钟、GPU、峰值显存、是否截断、侧车版本、模型 revision；失败场记录完整 traceback。
5. 汇总：逐场表 + 宏平均 + 配对差 + 95% bootstrap CI + 精确符号检验（n=8）；产物 `cpcor_report_moss_8m.json`，并在 `evaluation/reports/2026-10-23_moss_asr_comparison.md` 给出「可入账」判定。

**验证设计**：
- 样本：AliMeeting **Eval 全 8 场**（26.2–37.3min，总 252.1min），与云端 c3600 逐场配对；唯一主指标＝宏平均 cpCER 的配对差（MOSS−cloud）。
- 判定（预注册，见 §4.3）：主门槛 (a) 8/8 有效转写；(b) 宏平均 ΔcpCER ≤ −5pp；(c) ≥7/8 场方向一致；(d) 配对差 95% CI 下界 >0；(e) CER 不劣化 >+1pp（防「换归属刷 cpCER」）；(f) 单场墙钟 ≤ 2×音频时长、零人工重启。
- 功效：n=8 配对连续量、双侧 α=0.05、power 0.8 时 MDE≈1.0×sd_pair（DESIGN 已登记 MDE≈6–7pp）；因此 **+5pp 门槛本身处于功效边缘**，结论表述必须是「方向一致 + 效应大」或「检不出」，不得把「未过 5pp」写成「无效」。两场历史差 −16.12/−15.20pp 远大于 MDE，但样本被「成功性」筛选，乐观偏差必须写明。
- 回滚：产品默认引擎不动；实验只动 `TRANSCRIPTION_ENGINE/ASR_HTTP_URL` 环境变量；失败一键切回 dashscope 并停侧车（不改代码，回滚测试单列）。

**代价与风险**：
- 成本/延迟：历史 frozen 快照墙钟 R8001 **575s**/R8003 **777s**（RTF≈**0.37**），云端 c3600 为 **54s/62s**（RTF≈**0.03**）——本地 MOSS 约 **12×** 慢；8 场满跑预计 ≈93min GPU 推理 + 失败重试预算 ≤2×。侧车串行（信号量 1），产品并发任务会排队并可能触发 600s 默认超时。
- 风险：① 5/8 历史失败与 1/8 静默截断（§4.2）；② token 预算/长音频上限（>90min 模型不支持，而产品 `MAX_DURATION_SECONDS=7200`）；③ 许可虽 Apache-2.0，但 **FunASR 适配器/推理栈**版本漂移风险；④ 若只跑通 2–3 场就下结论，等于重复 2026-09-27 的暂停点，**不产生可入账证据**。

#### A1-2（P0）转写完整性守卫（silent truncation / 覆盖 / 超时 / 引擎上限）

**原理**：对下游（纪要、完整性、行动项、知识库）而言，**「静默截断的成功转写」比「明确失败」更有害**——它把缺失内容当成事实基线。R8007_M8010 快照：音频 1854.03s，输出仅 142 段、last_end=229.31s（覆盖 **12.4%**）、假设 1832 字 vs 参考 17028 字（**10.8%**），而产品状态是 `SUCCEEDED`；若直接进 cpCER 会得到 90.86% 的假读数，若进纪要学会静默丢 88% 内容。

**外部证据与差异注记**：长音频 ASR 的截断/漂移是已知失效模式——Whisper 的滑窗/缓冲长音频解码会出现 drifting、hallucination、repetition（R14 摘要），其解决方案之一是用 VAD cut&merge 预分段（R14）；MeetEval 的 tcpWER 也说明「时间戳不可信时匹配会失真」（R6）。MOSS 模型卡要求长音频显式增大 `max_new_tokens` 并建议官方 serving（R2）；其论文声明单次支持 ≤90min（R1）。这些是**工程约束**而不是模型能力结论，需按本项目链路实测。

**最小实现路径**（全部确定性、零 LLM 调用）：
1. 侧车返回 `audio_seconds`、`duration`、`truncated = duration < audio_seconds − 5`、`model`、`model_revision`、`elapsed_seconds`；异常返回结构化 `error_code`（OOM/timeout/parse），并打印 traceback。
2. 产品 http 分支（`transcription_service.py` L334–355）增加守卫后再落库：
   - **覆盖率**：`max(seg.end)/audio_duration ≥ 0.95`，否则按失败处理并写 `error_message`（含覆盖率）；
   - **字符密度下限**：`len(full_text)/audio_seconds ≥ 0.8`（中文会议远场正常约 3–6 字/秒；R8007 截断样本为 **0.99 字/秒**，R8001 正常为 **6.9 字/秒**、R8003 **5.5 字/秒**，阈值空间很大）；
   - **结构**：段 start 单调不减、speaker 数 ∈ [1, 10]、`full_text` 非空；
   - **引擎差异化上限**：`TRANSCRIPTION_ENGINE=http` 时上限取 **5400s**（90min，MOSS 能力上限），dashscope 维持 7200s；
   - **超时**：本地引擎用独立配置（建议 ≥3600s），不能沿用默认 `ASR_TIMEOUT_SECONDS=600`；
   - **失败语义**：5xx/超时是否重试由引擎配置决定；本地 GPU 失败默认**不自动重试**（避免重复烧 GPU），由任务显式重试。
3. 守卫上线前，用现有 8 场快照做离线回归：R8007 必须被拒、R8001/R8003 必须通过；产品 `tests/test_transcription.py` 增加截断/短文本用例。

**验证设计**：
- 离线：8 场历史快照 + 人工构造 3 种截断（50%/10%/空段）→ 期望 4/4 拦截、正常样本 0 误拒；`pytest` 单测。
- 在线：MOSS 复测 8 场里若发生截断，必须体现为 `FAILED`（或显式 `truncated` 标记，人工窗口外不落库）；统计拦截率与误拒率。
- 判定：拦截率 100%（已知截断样本）；误拒率 0（8 场正常样本）——这是结构性不变量，发现一条即失败。
- 回滚：守卫以 env 开关（`TRANSCRIPTION_COVERAGE_GUARD`，默认开）+ 独立函数实现，可一行关闭；关闭后行为等价旧版（用 8 场重放验证）。

**代价与风险**：产品约 30–50 行 + 侧车返回字段；0 LLM 调用。风险：① 阈值过严误拒（如会议开头长静音、纯音乐段）；② 时长口径差异（容器时长 vs 解码时长）；③ 掩蔽真实模型退化（截断被当失败后，失败率上升需要与模型质量区分）——因此必须同时报「失败率」与「截断率」。

#### A1-3（P1）引擎元数据 / 运行清单 / 失败可观测性

**原理**：评测数字的可入账性取决于「同一输入 + 同一模型 + 同一解码参数 + 同一工具」四要素可复现。当前 MOSS 快照的 task JSON `model_name` 仍是云端模型名（`qwen-audio-3.1-asr-flash-filetrans`），不记录 MOSS revision/`max_new_tokens`/GPU/耗时；失败场只留一句「本地ASR服务请求失败：Internal Server Error」——**无法区分 OOM、token 截断、模型加载失败、路径错误**。

**外部证据与差异注记**：这是工程可复现性要求，非论文结论；MOSS 模型卡明确给出官方 serving 方式与长音频 `max_new_tokens` 建议（R2），本身就在强调参数/栈的可控性。

**最小实现路径**：
1. 侧车 `/health` 返回 `{model, model_revision, backend, dtype, max_new_tokens_default, device}`；`/transcribe` 返回覆盖率与耗时。
2. 产品 task 产物增加 `engine`、`engine_model`、`engine_revision`、`decode_params`、`audio_seconds`、`coverage`、`elapsed_ms`、`gpu_name`（侧车回传）；`ai_call_log` 已记录 `LOCAL_ASR_MODEL_NAME`，需要与 task 产物对齐。
3. 评测脚本落 `run_manifest.json`：git HEAD、侧车文件 sha256、requirements 锁文件、模型 revision、GPU/驱动、每场输入文件 sha256、开始/结束时间、失败 traceback 路径。

**验证设计**：一次 8 场复测的 manifest 必须能回答「换一台机器能否重放」；抽查 2 场用 manifest 重建环境复跑，cpCER 差异 ≤0.5pp 视为可复现（温度/greedy 同参数下允许微小的非确定性，需在 manifest 说明）。回滚：仅新增字段，不影响旧消费者。

**代价与风险**：小（脚本+字段）。风险：产物 schema 变更需兼容旧快照（缺字段按 null 计，不得阻断）。

#### A1-4（P1）推理栈对齐官方（vLLM/SGLang 或 HF transformers + revision pin）

**原理**：MOSS 模型卡的官方用法是 HF remote code / SGLang Omni / vLLM；当前侧车走 FunASR `AutoModel` 适配器，属于**非官方推荐路径**，长音频生成参数（`max_new_tokens`、`max_length`、batch/VAD 行为）与官方文档不一致，导致「公开 22.17 与本项目复测不可比」。在证据链上，应当优先使用官方路径；若 FunASR 路径保留，必须作为「不同推理栈」单独登记。

**外部证据与差异注记**：模型卡 Quickstart/部署段（R2）明确 SGLang Omni `/v1/audio/transcriptions` 与 vLLM serve，并提示长音频调大 `max_new_tokens`（示例 65536）；论文声明 128k/90min（R1）。差异：vLLM/SGLang 需要额外依赖与显存配置，CPU-only 环境不适用。

**最小实现路径**：先在 1–2 场上做**推理栈 A/B**（同一输入、同一 `max_new_tokens`），比较 cpCER/覆盖率/墙钟；若官方栈显著更好，则复测主臂改用官方栈；否则保留 FunASR 路径但记录 stack 标识，并在结论里注明「非官方栈」。**不要求为了栈而暂停复测**——但任何入账数字必须标注栈。

**验证设计**：A/B 配对 2 场 × 2 栈；判定：若 cpCER 差异 >3pp 或覆盖率差异 >2pp，才值得切换栈并重跑 8 场；否则保持现栈、只补 provenance。回滚：两套脚本并存，env 切换。

**代价与风险**：中（新依赖/服务）；风险：vLLM nightly 版本漂移、CUDA 12/13 差异（模型卡已注明），以及额外服务运维成本。

### 3.2 轴2：忠实度与幻觉

#### A2-1（P0）断言级证据契约 + 生成后校验修复

**原理**：把「纪要是否忠实」从**整篇打分**降维成**逐断言可核验**：每个条目/断言必须携带 quote（转写连续子串）或显式 `declared_unknown`；生成后由独立校验器判定 `supported_by_quote / supported_elsewhere / citation_missing / unsupported / derived / meta`；对 `unsupported` 只做**有界机械修复**（补引用或删除），不做整段重写。这与「先写、再自评、再重写」的反思环不同：校验信号来自**外部原文**，不是模型自评。

**外部证据与差异注记**：
- MiniCheck：770M 的 FT5 在 LLM-AggreFact 上达到 GPT-4 级判定、成本约 1/400（R18）；SummaC 用 NLI 分段聚合，在 SummaC 基准 balanced acc 74.4%（R19）；RAGTruth 提供 18k 人工词级幻觉标注，说明「无支撑断言」是可标注、可训练的（R20）；HHEM-2.1 在 RAGTruth-Summ 上 recall 仅 31.86%（R17），证明整篇分类器单独用不够。
- 差异：上述基准是英文/摘要/QA 场景；本项目是中文会议纪要 + 六字段结构，需要自建判定提示词与 schema；「转写本身有错」会造成「原文不可信但断言有依据」的伪 unsupported，判定时必须以**转写文本**（而非世界知识）为唯一依据。

**最小实现路径**：
1. 契约升级：条目/断言级 `evidence.quote`（原文连续子串 ≥2 字）+ `basis`（stated/inferred/not_mentioned/open_ended）；保留字段级 `declared_unknown`。
2. 生成后校验（与产品解耦的评测/产品共用机制）：校验器只拿到「转写切片 + 断言」，输出四类标签；产品侧对 `unsupported` 执行「删除或降格为待确认」，对 `citation_missing` 补引用（不改文字）。
3. 守卫：删除句比例 >30%、答案长度 <60%、引用清空 → 回退原稿（防止 v2 时代 `−0.67/−0.50` 灾难性删除重演）。
4. 与已有工作对齐：另一任务（LEDGER §40）已在 RAG 答案侧预注册「答案级证据校验与有界修复」，本机制在纪要侧复用同一契约与指标定义，**不重复造第二套口径**。

**验证设计**：
- 主指标：条目级无依据原子率（词法代理，与历史可比）＋人工判定的「真 unsupported 率」（100 条断言金标）。
- 样本/配对：vcsum-test26 配对（初稿 vs 校验后），零模型重跑可用现有产物做**离线重放**（把校验器应用于已落库的 26 场条目，不需要重生成）；另跑 6–8 场端到端确认调用预算。
- 判定阈值（预注册）：(a) unsupported 原子率相对下降 ≥1.5pp，或人工真 unsupported 下降 ≥5pp；(b) completeness core 下降 ≤2pp；(c) 单场删除句 >30% 的场次 ≤2；(d) 双族裁判方向一致。四项全过才算可平衡；任一项失败 → 只保留「无依据标注」不自动删除。
- 回滚：校验修复以独立开关控制（默认关→灰度开），回退等价旧行为；回滚需用 26 场重放确认。

**代价与风险**：每场多 1 次校验调用（若用 770M 本地模型则成本≈0，但中文会议域需验证）；风险：校验器误杀正确推断（`derived` 判定边界）、删除导致覆盖下降（已有历史前科）、以及「转写错→断言被误判」的二阶误差。

#### A2-2（P0）审查 issue 证据门控

**原理**：当前审查输出 145–179 条 issue，但与词法代理一致者只有 6/145（test26）或 14/179（dev22）；issue 中大量是**无定位、可套用于任何文本的模板化意见**（每轮 issue 数与代理标记数 Spearman 仅 0.416/0.249）。门控规则：每条 issue 必须携带**可定位的 source_span/quote**，且 quote 必须是转写的连续子串；不能定位的 issue 降级为「建议」或不输出。

**外部证据与差异注记**：ALCE 的自动引用评测把「引用是否支撑断言」作为一等指标（R38），说明「带证据的生成」可被机器校验；CoVe 的验证问题是「先独立回答再核对草稿」，其有效前提仍是外部可核验性（R39）。差异：本机制是**输出契约**而非新模型，收益主要在 precision 而非召回。

**最小实现路径**：
1. 修改 `MINUTES_REVIEW` 输出 schema：issue 必填 `source_span`（原文连续子串）+ `target_index`；`UNSUPPORTED` 允许 `whole_block` 但必须附 quote。
2. 服务端门控：`source_span` 归一化后不是转写子串 → 丢弃并计数（`issue_gate_dropped`），保留 `review_pass_rate`/issue 分布等行为指标。
3. 用现有冻结产物离线重放：统计「被门控后剩余的 issue 里，有多少能触发实质修改」，先回答「审查到底还有多少可用信号」。

**验证设计**：人工金标 100 条 issue（从现有 51/44/43 轮审查里分层抽），双人判定「是否真问题」；判定：门控后 precision ≥50%（相对现状 4.1–7.8%）且 recall ≥30%（对真问题）；若 precision 上不去，说明问题在审查能力而非契约，进入 A5-2。回滚：schema 向后兼容（旧 issue 缺 span 视为 suggestion）。

**代价与风险**：提示词/schema 改造 + 1 次离线重放；0 额外调用。风险：门控过严导致 review 通过率虚高（issue 被丢光），需同时报「被丢弃率」。

#### A2-3（P1）裁判校准卡 + 双族 + 人工锚点（HHEM 只作对照尺）

**原理**：本项目所有「23.1%」「7.7%」「4.1%–7.8%」都依赖 LLM 裁判；实测跨族标签翻转 26%–34%，单裁判读数只作方向信号。校准卡要求：每个裁判记录模型/版本/温度/完整 prompt/样本/一致性/κ；主结论必须双族一致或人工锚点；HHEM 保留为「与业界同单位」的对照尺，不单独作为验收标准。

**外部证据与差异注记**：MT-Bench 显示强裁判可与人类 >80% 一致，但存在位置/冗长/自我增强偏差（R36）；G-Eval 在摘要任务上 Spearman 0.514、并提示 LLM 评委偏袒 LLM 生成文本（R37）；self-preference 实验显示同一模型既生成又评判会系统性偏高（R35）；HHEM 模型卡给出 AggreFact/RAGTruth 的精确率/召回权衡（R17）。差异：这些一致性是英文/通用任务，本项目已有更保守的本土实测（26–34% 翻转），应以项目内实测为准。

**最小实现路径**：冻结 JUDGE_CARD（已有 `gold/JUDGE_CARD.md` 机制，R3）；每次裁判更换即更新并重述历史绝对数；判定包双族（deepseek+qwen）抽 30% 复判；报告里同时给点估计+精确区间+双族一致率，不合成总分。

**验证设计**：人工锚点 100 条（claim 级）双人标注 κ≥0.6 才可用于校准；裁判与人工一致率 ≥80% 才可用于主结论；否则只作方向信号。回滚：不涉及产品。

**代价与风险**：判定预算 + 标注成本；风险：锚点本身有偏（需盲标、仲裁）。

#### A2-4（P1）引用级评测与引用约束生成

**原理**：纪要/答案的可核验性最终落在「引用是否支撑该断言」。ALCE 定义 fluency/correctness/citation quality 三维，且说明即使是最好模型在 ELI5 上仍有 50% 情况缺少完整引用支撑（R38）。本项目已有 citation precision 65.4%、ALCE 严格版 43.1%，处于公开长文强模型带内；下一步不是盲目要求「都加引用」，而是**先建立引用级端点**，再决定 quote-first/引句上限是否值得开默认。

**最小实现路径**：复用 `judges` 里已有的 citation 判定，按 ALCE 三指标出报告；生成侧试点「先选 quote 再写条目」的 quote-first（默认关），并记录引用剪枝/引句上限的副作用。**验证设计**：26 场配对 + 人工抽检 50 条引用；判定：citation precision 提升 ≥5pp 且 coverage 不降 >2pp 才考虑开默认。回滚：机制开关默认关。

**代价与风险**：判定成本；风险：过度引用（shotgun citation，本项目多余引用率已达 ~33–42%）会让引用 precision 虚降，需先定义「必要引用」口径。

### 3.3 轴3：完整性

#### A3-1（P0）抽取步 keypoint checklist + 分段证据

**原理**：本项目已把覆盖损失定位到**分段抽取步（0.242）**，合并步 ≈0；v2 时代的「重写补回漏记」是仪器截断伪影（LEDGER 已撤回）。因此正确机制是「**每段抽取时先把该段的可核验要点抽全并带证据**，再合并成六字段」，而不是在最终稿上做 gap-fill。外部对应：FineSurE 用 LLM 做 completeness/faithfulness/conciseness 细粒度评估，并显示 LLM 评估在 completeness 维度优于 NLI/QA 方法（R21）；KPA 把摘要质量量化为「关键点及其匹配论据的覆盖率」（R23）；QMSum 的 locate-then-summarize 说明长会议须先定位再总结（R22）；FRAME 用「事实抽取+评分+主题化」的模块化管线，在 QMSum/FAME 上把幻觉与遗漏各降 2/5 分（R24）。

**外部证据与差异注记**：FineSurE/KPA 是英文/通用摘要，FRAME 是 2025 年会议摘要工作（QMSum/FAME），本项目是中文六字段结构化纪要；指标不能直接换算，但「先抽事实再组织」的方向与「损失在抽取步」的本项目诊断一致。

**最小实现路径**：
1. 评测侧：v3 清单（已原子化+core 分层）保持为**独立端点**，产品 plan 清单绝不作端点（LEDGER 纪律）。
2. 产品侧：分段抽取调用改为「输入转写分段 + 上下文（详见 A3-3）→ 输出 `keypoints[{text, quote, kind, importance}]`」；六字段生成只从 keypoints 里取材，不允许新增事实（与 A2-1 契约一致）。
3. 合并步：按 kind/importance 去重、按字段路由；合并步的 lost-in-middle 风险用「分段摘要 + 逐段要点」控制（§6 R25）。

**验证设计**：vcsum-test26 配对（baseline 臂 vs keypoints 臂）；主指标 v3 core 覆盖（deepseek 主口径，qwen 方向对照）；判定阈值沿用预注册 +3pp（宏平均差），且 (a) 双族方向一致；(b) 无场次覆盖下降 >10pp；(c) 调用预算 ≤ 1.3×baseline。回滚：开关默认关；回滚需 26 场重放确认覆盖回到 baseline。
**代价与风险**：+1 次/分块抽取调用（26 场多块会议 ≈2–4 块/场，预算约 +50–100 次）；风险：清单化让「举例/铺垫」被误当核心点（v3 试点已暴露过「过度包容」缺陷，需要重要性门槛）；强场可能因清单噪声回退（R4 形态）。

#### A3-2（P1）coverage-gated plan（弱场触发，强场不触发）

**原理**：R4 的 plan+gap-fill 宏平均 +1.92pp（11↑12↓3=），形态是「弱场获益明显、好场回退」——说明机制本身有效但**分发条件错了**。Plan-and-Write 的收益依赖计划质量与任务结构（R26）；长上下文模型存在中间位置信息利用差（R25），因此应把 plan 作为**低覆盖/长尾会议的定向补写**，而不是全量默认。

**最小实现路径**：用零调用的场级特征（转写长度、议程/分段数、抽取密度=keypoints/千字、字段空置率）做门控；门控阈值在 dev22 上调，test26 上验证；被触发场才跑 plan+gap-fill。**验证设计**：test26 配对，比较「全量 plan 臂」「gated 臂」「baseline」；判定 gated ≥ baseline+1.5pp 且无场次回退 >5pp，才算「可默认」。回滚：门控开关 + 阈值配置化。
**代价与风险**：分发逻辑复杂度；风险：门控在 test26 上过拟合（用 dev22 调、test26 只验一次）。

#### A3-3（P1）分段上下文补全（前文摘要/议程/已抽要点去重）

**原理**：长会议分段抽取时，每段单独看会漏掉「跨段指代/前文铺垫/议程呼应」；lost-in-the-middle 说明模型对长上下文中部信息利用更差（R25），因此给每段喂「前文压缩摘要 + 议程 + 已抽要点索引」比无限加长上下文更稳。QMSum 的 locate-then-summarize 同样强调先定位相关跨度（R22）。

**最小实现路径**：抽取调用输入 = 当前段 + 上一段 200 字摘要 + 会议议程/标题 + 已抽要点 id 列表（去重用）；预算控制：上下文 ≤ 1.5×当前段长度。**验证设计**：与 A3-1 同批 26 场配对，作为 A3-1 的消融项（keypoints 有/无上下文）；判定：在 A3-1 收益基础上再 +1pp 才值得增加复杂度；否则只保留「已抽要点去重」这一低成本子项。回滚：同一开关。

**代价与风险**：token 成本小幅增加；风险：前文摘要本身带错会污染抽取（需要摘要只做指代消解、不做事实扩写）。

### 3.4 轴4：行动项 / owner / deadline

#### A4-1（P0）字段级类型校验 + 条件规则

**原理**：当前两处已证实缺陷都是**类型/条件问题**，不是模型能力问题：
- 期限字段 `field_misuse`=14：期限槽里写的是动作（"完成数据收集和目标差距分析"、"尽早启动"），而合法的期限应当是 timex（可解析时间）或 `declared_unknown/open_ended`。
- `MISSING_DEADLINE` 规则无条件触发：对「原文本来就没有截止日期」的条目误报 **77.8%**（7/9）与 **85.7%**（12/14）——规则应先定位条目来源窗口，只有窗口中确实出现时间表达时才报。

**外部证据与差异注记**：timex 抽取/归一化有成熟规则系统——SUTime 是确定性规则系统、在 TempEval-2 上优于当时 SOTA（R30），HeidelTime 是跨语言/跨域规则系统（R31）；但两者以英文为主，中文相对日期（"下周三前"、"月底"）需要自建规则或用模型抽取后再规则校验。MUG/AliMeeting4MUG 的 AID 任务是**句子级「是否与行动项相关」分类**（R28），不提供 owner/deadline 字段金标，因此字段级只能做**原文证据人工审查**，不能报公开集字段准确率（仓库 ALIMEETING_PROTOCOL 已写死）。

**最小实现路径**（确定性，零 LLM 调用）：
1. 期限槽 type-check：正则+规则识别 timex（绝对日期/相对日期/时段/截止词），非 timex → 改判 `field_misuse`/`declared_unknown`，并回填「动作」到内容或丢弃。
2. `MISSING_DEADLINE` 条件化：先按条目文本在转写中定位来源窗口（6 字子串命中，最长窗口 ±30s），窗口内无时间表达时不报；有则报并附 `source_span`。
3. owner 槽：owner 值必须满足「出现在本段/相邻段的具名实体或 speaker 标签映射表」；否则降为 `declared_unknown`（不允许凭空人名）。
4. 离线重放：把规则作用于现有 26 场产物，直接得到「若规则已上线」的 field_misuse/MISSING_DEADLINE 指标变化（不需要重跑模型）。

**验证设计**：主指标 (a) `field_misuse` 14→≤3；(b) `MISSING_DEADLINE` 误报率 ≤20%；(c) 真漏报（窗口含时间但规则未报）≤1/26 场。样本：26 场现有产物离线重放 + 人工抽检 30 条行动项（双人）。判定：三项全过才允许进默认（规则层）；回滚：规则配置化，可回退到旧行为。
**代价与风险**：规则代码 + 人工抽检；风险：中文相对日期规则误判、把「尽早/尽快」当 timex（这是 field_misuse，不是 deadline）；若人工抽检发现「原文确实没有 deadline」比例高，说明该规则天然低收益，应如实登记。

#### A4-2（P1）speaker-attributed owner 证据链

**原理**：负责人错误的根因是「把谁说的/谁承诺的」与「谁负责」混为一谈，或从上下文推断出不存在的人。如果转写带可靠 speaker 标签（SA-ASR 输出），owner 可以绑定「承诺语句所在段的说话人 + 原文引句」；无引句则不写具体人。外部依据：端到端 SA-ASR 在 LibriCSS 上 cpWER 11.9%/16.3%（SOTA 级，R8），说明「谁说了什么」可端到端建模；本项目 MOSS 快照也显示 hyp speaker 数与参考一致（4/4，cpCER 25.92/11.98，§4.2）——前提是转写的说话人归属本身可信。

**最小实现路径**：行动项抽取时同时输出 `owner_evidence: {speaker_label, quote}`；owner 值必须与 evidence 中的人名/角色一致；speaker_label 需映射到参会人（产品已有 participants/speakers 表，映射不确定时保留 `speaker_label` 并标 `declared_unknown`）。**验证设计**：26 场重跑 + 人工抽检 40 条 owner（双人，判「有原文依据且正确」）；判定 fabricated ≤2%（现状 6.3%）、grounded 不降。回滚：开关默认关，字段向后兼容。
**代价与风险**：26 场生成重跑 + 判定；风险：speaker 匿名标签无法映射真人（需产品侧参会人登记）、昵称/代称（"老王"）需要实体链接。

#### A4-3（P1）期限 timex 归一化

**原理**：即使期限字段合法（是时间表达），"下周三/月底/会后两周"也需要锚定**会议日期**归一化为绝对日期，否则下游提醒/检索无法使用。期限当前 grounded 仅 12/143（8.4%），其中可能大量是相对表达；timex 归一化可提升「可执行性」，但**不能创造原文没有的期限**。

**最小实现路径**：抽取 timex → 以会议日期/时区为锚做规则归一（SUTime/HeidelTime 思路，中文规则自建）→ 输出 `deadline_iso + quote + anchor`；无法归一保留原文 + `open_ended/declared_unknown`。**验证设计**：26 场离线重放（只改字段不重生成）+ 人工抽检 30 条；判定：可解析率提升 ≥10pp、错误归一 ≤5%（人工）；回滚：字段旁路。
**代价与风险**：中文 timex 规则覆盖成本；风险：把动作词当时间（与 field_misuse 同源）、时区/会议日期缺失导致错锚。

### 3.5 轴5：自检反思环的有效性边界

#### A5-1（P0）反思环契约收缩：4 类可核验 issue + 强制 quote + 有界修改

**原理**：Self-Refine 类方法在有**可靠外部反馈**时有效（R32），而无外部反馈的「自评自纠」在推理类任务上经常无效甚至变差（R33）；系统综述进一步指出：prompted LLM 的自我纠错在缺乏可靠外部反馈时几乎没有成功证据，只有「任务特别适合自我纠错」或「有可靠外部反馈」或「大规模微调」三类条件成立（R34）；此外同一模型既生成又评判存在 self-preference（R35）。本项目的证据与此一致：审查 precision 仅 4.1%–7.8%，内容支撑 AUC 0.487–0.624（≈无区分力），而「多写一遍」能把整篇 HHEM 问题率从 23.1% 压到 0–7.7%——这更像「写短/写泛」的度量效应，不是内容变好。

**最小实现路径**：
1. 审查只允许 4 类可核验 issue：`UNSUPPORTED`（断言无原文依据）、`MISSING_ITEM`（原文有、纪要无）、`ATTRIBUTION`（归属/引语错）、`MODALITY`（未定→已决/建议→承诺）；每类必须给 `source_span`（原文连续子串）+ `target_index`。
2. 审查不得自由重写整段：只输出「删除/降格/补引/改归属」四类有界操作；生成侧按操作执行，执行后再跑一遍护栏（保默认、内容归零、双层门控）。
3. 审查通过率不再作为质量指标（通过率本身不稳定：test26 2.0%、dev22 0.0%、另一轮 48.8%；而 4–8% precision 说明报的大多不可用）；主指标改为「人工判定的真问题 precision/recall + 每轮有效修改数」。

**验证设计**：从现有 51+44+43 轮审查里分层抽 100 条 issue 做人工金标（双人，判「是否真问题/是否有原文依据」）；判定：门控+契约后 precision ≥50%、recall ≥30%、有效修改/场 ≥1；端到端 26 场配对：unsupported 不升、coverage ≥−2pp（预注册）。回滚：契约开关；回退后审查行为等价旧版（用 3 场重放验证）。
**代价与风险**：提示词/JSON 契约改造 + 26 场重跑；风险：① 边界过窄→「审查无增益」再次出现（但这次是可解释的「没有可核验问题」而不是「机制无效」）；② 有界修改仍可能过度删除（保留护栏与回退）；③ 需要人工金标投入。

#### A5-2（P1）跨族审查 + 盲判 + 双族一致率门槛

**原理**：同族闭环是已登记的存疑项（"qwen 审查删除 + qwen 盲判删除质量 = 同族闭环"）。跨族审查/盲判可降低 self-preference（R35），并使判决更接近人工；MT-Bench/G-Eval 的经验是强 LLM 裁判可近似人类但需控制偏差（R36/R37）。本项目的实际约束是成本：跨族判定只抽 30% 样本。

**最小实现路径**：审查生成用 deepseek、判定用 qwen（或反之），报告双族一致率；不一致的 case 进入人工仲裁池。**验证设计**：同一批 100 条 issue 双族判定，报告一致率/κ 与翻转率；判定：双族一致率 ≥70% 才把「审查质量」写进结论，否则只报方向。回滚：抽样层，不影响产品。
**代价与风险**：判定预算 ×2（抽样 30%）；风险：两族同错（都偏好「短/泛」输出）——用人工锚点兜底。

#### A5-3（P2，缓做）多候选 + 验证器选择

**原理**：self-consistency 在推理任务上有效（R41），但本任务是「有原文约束的结构化抽取」，多候选的边际收益取决于验证器可靠性；若验证器本身弱，多候选只会放大挑选偏差。建议在 A2-1 的 claim verifier 达到可用（人工一致率 ≥80%）后再做 2 候选 best-of-2 实验。

**最小实现路径**：同输入生成 2 份纪要，用 claim verifier 打分选优；**验证设计**：26 场配对，+1 次生成成本对应 unsupported/coverage 的净收益 ≥1pp 才值得。回滚：开关默认关。
**代价与风险**：2× 生成成本；风险：验证器偏差被放大。

### 4.3 预注册（建议由 lead 批准后，先于复测执行写死）

> **标题**：MOSS-Transcribe-Diarize 0.9B 本地侧车 8 场 cpCER 复测（2026-10-23）
> **背景与假设**：当前产品默认（dashscope c3600 单请求）AliMeeting Eval 8 场 cpCER 30.1%（Δcp +5.1pp，CER 24.9%）。假设：本地 MOSS 端到端 SA-ASR 在同输入同口径下显著降低 cpCER（≥5pp），且 CER 不劣化、无静默截断。
> **主指标**：8 场宏平均 cpCER（MeetEval cpwer，字级、双侧 no_punct、按 speaker 分组），配对差 = MOSS − 云端 c3600。
> **次指标**：CER（同口径交叉验证）、Δcp、hyp 说话人数 vs 参考、覆盖率（last_end/audio_seconds）、每场墙钟/RTF。
> **样本与配对**：AliMeeting Eval 全 8 场（R8001_M8004/R8003_M8001/R8007_M8010/R8007_M8011/R8008_M8013/R8009_M8018/R8009_M8019/R8009_M8020；26.2–37.3min，合计 252.1min），与云端 c3600 逐场配对；输入必须同一份 `hyp_*_avg.mp3`（sha256 记录）。
> **判定规则（全部满足才算「可采纳」）**：
> (a) **有效性**：8/8 场产出有效转写；每场覆盖率 ≥95% 且字符密度 ≥0.8 字/秒（守卫命中即失败重跑，不得把截断算成结果）；
> (b) **主效应**：宏平均 cpCER 配对差 ≤ **−5pp**（即 MOSS ≤25.1%）；
> (c) **稳健性**：≥7/8 场方向一致（MOSS 更优），且配对差 95% bootstrap CI 下界 > 0；
> (d) **不换指标作弊**：CER 配对差 ≤ **+1pp**（MOSS 不得以识别退化换归属改善）；
> (e) **工程**：8 场全程无人工重启、无超时/5xx；单场墙钟 ≤ 2×音频时长；
> (f) **成本**：GPU 推理总时长 ≤ 2×预估（8 场 × RTF 0.37 ≈ 93min，上限 186min），显存峰值记录在案。
> **功效与表述**：n=8 配对连续量、双侧 α=0.05、power 0.8 时 MDE≈1.0×sd_pair（DESIGN 登记 6–7pp）；因此 (b) 的 +5pp 门槛处于功效边缘：**结论只能写成「8/8（或 7/8）方向一致且效应量 ≥5pp」或「检不出」**，不得写「MOSS 无效」，也不得把 n=2 历史值当预期。
> **失败/不达标处理**：任一项不满足 → 不切默认引擎；保留 dashscope；MOSS 降级为「可选实验引擎」；若 (a)/(e) 反复失败，先修工程再复测，**不得用部分成功场次的宏平均上报**。
> **回滚条件与动作**：产品默认引擎保持 dashscope；若实验期间切换过 `TRANSCRIPTION_ENGINE`，复测结束必须一键切回并做一次健康检查（`/health` + 1 场冒烟）；回滚演练单列为验收项。
> **产物与登记**：`evaluation/asr/first_test/cpcor/cpcor_report_moss_8m.json`（逐场 + 宏平均 + 配对差 + CI + 符号检验）、`evaluation/reports/2026-10-23_moss_asr_comparison.md`、`run_manifest.json`；只有全部齐备后，才允许由 lead 决定是否在 LEDGER 轴1 新增 MOSS 行（本报告不改 LEDGER）。
> **纪律红线**：不按场次挑选结果；失败场必须逐场列出原因；不得改 c3600 基线口径；不得把 MOSS 卡公开 22.17 当成本项目预期值；不得用「平均分」替代逐场配对。

### 4.4 长音频失败排查清单（复测时逐项勾选）

1. **输入时长核对**：`ffprobe`/`wave` 读音频秒数，与产品 `total_duration_ms`、侧车 `audio_seconds` 三者一致（±1s）。不一致 → 先查容器/中间转码。
2. **覆盖率**：`last_end / audio_seconds`；<0.95 即截断。R8007 案例 = 229.31/1854.03 = 12.4%。
3. **字符密度**：`normalize(full_text).len() / audio_seconds`；中文会议远场正常约 3–6 字/秒，R8007 = 0.99、R8001 = 6.9、R8003 = 5.5。低于 1.5 字/秒必须解释。
4. **token 预算**：记录实际生成 token 数（侧车日志/返回值）；`max_new_tokens ≥ 15×audio_seconds + 4096`（30min≈31k、60min≈58k、90min≈85k）；`max_length`（含音频 token）不低于模型的 131072 上限配置；超限前必须显式报 `truncated` 而不是静默停。
5. **上下文上限**：单次输入 ≤90min（MOSS 声明）；产品 >90min 时应拒绝或分段，不得直传。
6. **显存**：记录 GPU 型号、峰值显存、是否 `expandable_segments`、是否出现过 OOM；长音频 KV cache 大，失败后需 `empty_cache` 或重启侧车再续跑（串行）。
7. **生成退化为空/短**：若 `segments=0` 或 `text` 为空，侧车必须抛错（不能 200 + 空），产品按失败处理。
8. **说话人数异常**：hyp 说话人数应 ≈ 参考人数（2–4）；出现 8+ 或 1 个巨簇 → 检查 diarization 输出解析、是否把时间戳/标签串进正文。
9. **时间戳单调性**：段 start 不得倒退；FunASR `sentence_info` 毫秒→秒换算必须统一（历史 bug：毫秒/秒混用）。
10. **模型加载**：确认 hub 选择（HF 而非 ModelScope）、`model_path`/revision、dtype/attn 配置；加载耗时单独记录（不混入 RTF）。
11. **超时/重试**：本地引擎超时 ≥3600s；单场失败不得自动重试超过 1 次（避免重复烧 GPU）；重试必须记 `retry_count`。
12. **环境漂移**：复测开始前记录 git HEAD、侧车 sha256、requirements 锁、GPU 驱动、CUDA 版本；复测期间不得升级依赖。

### 4.5 成本/延迟护栏

- **时长换算**：8 场总音频 252.1min；按历史 RTF≈0.37 预计 ≈93min GPU 推理，加上加载/失败重试上限 2×；云端同批估计 <10min（历史 3 场墙钟 54–78s，RTF≈0.03）——本地方案是「隐私/成本/可控性」换延迟。
- **超时**：本地引擎独立超时 ≥3600s；产品默认 `ASR_TIMEOUT_SECONDS=600` 不适用于本地。
- **并发**：侧车串行；评测串行执行；若在线试用，必须限制同时排队任务数并在队列层给用户可见等待时间。
- **预算闸**：复测期间 GPU 只服务本任务；失败重试 ≤1 次/场；总时长超 186min 即暂停并上报 lead。
- **显存**：16GB 单卡是历史配置；若复测环境不同，必须在 manifest 记录，结论只适用于记录的环境。

### 4.6 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 5/8 失败重现 | 中 | 复测无效、烧预算 | 先修 F3–F6 + 单场冒烟（1 长 1 短）再全跑 |
| 静默截断未拦截 | 中 | 假 cpCER 进入汇总 | A1-2 守卫先行；汇总脚本强制校验覆盖率 |
| token 预算仍不足 | 中 | 长场截断 | 按 15×秒数+margin 设置；记录实际 tokens |
| 推理栈与公开值不可比 | 高 | 数字无法外推 | 结论只写「本项目链路」；A/B 栈单独登记 |
| 许可/合规 | 低 | MOSS Apache-2.0 可商用；但 FunASR/transformers 依赖需过法务 | 依赖清单法与模型卡链接入档 |
