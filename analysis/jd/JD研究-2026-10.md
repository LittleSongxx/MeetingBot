## 0. 一页结论（先看这 6 条）

1. **「评测 + 可观测」是跨公司第一硬共识，不是腾讯特色**：24 条里 **16 条**明确要求评测/回归/A-B/可观测/量化指标，且 2027 届校招也在写（快手 S3/S4、蚂蚁 S5、九方云 S6）。**RAG 明确提及 12 条、工具调用 12 条、记忆/上下文 10 条、规划/编排 10 条**——「RAG + 工具 + 记忆 + 规划」仍是四件套，但**排序上评测已经压过 RAG**（按「是否被写成岗位要求/职责」计，不只是加分项）。
2. **「Agent Harness / Context Engineering / MCP」是腾讯、美团、网易三家 2026Q4 的「平台/专家岗」词，不是全行业基线**：本轮 MCP 仅 **3/24**、HITL 人机确认仅 **1/24**、Agent Harness 仅 3 家出现。**这意味着简历不能整体「堆 2026 新词」**，要按投递岗位族分叉：投**应用开发岗**用「RAG / 工具调用 / 评测 / 上下文管理 / 异常兜底」；投**Harness/平台岗**再上「Harness / Context Engineering / Durable Execution / Trace」。
3. **会议/语音场景有独立岗位族**：腾讯会议（S17 评测 PM、S18 AI 产品-ASR）、微信语音识别算法（S15）、企业微信语音产品（S19）说明 **ASR 模型、流式识别、热词、说话人分离是语音算法/产品岗的专业职责**；应用开发岗的合理边界是**链路集成 + 转写质量评测 + 编排 + 产品化**。→ 简历里 ASR 指标必须标清「第三方引擎（DashScope/MOSS）」，不要写成自研模型能力。
4. **1–3 年社招（S9 百度 / S10 小红书 / S11 B站 / S7 美团不限经验）的门槛是「端到端交付一个模块 + 工程栈 + 场景落地」**，不要求体系设计；「3–5 年+」（S12 蚂蚁算法、S13/S14 网易、S20/S22 腾讯）才要求评测体系、平台、成本/SLA、知识治理。**同一份项目经历需要准备两个版本**。
5. **招聘方对「个人项目」的真实表态分散但一致**：蚂蚁写「课程项目、开源贡献、个人作品均可」（S5）；小红书写「有完成小型 AI 项目 demo 经历加分」（S10）；快手写「做过 AI Agent / LLM 应用的课程项目或比赛项目」（S4）；B站直接写「独立、完整地做成过一件事：创业/个人项目/开源项目均可——看重把一件事从头到尾推进到结果的能力」（S11）。**即：学生项目可以投，但必须证明「完整闭环 + 真实结果」**。
6. **对本项目最相关的 10 项要求**见 §6；若只保留 5 条 bullet，按 JD 覆盖面排序应是：**①评测与可观测 → ②RAG 混合检索与引用可追溯 → ③Agent 编排/工具调用/异常恢复 → ④长期记忆与上下文工程 → ⑤语音转写链路的集成与质量评测**。

### 3.1 三条结构性判断【归纳】

1. **评测是「跨公司、跨级别」的第一硬要求**（16/24），而且校招 JD 也写「评测集建设、模型评测」（快手 S3、S4、九方云 S6）。**它同时是「学生项目」与「生产项目」的分界线**：评测需要 gold 集、指标、回归，天然要求版本化和可复现。
2. **「RAG + 工具调用 + 记忆/上下文 + 规划」四件套的覆盖面（10–12/24）没有评测评高，但它是「入场券」**：没有这四样的项目基本不会被认作 AI 应用项目；有了这四样只能算「合格」，**评测 + 可观测 + 成本/时延才决定档位**。
3. **2026 新词（MCP 3/24、HITL 1/24、Agent Harness 3 家）在本轮样本里不是基线**。原因有二：本轮纳入了非腾讯公司与 1–3 年社招，这些岗位用更朴素的原词；以及会议/语音/产品岗不提这些词。**结论：把新词放在「与岗位族匹配」的句子里，而不是全局堆砌**。

2. **真实结果**（有指标/可复现/可演示，而不是「跑通过一次」）；
3. **本人主导**（「独立完成」「自己动手」，团队大作业容易被追问分工）。

| 只列框架名（LangChain/Chroma/Ollama） | 「会调库，不等于会做应用」——JD 里框架名最多是「优先」，从不是主要求 | 每个框架后跟一句「解决什么问题 + 为什么选它」 |
| 只有「跑通」，没有评测/对比 | 快手/网易/腾讯都要求评测；无评测 = 无法证明变好 | 补「小 gold 集 + 指标 + 基线 vs 改进」 |
| 没有失败路径 | JD 高频「异常兜底/恢复/降级/重试」 | 写清超时、限流、重试边界、降级策略 |
| 无权限/无数据边界 | 应用岗 JD 也写「权限控制/沙箱」 | 写「检索层权限过滤 + 工具只读 + 人工确认」 |
| 全是大词（多智能体/自进化）但无落地 | 小红书：「而不是为了创新而创新」；快手：「不是 PPT」 | 降低词面，突出「真实用户场景 + 数字」 |
| 把 ASR 当自研能力吹（会议项目特有） | 腾讯 S15 是独立语音算法岗；S17/S18 是语音评测/产品岗 | 明确「第三方 ASR 引擎集成」，把差异化放在「转写后处理 + 纪要 + 检索」 |
| 论文/竞赛堆砌投应用岗 | 本轮应用岗 JD 中仅算法岗（蚂蚁 S12）提论文/顶会 | 投应用岗时论文放最后一行或不写 |
| 无成本/时延意识 | 快手/网易/腾讯 FDE 都提成本与 ROI | 补成本口径：单会议成本、单题成本、p95 延迟 |

## 9. 给简历/项目叙事的 3 条硬建议（【归纳】）

1. **第一屏（项目简介）就出现「评测 + 可观测」**，其次才是「RAG + Agent」：因为 16/24 的 JD 把评测/可观测写成职责，而校招生普遍只写「做了 RAG」。建议句式：「离线评测集 + 回归门禁 + 调用级 Trace（Token/延迟/失败率）驱动迭代」。
2. **数字必须带口径**：`Recall@5 98.1%（27 轮）`、`cpCER 13.47%（8 场，第三方 ASR）`、`单题成本 ¥0.15`、`首 token p95 2.46s`。JD 反复出现「可量化/可追溯/口径/ROI」，无口径数字会被追问打假。
3. **按岗位族分叉投递**：投**应用开发岗**（S1/S3/S6/S9/S13）用「RAG + 工具调用 + 评测 + 上下文管理 + 异常兜底」；投**Harness/平台岗**（S7/S14/S20/S22）再上「Agent Harness、Context Engineering、Durable Execution、Trace、知识治理」；投**产品岗**（S17–S19/S21/S24）换成「评测体系、Benchmark、指标、用户反馈闭环、产品化」。
