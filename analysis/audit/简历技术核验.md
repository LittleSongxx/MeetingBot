**最该改的 3 处（按被追问翻车概率排序）**：
1. **`Recall@5 98.1% / nDCG@5 92.5%`** → 实际是 `recall@k=98.148% / nDCG@k=92.650%`，**n=27 轮，k 由模型自选（分布 [3,4,6]）**，既不是 @5 也不在 100 题集上（`evaluation/results/metrics.json#retrieval_metrics`、`evaluation/results/METRICS_REPORT.md:653-664`）。仓库自己的求职研究文档也写明「指标要写 recall@k」「无 baseline 的 Recall@5 是经典崩盘点」（`docs/resume/02-mianjing-research.md:309,399`）——**现简历违反了仓库自己的研究结论**。
2. **`忠实度 93.1%（100 题）`** → 93.1% 是 **2026-10-26 单次 live 重抓**（qwen 单裁判、per-case scope、非冻结协议）的读数（`docs/可观测性与延迟成本现状.md:167-173`）；同 100 题集的**预注册三次均值是 88.34%**（`evaluation/reports/2026-10-23_eval100_fresh_repeat.md:94-99`），冻结组装集是 89.21%。选单次最优值会被一句「同协议三次均值多少」打穿；且文档自己写明「单裁判不可靠（α=0.426<0.70）」「不要当 SLA」。
3. **MOSS `8 场 cpCER 13.47%/CER 17.74%`** → 数字属实且可复算，但口径是 **AliMeeting Eval 8 场、8ch 远场平均下混、直连 MOSS 侧车（不是产品 HTTP 链路）的「模型自身指标」**；产品链路只复核了 **1 场**（13.99% vs 直连 12.35%，+1.64pp）（`evaluation/reports/2026-10-22_moss_own_metrics.md:7-11,48-84,202-210`）。面试官一问「这是端到端还是模型自身」「云端基线多少」「为什么产品变差了 1.64pp」就要能立刻分口径。

## 5. 建议措辞（逐条，可直接替换简历原文）

> 目标：机制保留、口径显式、每个数字都有 n 与测试集；不超过原 bullet 长度太多。

**Bullet 1（Agent 自检循环）**
> 基于 LangGraph 建「评审→修订→复审」反思环：审查步**直读转写原文**（不走向量检索）核对六字段，每条意见强制附 `source_span/target_text`，定位不到即硬门控挡在重写之外；默认 2 轮、可配 1–5，命中上限转人工；修订稿经人工确认后才写回，纪要确认后归档。

**Bullet 2（转写与说话人分离）**
> FFmpeg 统一抽单声道 16k 音轨，ffprobe 预检时长（部署守卫 45min）后整段单请求转写；DashScope 与本地 MOSS SA-ASR 双引擎按环境变量切换；输出带时间轴与说话人标签的片段，支持逐段人工修订/说话人匹配；MOSS 在 AliMeeting Eval **8 场直连侧车自身指标** cpCER 13.47%、CER 17.74%（产品链路单场复核 13.99%，与直连差 +1.64pp）。

**Bullet 3（结构化输出与校验）**
> 六字段纪要由 JSON Schema 与 Pydantic 同源约束输出，条目强制标注 `origin`（原文/推导/模型推断）并提供可定位证据 span；行动项写库前校验 owner/deadline/evidence（owner 编造 0/6）；26 场 50 条行动项审计中证据可定位 **50/50**（规则代理口径）。

**Bullet 4（RAG 检索）** —— 必改
> 300 字/2 句窗口切块（部署配置；代码默认 500），CONFIRMED 纪要与 RAW 转写分别入索引；pgvector+BM25 双路召回 + 应用层 RRF + qwen rerank，检索按用户可见会议做会议级 ACL 过滤；简单事实题确定性预检索、无命中/异常回退 Agent 路径；**27 轮检索诊断 recall@k 98.1% / nDCG@k 92.65%（k 由模型自选 3/4/6）**；100 题混合集三次均值 faithfulness 88.3%、answer relevancy 99.0%；27 轮 77 条引用可定位 100%（CP 下界 93.5%）。

**Bullet 5（可观测性）**
> `ai_call_log` 按 trace_id/span_id 记录模型调用耗时、Token、状态、失败原因与成本，/metrics 暴露 token/耗时直方图与成本计数，观测页按 SQL 最近秩展示 p50/p95；问答首 token p50 1.75s/p95 2.46s（n=10 单次，SSE 客户端口径）；累计 25,036 次调用成功率 99.45%（调用级、含评测流量）；单题成本约 ¥0.15（估算单价，不含 ASR/裁判）。

**如果只想改 3 处（最低成本）**：① bullet 4 的 `Recall@5/nDCG@5（27轮）` → `recall@k/nDCG@k（27 轮，k 由模型自选）`；② 忠实度 `93.1%（100题）` → `88.3%（100 题三次均值）` 或标注 live 单次；③ MOSS 句加「AliMeeting 8 场、直连侧车自身指标」并在追问时主动补产品链路单场复核。
