## 0. 一页结论（先看这十条）

1. **"介绍项目"之后，面试官第一刀几乎固定是"完整链路 + 每一层输入输出"**：N03 字节问「描述一下最简单的 Agent Loop 是什么样子」；N07 小厂连续追问「Agent 链路的代码架构具体怎么实现的」「意图识别怎么设计的」；N01 拼多多问「音视频流进入系统后，经过哪些步骤生成转写文本和会议纪要？」——**这是 MeetingBot 最该准备的一张图**（见 §4）。
2. **第二个必问点已经从"你做了什么"变成"你的指标怎么测出来的"**：N02 快手问「tool 调用准确率提升了多少，怎么衡量」；N01 问「你会怎么评估 Agent 效果，而不是单纯提升难度」「如果项目没有严格实验，不能编造曲线」；N09 阿里云问「这个取消机制你实际尝试过吗？」——**"实测过没有"是 2026 年区分真假项目的核心问法**。
3. **会议转写 / 长音频 / ASR 是真实存在的专门考察区，且已出现"会议转写项目"整套深挖原题**：N01（拼多多）一面第 2–7 题连续 6 问题主会议转写项目：完整流程、谁负责、音视频到纪要的步骤、为什么选阿里云 ASR、ASR 效果怎么评、隐私安全；N17（天琴实验室 2025）问 ASR/声纹的"上线了吗、数据多少小时、baseline 与最后效果、为什么用 sensevoice"。**02 文档完全没覆盖这个区**。
4. **可靠性/失控的考法非常具体**：任务太慢怎么取消（N03、N09）、Agent 怎么防死循环（N04 第 8 题、N02 第 11 题）、工具超时/脏数据/重复执行怎么兜底（N01 第 13 题、N04 第 13 题）、上下文爆炸怎么办（N02 第 10 题、N04 第 16 题、N09 第 2 题）。**"有界 + 分类 + 降级 + 可观测"是标准答案骨架**。
5. **评测题已经细到"指标定义/样本量/谁标的/baseline/能否复现"**：N01 明确写「工具调用成功率要分层定义，不能只看 HTTP 200」「如果项目没有严格实验，不能编造曲线」；N14 字节二面问「你会用什么标准判断一个 Agent 已经具备企业使用的条件」。
6. **"Workflow vs Agent"是 2026 年出现频率最高的设计辨析题**：N04 第 6/7 题、N13 第 4 题、N14、C01 都把「为什么很多 Agent 最终以 Workflow 形式实现」列为快手/字节高频。**用"固定路径 Workflow + 动态节点 Agent"作答的人明显更稳**。
7. **MCP / Skill / Harness 已经从加分项变成必答题**：N13 问「MCP 底层使用的是什么协议？」「你认为 Skills 的本质到底是什么？」；N05 网易云音乐直接问「harness、hook、mcp、记忆模块的底层实现原理」；N10 问「开发一个 MCP 如何评测效果，怎么迭代」。**只答"工具调用协议"会被继续追**。
8. **"这个项目是你自己做的吗/上线了吗/有真实用户吗"依然必问，而且 2026 年更直白**：N06 58 同城问「你有真正自己开发过 Agent 或写过 Skill 吗？不一定生产，自己练习也行」；N16 中兴问「这个科研 Agent 项目是你一个人做，还是多人协作？」；N01 把"团队架构 vs 个人贡献"写进了标准答题要点。**主动自标签"个人作品集/离线评测"比被问出来安全**。
9. **手撕题以 Medium 为主，但 2026 出现了"手撕 LRU / 手撕 JUC 串行执行器 / 手撕扁平 JSON 转树"这类工程手撕**：N01 一面 LRU、二面扁平 JSON 转树 + 锯齿层序；N03 字节 JUC `submit(key, task)` 同 key 串行；N10 最长有效括号；N13 二叉树层序；N08 爬楼梯改编（3/5/7 步、上一步 7 下一步只能 3）；N03 接雨水 II（只讲思路）。**算法之外，手写"带轮数上限/终止条件/错误回填的 Agent 循环"仍是高频预期**（02 文档 S96 已提示，本次在 N04 第 8 题、C01 得到印证）。
10. **本简历最可能减分的不是技术，而是三处口径**（详见 §11、§14）：①「MOSS 8 场 cpCER 13.47%」的样本量与基线没讲清；②「Recall@5 98.1% / 忠实度 93.1% / 相关性 99.0%」是自建 100 题 + 27 轮，且没有 baseline/区间就并列；③「调用成功率 99.45% / 单题成本 ¥0.15」容易被读成任务成功率与线上稳定成本。**这三处恰好都对应 2026 年最狠的追问（N02/N01/N10）**。

## 4. 这类项目会被怎么深挖：五层追问模型

> 把 N01/N02/N04/N07/N09/N13/N19 的问法抽象成"五层"。MeetingBot 的每条 bullet 都要能扛到第 4 层。

| 层 | 面试官在验证什么 | 典型原话 | 应对要点 |
|---|---|---|---|
| L1 事实层 | 项目是不是你做的 | 「介绍你的实习项目，你做了哪些事情以及你的思考」（N02）；「项目是个人完成还是团队合作？你具体负责哪些部分？」（02 文档 S16） | 一句话定位 + 个人模块边界 + 别人的部分 |
| L2 链路层 | 你是背的还是真跑过 | 「描述一下最简单的 Agent Loop 是什么样子」（N03）；「音视频流进入系统后，经过哪些步骤生成转写文本和会议纪要？」（N01）；「从用户提出问题开始，完整走一遍项目里的检索流程」（N14） | 画图式口述：输入/输出/状态/失败点 |
| L3 机制层 | 每个技术名词背后的机制 | 「LangGraph 是如何搭建的？Memory 组件工作机制？」（N10）；「RRF 融合/父子索引代价是什么？」（N07、N09）；「MCP 底层协议？」（N13） | 每个组件准备"为什么用它/代价/什么情况下不用" |
| L4 数据层 | 指标是不是测出来的 | 「tool 调用准确率提升了多少，怎么衡量」（N02）；「怎么判断召回结果是否准确」（N19）；「这个取消机制你实际尝试过吗」（N09）；「用什么标准判断一个 Agent 已具备企业使用条件」（N14） | 指标定义 + 样本量 + baseline + 口径 + 复现 |
| L5 边界层 | 你知不知道自己的系统哪里不可信 | 「有没有你目前解决不了的 bad case？难点是什么？」（C01 死亡追问层）；「如果项目没有严格实验，不能编造曲线」（N01）；「Context 超限/工具失败/多 Agent 冲突怎么办」（N04、N09） | 主动说"做到了 X；Y 没做，原因是 Z" |

**一条可直接背诵的"会议项目 60 秒链路"**（对照 N01 第 3 题、N14 检索链路题）：
> 上传（鉴权/幂等 key）→ FFmpeg 抽单声道音轨 + 预检（时长/采样率/静音）→ ASR（整段请求，返回带时间轴/说话人的片段）→ 人工修订转写 → 六字段纪要生成（Pydantic/JSON Schema 契约 + 依据标注）→ 评审-修订-复审（LangGraph，轮数上限 + 证据校验）→ 人工确认（DRAFT→CONFIRMED）→ 入知识库（仅已确认）→ 问答（简单事实预检索 / 复杂走 Agent，混合检索 + RRF + rerank + 引用绑定）→ 观测（trace_id / token / 成本 / p50-p95）。
> 每一段后面跟一句"失败时会怎样"：ASR 超时、纪要证据无法定位、检索为空、引用绑不上、任务中断恢复——**这正是 L2→L4 的入口**。

## 5. 主题聚类 A：RAG 全链路（最高频，几乎每场都问）

### 5.1 完整流程与"每一层的意义"

- N01 第 8 题「介绍一下项目中的 RAG 流程，离线建库和在线检索分别做了什么？」；N07 第 4 题「简单说一下 RAG 系统」（离线：清洗→OCR→分块→向量化→入库；在线：向量/关键词/图谱三路召回→RRF→Cross-Encoder 精排）；N20「RAG 最难的地方是哪」；C02 总结字节"把 RAG 拆成链路逐段深挖"、腾讯"偏工程落地与概念辨析"、百度"分块导致语义割裂怎么解决"。
- **想听到的**：索引阶段（解析/分块/embedding/索引类型/更新策略）、召回阶段（多路/融合/rerank）、生成阶段（上下文预算/引用/拒答）、评测阶段（检索/生成/端到端）四段都要有"输入输出 + 失败点"。

### 5.2 切分与索引

- N01 第 9/10 题「文档如何切块？Chunk 大小和重叠窗口根据什么确定？」「是否用 Recall@K、MRR 做过实验？」——标准答案要点已在帖中：切块服从文档结构、块大小受自包含/embedding/reranker/业务跨度四类约束、重叠不宜过大、参数必须用 Query 集做实验，**"如果没做严格实验，不能编造曲线，可以说明现在会补什么标注集和消融"**。
- N07「重叠的值怎么设置的？」（答：当前策略 15%）；「长文档怎么解决？」（答：父子分块）；「大表格被分到不同 chunk 怎么解决？」（答：没遇到，思路是确定性代码校验+人工）——**注意：答"没做过"在 N07 里没有被扣分，反而因为给了思路显得可信**。
- N09「RAG 中的父子索引是什么？解决了什么问题？代价？」；N10 第 9 题 BM25 原理与相对 TF-IDF 的改进；N14「文档切块大小怎样确定？依据哪些因素设置 Chunk 范围？」。
- **与本项目的对应**：300 字/2 句重叠、纪要入索引。会被追问：**"300 字是怎么验证的？换会议/长纪要/多说话人时还是一样吗？索引里到底是纪要还是转写原文？"**（N01 明确要求区分"检索单元 vs 注入上下文"）。

### 5.3 召回、融合与 rerank

- N01「为什么使用当前的切块策略？是否通过 Recall@K、MRR 等指标做过实验？」；N07「三路召回 + RRF + Cross-Encoder」；N09「父子索引代价」；N14「什么情况下接 RAG、什么情况下把知识整理成 Skill」。
- **必答题**：RRF 为什么不需要调权重（只看排名）、k 值作用、两路候选深度与 rerank 延迟/成本的权衡、rerank 模型是 cross-encoder 还是 LLM、截断 top-k 怎么定。
- **高频反问**：**"召回率多少？"**（C03 标题就是"你做了三个月 RAG，召回率多少？"）；追问链通常是：指标定义（Recall@K 还是 Hit@K / 多证据是否要覆盖率）→ 测试集怎么建（自建多少题、谁标）→ baseline 是什么 → 提升几个点、可信区间多少。

### 5.4 生成侧：幻觉、引用、冲突、兜底

- N04 第 10/15 题「如何解决 Agent 的幻觉问题？有哪些校验与反思机制」「RAG 检索内容与模型知识冲突时，如何处理？」；N13 第 4 题「RAG 检索出来的内容相关性很差，你会怎么排查？实际做 RAG 项目时遇到过什么问题，最后怎么解决的？」；N20「怎么规避大模型的幻觉？微调和 RAG 的优劣势？」；C02 腾讯代表题「检索不到结果或知识库无匹配内容时如何处理？」。
- **想听到的**：幻觉 = 事实错 / 引用错配 / 证据不支持 / 工具结果误读 / 业务状态误判；治理 = grounding + 拒答 + 结构约束 + 证据校验 + 拆分成可验证子问题；**"引用错配"与"事实错"要分开说**——这正好对应本项目的 citation_bind/引用可定位。
- **注意 N01 的硬要求**：「会议纪要不是把整场转写一次性塞给模型……关键结论要能回指转写片段」「输出后检查引用是否存在、结论是否被引用片段支持、数字和实体是否一致」——**这就是面试官心中"证据溯源"的标准答案，背下来可对齐本项目的表述**。

## 8. 主题聚类 D：语音 / ASR / 说话人（02 文档空白区，本次重点补）

> 这一节是本报告对 Lead 最有增量的部分：N01 把"会议转写项目"当成完整项目深挖了 6 问，N17 是 ASR+声纹专场。

### 8.1 流程与工程链路（N01 第 3 题原题：音视频流→转写文本与纪要，经过哪些步骤）

帖子（WeThinkIn 整理版）给出的标准答案骨架，几乎可以逐句对照本简历：
- 接入：鉴权 + 稳定 `meeting_id`/流 ID/**幂等键** → 解复用抽音轨 → 固定采样率/位深/声道 → 降噪/回声消除/AGC/VAD/固定时长分帧；
- 实时链路：interim vs final（**final 才适合持久化**）、按 `segment_id`/时间戳/版本合并、说话人分离/声纹映射、标点恢复、数字规范化、热词纠错、敏感信息处理；每个片段保留**音频区间、置信度、说话人、修订版本**；
- 会后：按议题/时间/语义分段 → 局部事实/决定/行动项 → 分层合并 → 结构化 schema（topics/decisions/action_items/owner/deadline）→ 负责人/时间/数字**确定性校验** → 关键结论**可回指转写片段**；
- 异常：断线重连、迟到分片、重复回调、识别服务限流、会议未正常结束、模型超时、部分结果恢复。

### 8.2 ASR 选型与双引擎（N01 第 4 题 / N17 二面）

- N01 第 4 题「为什么选择阿里云 ASR？对比过其他云服务或开源语音识别模型吗？」——标准答法：**"不能回答成因为调用方便"**；按目标场景做实测矩阵：普通话/方言覆盖、会议远场与噪声鲁棒性、流式延迟、热词/自学习、说话人能力、并发配额、SLA、数据合规、地域、单小时成本、SDK 稳定性；没有完整对比就如实说只做了小规模 PoC/基于团队既有设施。
- N17（腾讯音乐天琴实验室）二面：「paraformer 的优势」「还有哪些创新点」「为什么用 sensevoice」「介绍原理、数据、实验、效果」；一面「介绍 asr 工作」「你的工作上线了吗」「有了解其他多任务模型吗」「论文是你自己调研的吗」；二面还问「数据有多少小时」「有做数据清洗吗」「创新设计是什么」「baseline 效果如何，最后效果如何」。
- **对本简历的直接威胁**：bullet 2 写"支持 DashScope/MOSS 双 ASR 引擎"+"MOSS 8 场 cpCER 13.47%、CER 17.74%"，**必然被问：为什么两个引擎？怎么对比的？8 场是什么测试集（AliMeeting far/near？）、谁标的参考文本、cpCER 定义、有没有 baseline/置信区间？** 8 场这个样本量在 N17 的"数据多少小时/baseline 是什么"面前明显偏小，必须准备"这是技术选型 PoC、不是产品结论"的边界说法。

### 8.3 ASR 评测（N01 第 5 题原题）

- 「ASR 的识别效果怎么评估？遇到专有名词、同音字和错别字时怎么处理？」标准要点：中文 CER = (S+D+I)/N；**仅看整体 CER 不够**，要分桶（噪声/口音/设备/远近场/人数/领域）+ 专有名词召回率/数字日期准确率/说话人归属准确率/标点质量/实时延迟；热词表（带版本与租户隔离）、N-best+词级置信度+拼音相似度/编辑距离/领域纠错、低置信度保留候选或人工校正；大模型纠错要限制修改范围、记录前后版本、用时间戳回查；评测集来自真实分布、与调参数据去重；**同时看下游指标（纪要事实支持率、行动项 F1、用户修改率）**。

### 8.4 说话人分离与长音频

- 场景：发言时间轴、说话人标签、人工修订——本简历 bullet 2 写了"说话人标签 + 人工修订"。**面试官会问"说话人分离怎么做的？聚类还是声纹？重叠说话怎么办？说话人归属准确率怎么测？"**（N17 声纹工作被连续追问"业务背景/实验过程/效果"）。
- 长音频：整段请求 vs 分段。N01 提到"流式 ASR 的 interim/final"和"会议未正常结束/迟到分片"；本简历是"预检时长后整段单请求"，**会被问"2 小时会议也整段？ASR 服务上限多少？超限怎么办？失败重试会不会重复计费/重复入库？"**——这正是 N03/N09"取消/超时"考点在语音链路上的变体。

### 8.5 隐私与安全（N01 第 6 题）

- 会议录音/转写是个人敏感信息：授权与用途说明、TLS/SRTP、KMS、私有桶+短签、行级/租户隔离、RBAC/ABAC+每次读取校验、导出/分享二次鉴权+审计、DLP/脱敏/水印、供应商数据留存与训练政策、删除响应机制、异常访问告警。**本项目的"权限过滤下沉 + 只读工具 + 人工确认"可以对齐讲**。

## 9. 主题聚类 E：评测与指标口径（2026 年最狠的一刀）

### 9.1 原题与要点

- N02 第 3 题**原题**：「升级之后 tool 调用准确率提升了多少，怎么衡量」；标准答法（帖中给出的"参考答案"）分层：工具选择正确 / 参数 schema 与业务约束 / 执行成功无超时无重复 / 结果被正确理解并使用；指标：工具选择准确率、参数填充准确率、无效调用率、重复调用率、最终任务成功率；**分母要说明是否排除用户取消/外部不可用/无权限，重试成功要同时记首调与最终成功率**。
- N01 第 12 题**原题**：「Agent 的工具调用成功率是怎么定义的？项目最初的数据是多少，后来如何提升？」——明确写"不能只看 HTTP 200"，且"'最初的数据是多少'必须引用真实评测集或 trace，说明样本量、时间窗口和口径；若没有可靠记录，应直接说明"。
- N19 一面**原题**：「怎么判断召回结果是否准确」「上下文压缩怎么设计的」。
- N14 二面**原题**：「你会用什么标准判断一个 Agent 已经具备企业使用的条件？」（预期答题方向：任务集成功率、失败可恢复、成本/延迟预算、可观测、权限审计、回归集）。
- N01 第 10 题**原题**：「为什么使用当前的切块策略？是否通过 Recall@K、MRR 等指标做过实验？」并明说「如果项目没有严格实验，不能编造曲线。可以坦诚当时依据少量样本和线上反馈选择」。
- C01"死亡追问层"：**「你优化后的方案，有没有出现新的 bad case？」「如果要求准确率从 90% 提到 99%，从哪些方向优化、优先级怎么排？」「你做的这些优化有没有理论依据？」「有没有你目前解决不了的 bad case？」**

### 9.2 评测题的"五件套"答题模板（本简历可直接套）

1. **定义**：这个指标具体怎么算（分子/分母/口径/裁判是谁）；
2. **数据**：多少条、怎么来的（人工/代理/真实 trace）、谁标的、是否与调参数据隔离；
3. **baseline**：相对谁提升（原方案/无此模块/随机）；
4. **可信度**：样本量小就说不可外推（置信区间/α 一致性），单裁判不当真值；
5. **复现**：冻结基线 sha、一条命令跑回归、数据可查。

> 本简历其实五件套齐全（预注册、配对 A/B、冻结 sha、零调用回归、α 失败降级），**问题只在"简历上一句话把五件套压成两个数字"**，面试官看不到口径就会按 N01/N02 的方式追问。建议每条数字后补 6–10 字的限定词（离线回放/运行时/A/B/单裁判/估算价）。
