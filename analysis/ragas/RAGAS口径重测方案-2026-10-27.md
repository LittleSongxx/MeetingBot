# RAGAS 官方口径重测方案（v1，2026-10-27）

> 目标：用 **RAGAS 官方库口径** 重测一版可当"最终证据"的 RAG 质量读数，替换简历/作品集里非标准的 recall@k 叙事。
> 依据：仓库代码与评测产物实查（`evaluation/`）、RAGAS 官方文档 0.4.x（见 §9）、PyPI `ragas==0.4.3`。

## 0. 结论先行（推荐路径）

可以推进，但"RAGAS 口径"不是把现有指标改个名：**RAGAS 的四指标与项目现有自研指标在定义、输入、判定方式上都不同**。推荐：

1. **方案 A（推荐）**：装官方 `ragas==0.4.3` 到隔离 venv，**离线**读现有 `eval100_scope_fixed_packet.json`（100 题，含 answer/contexts/expected_facts），用 **DeepSeek-flash 判官 + 百炼 text-embedding-v4** 计算官方四指标：`Faithfulness`、`AnswerRelevancy`、`ContextPrecision`、`ContextRecall`；其中 ContextRecall/ContextPrecision 需要 **reference answer**，用"金标事实模板 + AI 起草 + 人工抽查"构造并冻结。
2. **先 30 题 pilot，再全量 100 题 × 3 次**；按仓库评测宪法先写预注册（`LEDGER.md`），报告新旧两套并排，**不覆盖旧口径、不混算**。
3. 产出：`evaluation/reports/2026-10-27_ragas_official.md` + `results/ragas_official_*.json` + 质量闸新增 `ragas_official` 行（旧 17 行不动）+ 简历/作品集统一改用新数字。

## 1. 仓库现状盘点

### 1.1 已有的（可直接复用）

| 资产 | 位置 | 用途 |
|---|---|---|
| 100 题评测 packet | `evaluation/results/eval100_scope_fixed_packet.json`（666KB） | 每题含 `question / answer / contexts[{ref,kind,meeting_id,text}] / expected_facts / unanswerable / judgement`；100/100 已抓取，contexts 全部 `context_source=retrieved`；平均 3.55 段上下文/题，answer 均 362 字 |

| 既有裁判链路 | `evaluation/lib/model_client.py` + `evaluation/judges/rag.py` | 现有自研四指标；DeepSeek/Qwen 端点与预算闸模式可复用 |

### 1.2 缺的（本次要补）

1. **官方 ragas 未安装**：`evaluation/` 与产品 venv 均无 `ragas`；产品 venv 有 `langchain-core 1.6.1 / langchain-openai 1.6.0 / openai 3.19.2`，版本可能与 ragas 依赖冲突 → **建独立 venv**（`evaluation/.venv-ragas`），不要污染产品环境。
2. **没有 reference answer**：只有 `expected_facts`，而官方 ContextRecall/ContextPrecision 需要 reference（见 §2）。
3. **没有 embedding 客户端**：官方 AnswerRelevancy 需要 embedding（百炼 compatible-mode `/embeddings` 已有产品实现可复用：`text-embedding-v4`，1024 维）。
4. **没有官方指标结果 schema / 冻结行 / 报告**。

### 1.3 现有自研 vs RAGAS 官方（关键差异）

| 指标 | 项目现状（自研） | RAGAS 0.4 官方 | 影响 |
|---|---|---|---|
| context_precision | 逐段判"有用"的**比例**（判定式，非排名加权） | **rank-aware**：Σ(Precision@k × v_k) / 相关片段总数，越靠前越重要 | 同一 packet 数值会变（通常不同），**不能与 71.83% 直接相减** |
| context_recall | 金标事实在上下文中被找到的**比例**（fact-coverage） | 把 **reference answer 拆 claim**，逐 claim 判是否能归因到上下文 | 需要 reference；新数值与 recall-v2 96.2% **不同口径** |
| faithfulness | 裁判拆 claim 后判支撑（两口径：全部/内容级） | claim 拆分 + LLM 判"能否从上下文推断" | 接近，但 RAGAS 会把"以上信息来自…"这类 meta 句算 claim → 数值可能偏低；需并列或预处理说明 |
| answer_relevancy | 二值"是否正面回答"（判定式） | **反向生成 3 个问题 + 与用户问题的 embedding 余弦均值** | 完全不同；需要 embedding，数值可能明显低于 99.0% |
| 聚合 | 逐指标报，不报加权总分 | 同样建议逐指标；无总分 | 一致 |

## 2. RAGAS 官方四指标：定义、输入、调用（0.4.3）

来源：官方 docs（`docs.ragas.io/en/stable`）与 `src/ragas/metrics/collections/__init__.py`。

| 官方类（collections） | 输入 | 定义 | 本项目可用性 |
|---|---|---|---|
| `Faithfulness(llm=...)` | `user_input, response, retrieved_contexts` | 答案 claim 中能被上下文支撑的比例 | 直接可用（packet 已有） |
| `AnswerRelevancy(llm=..., embeddings=..., strictness=3)` | `user_input, response` | 反推 3 个问题，与用户问题 embedding 余弦均值 | 需 embedding 客户端 |
| `ContextPrecision(llm=...)` | `user_input, reference, retrieved_contexts` | rank-aware 加权 precision@k | 需 reference answer |
| `ContextRecall(llm=...)` | `user_input, retrieved_contexts, reference` | reference 的 claim 能被上下文归因的比例 | 需 reference answer |
| `ContextUtilization`（无 reference 备选） | `user_input, response, retrieved_contexts` | 用 response 代替 reference 判上下文有用性 | reference 没造好前的降级方案（但会把答案幻觉算进"有用"） |

**官方 API 骨架（待装好后按实际版本微调）**：

```python
from openai import AsyncOpenAI
from ragas.llms import llm_factory
from ragas.embeddings.base import embedding_factory
from ragas.metrics.collections import Faithfulness, AnswerRelevancy, ContextPrecision, ContextRecall

judge = llm_factory(
    "deepseek-flash", provider="openai",
    client=AsyncOpenAI(base_url="https://api.deepseek.com/v1", api_key=DEEPSEEK_API_KEY),
)
emb = embedding_factory(
    "openai", model="text-embedding-v4",
    client=AsyncOpenAI(base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",
                       api_key=DASHSCOPE_API_KEY),
)
```
> RAGAS 0.4 的 collections 指标是 **async**（`await scorer.ascore(...)`），并发要用 `asyncio.Semaphore` 控。


## 3. 五个关键设计决策

| # | 决策 | 推荐 | 理由/备选 |
|---|---|---|---|
| D1 | reference answer 怎么来 | **模板拼接金标事实 + 可选 LLM 润色 + 人工抽查 30 条** | 零调用模板即可让 ContextRecall 工作；润色只喂 question+facts、不喂 answer/contexts，防循环；备选：人工写全 100（最贵，1–2 天） |
| D2 | 判官 | **deepseek-flash**（跨族、与现有判定同源、便宜） | 评测宪法要求裁判与被测 qwen 不同族；qwen 只做 20–30 条双族抽检，不作为主判官 |
| D3 | embedding | **百炼 text-embedding-v4**（OpenAI 兼容 `/embeddings`，与产品检索同源、中文好） | 不需 GPU；可选 20 题用 BGE-M3 做敏感性对照，但不混入主口径 |
| D4 | 指标范围 | **官方四指标全量**：Faithfulness、AnswerRelevancy、ContextPrecision、ContextRecall | 要"RAGAS 口径"就四项齐全；`ContextUtilization` 只作诊断副读数；不做 NoiseSensitivity/ContextEntityRecall（超出四件套，另立项） |
| D5 | 运行协议 | **离线 packet 重判**：固定 `answer/contexts`，不重新抓取 | 只换"尺子"不换"被测对象"，避免把产品变化与指标变化混在一起；这也符合评测宪法"换仪器 = 绝对数重述" |

## 4. 数据与 reference 设计

- 样本：`mixed100` 100 题（`eval100_scope_fixed_packet.json`），167 条金标事实，0 道不可答题，平均 3.55 段上下文/题（1–8 段）。
- reference 文件：`evaluation/gold/qa_ref_answers.json`，每条形如：

```json
{"case_id": "m001", "question": "...", "reference": "经营分析会由张晨牵头协调，在 9 月 1 日 9:00 前完成发布公告；对外通稿由李娜定稿，发布前一周 18:00 前完成。",
 "facts_used": ["..."], "provenance": {"method": "facts_template+llm_polish", "model": "deepseek-flash", "human_checked": true, "checked_by": "song", "date": "2026-10-27"}}
```

- 构造流程：
  1. `evaluation/gold/build_qa_ref_answers.py`：从 `expected_facts` 生成"根据金标事实：…"模板句（零调用、确定性）；
  2. （可选）LLM 润色为 1–3 句自然语言，输入**只有 question + facts**；
  3. 人工抽查 30 条（优先多事实题、27 条人工 gold 题）；发现新增事实/改写走样即回退模板；
  4. 冻结 `qa_ref_answers.json` 的 sha256（与 packet sha 一起写进报告与基线）。
- **边界**：`human_checked=false` 的条目必须在报告里单列；参考只代表"gold facts 的自然语言化"，不是人工金标答案。

## 6. 成本与时间估算（粗算，跑前用 pilot 复核）

- **LLM 调用/次运行**（按 RAGAS 实现拆解）：
  - Faithfulness：claim 拆分 + 逐 claim 判定 ≈ **2 次/题 × 100 = 200**
  - ContextRecall：reference 拆 claim + 逐 claim 归因 ≈ **3 次/题 × 100 = 300**
  - ContextPrecision：逐上下文判有用 ≈ **3.55 次/题 × 100 ≈ 355**
  - AnswerRelevancy：反向生成 3 问 ≈ **1 次/题 × 100 = 100**
  - 合计 ≈ **955 次/次运行**；3 次 ≈ 2,900 次；加 reference 构造/校准/重试 ≈ **3,100–3,400 次**。
- **Embedding**：AnswerRelevancy 每题 4 条短文本 ×100 ≈ 400 条/次运行，3 次≈1,200 条。
- **Token/费用**：packet 全文约 answers 3.6 万字 + contexts 7.3 万字/次运行，叠加 prompt 开销约 50–100 万 token/3 次；DeepSeek-flash 现价下预计 **¥10–40 量级**，embedding **<¥1**。以实际账单为准。
- **墙钟**：并发 6–8、单次 2–4s → 每次运行约 15–30 分钟，3 次 1–1.5 小时；reference 构造 + 人工抽查 0.5–1 天。
- **人力**：开发 harness 1 天；报告/冻结 0.5 天。

## 7. 统计、冻结与报告规范

- 逐题保存四指标原始分（含 `reason`），报告给 **pooled mean + 每题均值 + CP 95% CI**，并给 3 次运行的极差与 SD；**不报加权总分**（宪法第 6 条）。
- 新旧两套并列，明确"换仪器"：**不得把 RAGAS 的分数与自研 71.83/90.02/88.34/99.00 相减**，只能并排解释。
- 冻结：`quality_gate_baseline.json` 新增 `ragas_official` 段（ragas 版本、judge model、embedding model、prompt 语言、packet sha、refs sha、4 指标读数、CI）；`quality_gate.py` 校验 sha（产物/refs 变了未重冻 → FAIL）。
- 报告必须写：`ragas==0.4.3`、prompt 语言、judge 与 embedding、样本 100、N=3、reference 来源与 `human_checked` 比例、失败 case 数、调用/成本。
- 简历/作品集只引用**冻结后的 RAGAS 官方四指标**（+ 现有引用可定位/成本/TTFT 等零调用指标），不再用 recall@k 作为主指标。

## 11. v1.1 修订：吸收官方源码级调研（2026-10-27）

> 依据：`analysis/ragas/RAGAS调研-2026-10.md`（215 行，官方源码级口径）。以下 8 条修正**覆盖前文对应假设**；跑数前以本节 + 调研文档为准。

### 11.1 口径修正（必须按官方源码，不按文档转述）

| # | 前文写法 | 官方源码实际口径 | 对 harness 的要求 |
|---|---|---|---|
| 1 | context_recall 把 reference 拆 **claim** | 实际按 **句子（sentence）** 拆，分母 = reference 句子数 | reference 构造时**控制句子数**（1 事实≈1 句），不要写成长复句；分母在报告里写明 |
| 2 | context_precision 是"排序加权" | 官方是 **Average Precision**：只在 v=1 位置累加 Precision@k，**分母=被判有用的切片数**；全 0 → **0.0（不是 NaN）**；每切片 1 次调用 | 与现有 71.83 的 `useful/total` **不可比、不可相减**；报告单列"仪器 r1" |
| 3 | answer_relevancy 二值/余弦 | 官方：`strictness=3` 反推 3 问 + 余弦均值 × **noncommittal 惩罚**（N 个全非承诺才清零）；分数**可越界 [0,1]**；唯一吃 embedding | 需 embedding 客户端；中文预期明显低于 99.0，属口径差异；报告写模型名+维度 |
| 4 | faithfulness 由裁判拆 claim | 官方 **2 次调用**：拆原子断言 + 批量 NLI；**分母 = judge 拆出的断言数**；空断言 → **NaN** | 中文长句会膨胀分母；含"以上信息来自…"元陈述会被判不支持 → 主口径 raw + 附"内容级"两列 |
| 5 | 依赖 langchain 旧 wrapper | ragas **0.4.3 破坏性重构**：`ragas.metrics.collections` + `ascore(**kwargs)`→`MetricResult`；`ground_truths:list`→`reference:str`；`evaluate()` 弃用 → `@experiment()`；langchain 仍是硬依赖但 wrapper 弃用 | 独立 venv 锁 `ragas==0.4.3`；不要用 legacy API 写新脚本 |
| 6 | 并发/成本 | v2 指标内部**串行 await**；需外层 `asyncio.gather` + Semaphore（8–16） | 并发 8–12；`AsyncOpenAI(timeout=60, max_retries=5)` |
| 7 | reference 构造 | 用 `expected_facts` 拼**陈述句**；**不要用 answer** 当 reference（自证循环）；无金标 → `null` 不进分母 | 模板优先；LLM 润色只喂 question+facts；控制句数 |
| 8 | 中文 prompt | 官方 prompt 是英文指令+few-shot；可用 `metric.prompt.adapt(target_language="chinese", llm=...)`，但**adapt 即换仪器**，必须新 label 并重算 α | 10 条样本做 3 次拆分稳定性检查；句数波动 >±30% 才考虑中文适配，并登记 |

### 11.2 仪器标签与报告纪律

- 新开 **`r1` 仪器**（与现有 `a/b/c/d/e/g` 并列）；任何数字必须带 `r1` 标签；**禁止**把 r1 与现有 71.83/90.02/88.34/99.00 相减或写"提升/下降"。
- 四指标分母分别写清：context_precision = **有用切片数**；context_recall = **reference 句子数**；faithfulness = **judge 断言数**；answer_relevancy = **case 数**。
- CI 用 **case 级 cluster bootstrap**（复用 `evaluation/analysis/paired_bootstrap.py`）；同时报 Wilson/CP 近似作对照。
- 分层报：p0 / cross30 / new_meeting / mixed100 分开，不合并总分（宪法第 6 条）。
- 数字边界：空断言/空反推问题 → NaN，单列不并分母；全 0 切片 → 0.0 并单列。

### 11.3 judge / embedding / reference（最终建议）

| 决策 | 建议 | 补充 |
|---|---|---|
| 主判官 | **deepseek-flash，temp=0**（与项目现役裁判一致、便宜） | 若 instructor 结构化输出解析失败率高 → 切 `deepseek-chat` 并登记"换仪器"；生成与裁判同族要在报告披露 |
| 交叉校验 | **qwen 20–30 条 spot-check**，算 Cohen κ + Krippendorff α（阈值 0.70，复用 `gold/claim_anchor_score.py`） | 不做全量双裁判；α<0.70 时 r1 只作方向信号 |
| embedding | **百炼 text-embedding-v4**（OpenAI 兼容 `/embeddings`，1024 维，与产品同源） | 固定模型名+维度；可选 20 题 BGE-M3 敏感性对照，只进附录 |
| reference | `expected_facts` → 模板陈述句（1 事实≈1 句），可选润色；人工抽查 30 条；冻结 sha | 不用 answer；`human_checked` 逐条标；27 条人工 gold 优先抽查 |

### 11.4 N=2 还是 N=3：**最终取 N=3**

调研建议 N=2（省时）；我建议 **N=3**，理由：

1. **成本可忽略**：官方估 955 judge 调用/次 ≈ $0.4、4–5 分钟；N=3 约 $1.2–1.4、15 分钟，不构成决策变量。
2. **项目先例**：mixed100 三次 fresh 运行的预注册就是 N=3（`2026-10-23_eval100_fresh_repeat.md`），最终证据沿用同一协议；N=2 只能给"极差"，给不出 SD/方差。
3. **单次波动已知 5pp**：N=2 的"均值"仍可能被一次异常主导；N=3 的均值 + 极差 + SD 才够写"最终证据"。
4. **最终证据要保守**：报告可写"3 次均值 + 每次读数 + 极差"；若审稿质疑成本，成本数据本身可回答。
- 折中：**pilot 阶段 N=2 打通管线；正式全量 N=3**。若时间被压缩，最低 N=2 并在报告显式写"仅 2 次、不估 SD"。

### 11.5 成本/延迟复核（官方源码级调研）

- 调用数/次：precision **355**（每切片 1 次）+ faithfulness **200** + recall **100** + answer_relevancy **300**（strictness=3） = **955 次 judge**；embedding 400 条文本；input ≈ **1.0M tokens**、output ≈ 0.13M tokens。
- deepseek-flash 峰值价约 **$0.47/次**、低谷 $0.23；**N=3 ≈ $0.7–1.4**。
- 墙钟：955×3s÷12 并发 ≈ **4–5 分钟/次**；3 次 <20 分钟。
- 瓶颈：context_precision 355 次调用（尾部）；并发 8–12 + 重试 5。

### 11.6 中文场景必做检查（pilot gate）

1. 取 10 条答案，同一 judge 拆断言 3 次，断言数波动 >±30% → 才考虑中文 prompt 适配（并登记换仪器）。
2. 数字/日期：送 judge 前对 **上下文与答案同时**做归一化（同一函数处理两侧），避免制造差异。
3. judge prompt 语言全批统一（不允许一半中一半英）。
4. 预期 answer_relevancy 明显低于现有 99.0（官方 issue #1829：非英语更差）——这是口径差异，不是系统退步。
5. faithfulness 会因"以上信息来自…/meeting_id=…"元陈述被拉低；报告并列 raw 与内容级两列。
