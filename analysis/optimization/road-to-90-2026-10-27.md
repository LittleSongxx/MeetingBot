# 向 90% 推进的可行性分析与路线（2026-10-27）

> 当前冻结读数：M1b，r1 仪器，100 题 × 3 次：faithfulness 88.25%、context_precision 71.35%、context_recall 89.70%、answer_relevancy 89.64%。
> 目标"每个指标 ≥90%"需要先区分：哪些是系统可优化，哪些是 RAGAS 仪器/数据本身的结构性上限。

## 1. 差距在哪里（按 source set）

|---|---:|---:|---:|---:|---:|
| cross30（多会议/系列） | 30 | 0.856 | 0.803 | **0.292** | 0.727 |

- **cross30 是四个指标共同的短板**；单会议/新会议子集已接近或超过 90（CP 的 holdoutA 97.5）。
- 单题 ≥90 的比例：faith 68/99、AR 70/100、CP 65/99、CR 86/99；均值被少数尾部 case 拉低（faith 最低 0.12）。
- 反推：若 CP 要整体 ≥90，cross30 的 CP 需要从 29.2% 抬到约 **90%**（其他集已接近 90）；这在当前"多会议、多切片、每切片必须完整支持参考"的口径下几乎不可能。

## 2. 为什么 CP 低不全是检索问题（关键证据）

### 2.1 CP 的定义要求"单个 context 支持完整 reference"

RAGAS `ContextPrecision` 对每个 context 调一次 judge，prompt 是"该 context 对得出给定 answer 是否有用"；本项目 reference 是多事实句（如 m001 两条事实）。实测（2026-10-27，m001，5 个 context）：

- fact1-only reference：CP **0.367**
- fact2-only reference：CP **0.250**
- 两条事实合并 reference：CP **0.333**（同批 context 第一次跑为 0.0，judge 不稳定）

m001 的 5 个 context 中，有的只覆盖"通稿负责人"，有的只覆盖"公告负责人"；judge 以"没有覆盖完整 reference"判 0。也就是说：**多事实 reference + 事实分散在不同切片 → CP 结构性为 0，即使 CR=1、答案正确**。

### 2.2 典型 case：m016 / m018

- m016 问"系列最近一次会议形成的结论"，答案正确指出"尚未确认，只有草稿三项结论"；gold facts 也写"下午纪要三项结论…"。但抓取只有 1 个 context，RAGAS：faith=0.12、AR=0、CP=0、CR=0——**答案语义正确但上下文/参考不齐**。
- m018 答案正确指出"报表导出决定未确认生效"；gold facts 与答案一致，但 AR=0：RAGAS 的 answer_relevancy 用"从答案反推问题 + embedding 余弦"，否定式答案与原始问句相似度低——这是指标设计偏差，不是答案错。
- 结论：cross30 的低分里混有 **gold/reference 与上下文不匹配、CP 完整支持假设、AR 否定式惩罚** 三类仪器效应；不先分开，盲目调系统会把"仪器噪声"当"系统缺陷"。

### 2.3 CP 的 judge 稳定性

- m001 同一输入两次 CP：0.0 vs 0.333；m001 的 5 个 context 在单事实/多事实 reference 下分数都低。
- RAGAS GitHub 已知 issue：[#479 Context Precision Prompt Example wrong?](https://github.com/vibrantlabsai/ragas/issues/479)、[#668 `_calculate_average_precision` JSON 处理问题](https://github.com/vibrantlabsai/ragas/issues/668)；官方 prompt 对"部分支持"非常严格。

## 3. 哪些指标真的能到 90

| 指标 | 当前 | 到 90 的可行性 | 需要做什么 |
|---|---:|---|---|
| faithfulness | 88.25 | **高**（+1.75pp） | 清掉尾部无依据断言：推断必须标【推断】、数字/日期必须与引用一致、资料不足不写否定性断言；对 low-faith case 做逐 claim 复核（先 20 例，不按题打补丁） |
| answer_relevancy | 89.64 | **中高** | 答案第一句直接回应问句（尤其否定式答案要复述问题对象）；减少列表/背景铺陈；cross30 的 AR 80.3 是主要缺口 |
| context_recall | 89.70 | **中** | cross30 72.7 是短板；需要结构化覆盖（先枚举相关会议/系列→逐项检索→覆盖回执），不是加长 prompt；可参考现有 P1-1 结构化分解 |
| context_precision | 71.35 | **官方口径下低**（整体 90 需 cross30≈90） | 只能改"评测单位"：按会议/按事实分组 context、或按事实级 reference 计 CP（自定义仪器，非官方）；不改仪器则现实目标 ~75–80 |

## 4. 三条可选路线（需要你拍板）

**路线 A（推荐，诚实口径）**：保留官方 RAGAS 四指标，但把 CP 目标下调为 **75–80**；同时把 faith/AR/CR 推 ≥90；报告按 source set 分层，cross30 单列。这样"官方指标 + 已知边界"都站得住，简历写 "CP 71.4 / CR 89.7 / faith 88.3 / AR 89.6" 或推进后的新值。

**路线 B（自定义 fact-aligned CP，标 r1-fact）**：把 reference 拆成原子事实，逐事实算官方 CP 再平均；或把同一会议的多个切片合并成一个 context 单元。可能把 CP 抬到 90+，但**不是官方 CP 聚合**，必须标 "custom" 且不能与官方 CP 混比；适合"必须每个 ≥90"的展示需求，但面试需主动说明。

**路线 C（改数据/评测集）**：修 cross30 gold/reference 与上下文不匹配（m016/m018 类），统一 reference 为"单事实句"或重写为自然答案。这是评测集修订，不是系统优化；改后所有旧读数作废，需重冻 r1 基线。

## 5. 建议的下一步实验（按性价比）

1. **P0 数据体检（零模型调用）**：cross30 30 题逐题检查 gold/reference/context 对齐；先区分"真系统错" vs "仪器错"。产出：`cross30_diagnosis.csv`。
2. **P1 答案风格（faith/AR）**：对 low-faith/low-AR 的 20–30 题做定向 prompt 迭代（第一句直接回答、推断标注、数字/日期与引用一致），A/B 100 题、r1、N=1 筛选 → N=3 确认。目标 faith/AR ≥90。
3. **P2 覆盖（CR）**：cross30 结构化覆盖（先列相关会议/系列→逐项检索→覆盖回执），只对 cross30，预注册 + 跨集非劣。
4. **P3 CP 口径决策**：在 P0 结果后决定 A/B/C；若坚持官方 CP≥90，按路线 B 新增自定义仪器并明确标注，不用它替换官方读数。
