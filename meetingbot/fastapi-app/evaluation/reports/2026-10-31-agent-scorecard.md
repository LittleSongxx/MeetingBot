# Agent 产品指标 Scorecard（2026-10-31）

> 这份报告不看 ROUGE 论文分数，只看 **Agent 产品行为**：任务完成、人工接管、调用可靠性、证据接地、行动项可用性、延迟/成本。
> 数据来自评测栈 `meetingbot-aim-eval` 的演示会议（1 场）+ 2 次自检运行，样本很小，不能作为统计结论。
> 默认排除 `request_id` 以 `AICDEMO` 开头的演示种子日志和 `AGR-DEMO` 自检运行，避免把 demo 假失败当成真实可靠性；可用 `--include-demo` 复现旧口径。

### 2.5b QA claim-level 证据支持度

引用 ID 命中不等于“引用支持答案”。新增 `evaluation/qa_support_eval.py`，让独立 judge 把回答拆成 claims，逐条判断 cited evidence 是否**直接支持**：

| 指标 | Run 1 | Run 2 | Run 3 | 平均 |
|---|---|---|---|---|
| 回答数（有引用） | — | — | — | 24 |
| claims 数 | — | — | — | 86 |
| claim 支持率 | — | — | — | **86.05%** |
| 完全支持答案率 | — | — | — | **70.83%** |

结论：新增“回答中每一句 claim 都必须能被 citations 直接支持”的 Prompt 约束后，citation precision 从 83.38% 提升到 **92.35%**、claim 支持率从 75.63% 提升到 **84.30%**、完全支持答案率从 52.36% 提升到 **68.75%**，同时拒答率保持 100%。说明**生成时约束 claim 比后端事后改引用更有效**。

### 2.6 QA 测试集（40 题，含 16 道不可回答、10 道多证据）

为补上 QA 只有调用日志的缺口，新增 [`../golden/qa_demo.json`](../golden/qa_demo.json) 和 `evaluation/qa_eval.py`。QA 集从 30 题扩到 **40 题**（24 可回答 + 16 不可回答，10 道多证据），做了 3 次真实运行以观察方差：

| 指标 | 当前 | 目标 |
|---|---|---|
| 40 题平均 found 率 | **100%**（3 次均 100%） | ≥90% |
| 不可回答题拒答准确率 | **100%（16/16，3 次均 100%）** | ≥90% |
| 40 题平均引用 precision | **90.74%**（3 次：91.43/91.89/88.89） | ≥90% |
| 40 题平均引用 recall | **93.33%**（3 次：91.43/97.14/91.43） | ≥80% |
| 40 题平均引用 F1 | **0.9200**（0.9143/0.9444/0.9014） | - |
| 40 题平均答案相似度 | **0.5433**（0.5524/0.5230/0.5544） | 参考，不作硬门槛 |

关键修复：
- **拒答保护只检查第一句**，后文“材料未提及…”补充说明不再误杀；
- **上下文从 8 段提到 16 段**，避免演示会议证据 segment 12/14 被截断，导致漏答/漏引；
- **评测冷却修复**：连续运行 QA 评测时首题会撞 3 秒冷却，脚本现在每次请求前等待并对非 200 重试；此前 q1 的“空回答”就是评测工具误判，不是产品问题。

40 题 ×3 次无新增调用失败；16 道不可回答题三次全部拒答。

### 2.6b 可选 QA claim 审核 A/B（默认关闭）

开启 `QA_CLAIM_AUDIT_ENABLED=1` 后，QA 会多调用一次审核模型，逐条判断 claim 是否被引用支持，删除无依据 claim。

| 指标 | 关闭（基线） | 审核 + 引用收敛 |
|---|---|---|
| citation precision | **90.74%** | 88.89% |
| citation recall | **93.33%** | 91.43% |
| citation F1 | **0.9200** | 0.9014 |
| found 率 | 100% | 100% |
| 拒答率 | 100% | 100% |
| claim 支持率 | 86.05% | **93.83%** |
| 完全支持答案率 | 70.83% | **87.50%** |
| 答案相似度 | 0.5433 | **0.5512** |

解读：
- 40 题上审核把 claim 支持率从 86.05% 提到 **93.83%**、完全支持答案率从 70.83% 提到 **87.50%**；
- 代价是 citation precision 90.74%→88.89%、recall 93.33%→91.43%；
- found/拒答保持 100%；
- 审核模型也是 LLM，指标有自洽性偏差；**默认关闭**，高风险场景建议开启。

### 2.11 多轮追问 QA

5 组主问题 + follow-up，共 10 轮。修复前 follow-up 只拿当前问题检索；修复后检索 query 会带上最近一轮用户问题。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| found 率 | 100% | **100%** |
| follow-up found 率 | 100% | **100%** |
| citation precision | **90%** | **100%** |
| citation recall | **90%** | **100%** |
| 答案相似度 | 0.3988 | 0.3898 |

第二轮修复把检索 query、多轮提示和引用排序都统一为“上一轮用户问题 + 当前追问”：多轮 citation P/R 从 90% 提到 **100%**，c5 正确引用 segment 14。答案相似度略降（0.4307→0.3898），因为回答更短、更直接；引用正确性优先。

## 3. 结论

**Agent 已经具备产品形态的行为指标**：

- 自检反思环能正常终止（fresh run 1 轮、3 步、72s，无失控循环）；
- 人工确认节点存在，且决策延迟可观测；
- 行动项确认/负责人/截止/重复率有数据可查；
- 调用可靠性、延迟、Token 已有统一日志。

**当前主要差距：**

1. **真实调用成功率 99.95%（1924/1925）**，已排除 `demo_seed` 假日志；此前 1 次失败来自修复前的 QA 空文本；
2. **证据覆盖率 95%**，只差 1 条，但样本只有 1 场；需真实会议量验证；
3. **QA 引用 precision 90.74%、recall 93.33%**（40 题 ×3 次），claim 支持率 86.05%、完全支持答案率 70.83%，拒答 100%（16 道不可回答题全部拒绝）；citation precision 刚过 90% 线，完全支持答案率仍约 71%；
4. **人工修改率 0%**，没有真实编辑行为，不能说明“终稿质量”；
5. **样本仍只有 1 场会议、2 个自检运行**；QA 已扩到 40 题，但行动项/人工编辑仍缺少真实业务数据。

## 4. 建议的 Agent 验收线

| 维度 | 指标 | 目标 |
|---|---|---|
| 任务 | Agent 终态完成率 | ≥95% |
| 任务 | 步骤成功率 | ≥99% |

| 接地 | 条目证据覆盖率 | ≥95% → 100% |
| 接地 | 引用合法率 | ≥99% |
| 接地 | 无依据声明率 | <5% |
| 行动项 | content F1（内部集） | ≥0.75 |

| 行动项 | 近似重复率 | <5% |

| QA | 不可回答题拒答率 | ≥90% |

> 这些是产品验收建议，不是论文指标；需要在内部 golden set（10~20 场真实会议）上重新测。
